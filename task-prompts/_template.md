4. 不提交 `_runs`、截图、cookie、token、临时实验包。

## Agent 自验证

修改前：

1. 列出本任务会影响的文件、流程、线上风险。
2. 列出计划改动边界。
3. 说明本任务对应的最小验证集。

修改后：

1. 运行相关 unit / integration / E2E 或等价只读验证。
2. 贴出验证命令、结果摘要、失败项和未覆盖风险。
3. 运行 `git diff -- <本任务相关文件>`，说明只改了本 TASK 范围内的文件。
4. 如有新增报告，写清楚报告路径。

## 人工验收

请产出一份可读验证报告，至少包含：

1. 样本单号或测试输入。
2. 修改前行为。
3. 修改后行为。
4. 预期结果。
5. Agent 自测结果。
6. 需要人工查看的卡片、日志、截图或报告路径。
7. 未覆盖风险。

不要因为 agent 自测通过就自动勾选 TASK 完成。只有用户确认报告接受后，才允许在 `TASK.md` 勾选完成。

## 40 部署准入

未经用户明确授权，不得部署 40。

如后续需要部署 40，必须先输出：

1. 本机验证通过项。
2. 未覆盖风险。
3. 影响服务。
4. 回滚方案。
5. 是否需要先执行 `40-snapshot-code.sh`。
6. 等待用户明确回复“授权部署 40”。

## TASK.md 回写

任务结束前必须回写 `TASK.md`：

1. 执行会话链接。
2. 修改文件。
3. 验证命令和结果。
4. 报告路径。
5. 当前状态：完成 / 阻塞 / 等人工确认 / 等 40 授权。
