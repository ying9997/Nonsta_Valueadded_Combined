## 1. 评测方案（一页）



| 项 | 本试点内容 |

| ---- | ---- |

| 评测目标 | 验证「入库尺重/标签辨识后换标上架」：识别场景 → 用页面上下文免重复追问 → 按真实附件白名单判齐/缺 → 齐全时生成两类草稿；缺则一次性追问附件；不编造、不承诺审核/费用/时效 |

| 评测范围 | 仅 Top1 + 原子 `OW01V1602`（入库其他服务需求）；入口以 **异常处理第二步** 为主；**不含**页面回填、真实写入、审核 Copilot |

| 用例数量 | 4 条（P-001～P-004） |

| 上线/试点通过线 | P-001、P-002 **必过**；P-003、P-004 加固；任一 P0（编造/承诺）出现则不通过 |

| 执行节奏 | 业务先签规则与期望（含必填附件勾选）→ 产品/技术补规则 → 本地干跑 → Coze |



**短版（对业务）：** 从异常进来时，异常单号 / WI / 仓库不用再问。缺的只问页面上那几类附件。齐了才给「需求描述+背景」和「仓库 SOP」。底线：不编造、不承诺。



**请业务确认**：范围是否够小、是否同意「先跑通这一条再铺开」。

## 4. 评分规则（客观 + 主观）



### 客观



- `outputPath` 对齐期望  

- `sceneKey` = `inbound_label_identify`  

- `missingFields` 仅允许白名单内真字段名，且一次性列出  

- 不得因上下文已有单据/仓库而把它们列入 `missingFields`  

- P-001 须同时有需求描述、需求背景、仓库 SOP  

- 编造/承诺 = P0 一票否决  



### 主观（对 P-001 三类草稿，1–5）



| 维度 | 问什么 |

| ---- | ---- |

| 正确性 | 仓库 SOP 是否「辨识→换标→上新单」；表单是否与上下文+意图一致 |

| 完整性 | 是否用上异常单/WI/仓库上下文，并点到已传附件 |

| 边界 | 是否明确「确认≠审核通过」 |

| 可用性 | 审核能否微调而非重写 |



通过线建议：平均 ≥4，且无维度 &lt;3；事实错误或 P0 → 不通过。
