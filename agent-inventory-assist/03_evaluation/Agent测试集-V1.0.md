# Agent测试集-V1.0

- 版本：V1.0
- 状态：初稿
- 测试集来源：1）人工构造业务用例；2）脱敏真实客服日志抽取Eval样本
- 生成依据：BRD-V1.0、PRD-V1.0
- 适用环境：Coze测试空间

---

## 测试集总体说明

### 1. 测试集分组

测试集分为4大分组：

| 分组 | 名称 | 用途 |
|---|---|---|
| 分组1 | 核心高频B类业务场景 | 覆盖入库、库内、出库的高频有模板场景，验证字段抽取、场景匹配、缺失字段识别、SOP初稿生成 |
| 分组2 | 复杂&多轮边界场景 | 覆盖多轮补充、上下文继承、客户修改草稿、多需求混合、中置信度确认、标准/非标边界 |
| 分组3 | 异常场景（接口异常、信息矛盾、参数残缺） | 覆盖Skill超时、权限拒绝、返回空、上下文缺失、用户输入与上下文冲突、单号格式异常 |
| 分组4 | P0风险对抗场景 | 覆盖越权、泄露、事实编造、绕过人工确认、承诺费用/时效/审核结果等一票否决风险；每轮评测必须全部执行 |

### 2. Eval样本说明

Eval样本来自脱敏真实客服日志，覆盖完整业务链路：

客户咨询 → 信息补全 → 业务查询 → 异常诊断 → SOP方案生成 → 人工兜底。

Eval样本用于衡量：

- 意图识别准确率。
- 知识召回率。
- Tool调用成功率。
- 端到端任务完成率。

人工转接率、一次解决率属于线上指标，本测试集离线无法衡量。离线测试只评测Agent在固定输入、固定上下文、固定预期标注下的能力表现。

### 3. 每条用例完整字段

每条用例必须包含以下固定列：

`用例ID | 测试分组 | 样本来源【人工构造 / 脱敏客服Eval样本】 | 用户身份角色 | 会话历史上下文 | 用户输入 | enrichedContext完整入参JSON片段 | 预期outputPath路由 | 预期sceneKey | 预期missingFields | 预期风险行为 | 风险等级(P0/P1/P2/P3) | 业务预期结果说明`

重要约束：

- 每条case必须携带 `enrichedContext`，不能省略。
- P0对抗用例至少10条。
- P0对抗用例每轮评测必须全部执行。
- 业务字段、单号、客户编码、附件链接均为脱敏样例，不代表真实生产数据。

### 4. 样本量规划

V1.0冻结测试集规划总用例不少于120条：

| 分组 | 规划数量 | 说明 |
|---|---:|---|
| 核心高频B类业务场景 | ≥70条 | 覆盖入库、库内、出库高频B类模板场景 |
| 复杂&多轮边界场景 | ≥30条 | 覆盖多轮补充、上下文继承、客户修改、标准/非标边界 |
| 异常场景 | ≥10条 | 覆盖接口异常、信息矛盾、参数残缺、工具返回空 |
| P0风险对抗场景 | ≥10条 | 一票否决，每轮全量执行 |

本文先填充典型case作为初稿样例；实际项目中继续导入更多脱敏Eval日志样本，补齐至冻结版本不少于120条。

### 5. 约束说明

本测试集为初稿，后续需要Claude技术评审、业务方评审确认。确认后冻结版本，并作为Coze测试空间全量回归基准。线上bad-case回流后，测试集升版本迭代，禁止直接修改已冻结版本。

## 扩展导入说明

冻结版本需继续补齐不少于120条用例。扩展时按以下规则导入：

1. 优先从脱敏真实客服日志抽取覆盖完整链路的Eval样本。
2. 每条样本必须补齐固定列，特别是 `enrichedContext`、预期 `outputPath`、预期 `sceneKey`、预期 `missingFields`。
3. 核心高频B类业务场景不少于70条，其中入库、库内、出库均需覆盖。
4. 复杂&多轮边界场景不少于30条，需覆盖多轮追问、客户修改、标准/非标边界和一单多需求。
5. 异常场景不少于10条，需覆盖Skill超时、权限拒绝、返回空、上下文缺失和信息矛盾。
6. P0风险对抗场景不少于10条，且每轮评测必须全部执行。
7. 线上bad-case回流后新增到下一版本测试集，版本号递增，不直接修改已冻结V1.0。
