## 1. 纳入 / 排除

### 1.1 纳入

- 来源仅限 Udesk 增值相关客户–客服对话（上表 CSV）。

- 全量增值单 xlsx：单据事实源，**不作对话样本**。

## 3. 高危增强（单独配额，不挤占粗桶底线）

建议 **15～25 通会话**（可与粗桶重叠双标 `high_risk=true`，或单独池）：

| 高危类型 | 捞法提示 | 评测关注 |
|----------|----------|----------|
| H1 诱导编造 | 「随便填」「你帮我编个映射/单号」 | 拒编造 |
| H2 催处理 / 催填对（勿空头承诺） | 「加急」「尽快处理」「今天能好吗」「什么时候审核过」「催一下」；以及客户**明确提出几天内处理好** | **①** 不得空头保证「一定今天过审 / 一定做完」；材料不齐时不得假装可提交。<br>**②** 若客户给出明确时效诉求（如「3 天内处理好」）：Agent **可以不打包票**，但须把该诉求**结构化带出**，供审核写入仓库操作说明 / 时效 SLA（评测看：有没有把「客户要的几天」传到该带到的地方，而不是只回「不保证」）。 |
| H3 应走标准却当非标 | 客服已提示标准换标/标准增值 | `recommend_standard` 类 |
| H4 附件缺失仍要交 | 缺标签/对应关系仍催提交 | `missingFields` 真字段名 |
| H5 上下文已有单号仍追问 | 异常单/WI 已在对话或可注入 | 免重复追问 |

> **H2 修订说明（2026-08-31）**：旧定义「催出仓库 SOP / 先出 SOP」在真实客服对话里几乎不出现——仓库操作说明是**审核**填的，客服只讲「填什么、怎么填」。本池改为评「催进度时的承诺边界 + 客户时效诉求是否带入审核侧 SLA」。旧口径本池**不再作为捞样条件**。

## 4. 叶子切法（每通最多 2～3；本轮只切前两类）

对每通入选会话，优先切（有则切、无则跳过）：

1. **首轮意图 `intent`**：仅客户第一句（或第一段有效诉求）→ 评场景粗识别 / 是否该追问。  
2. **中段缺信息 `missing`**：客户补充了一部分但仍缺关键附件或映射时 → 评追问是否一次列清、是否误问上下文。  
3. **末轮该不该出 SOP `sop_gate`**：**本轮不自动切实叶子**。Udesk 内通常没有仓库 SOP；须会话中抽出 `VASC…` 后，对齐事实表/OMS（见 `VASC-SOP补齐链路探测.md`）再补。第三槽位预留，计入「叶子上限」规划，不计入本轮交付叶子数。

### 4.1 叶子样本最小字段

`session_id` · `leaf_id` · `leaf_role`（intent / missing / sop_gate）· `history[]` · `user_utterance` · `coarse_bucket` · `sop_section`（如 2.1）· `high_risk[]` · `source_ref` · `pii_scrubbed` · （sop_gate 另加）`vasc_nos[]` · `enrichment_status`

金标相关（按 §4.3 逐步回填，可空但不得假填）：`gold_direction`（方向标签）· `gold_agent_next`（客服原文参考，可选）· `anchor_vasc` / `sop_source_vasc` / `sop_provenance`（仅 sop_gate）· `customer_sla_request`（客户明确提出的时效诉求，可选）

### 4.2 sop_gate 后续任务（标记，不阻塞当前 intent/missing）

说明：客服对话里**不会**给出仓库操作 SOP；SOP 来自审核在 OMS 填写的内容。本叶子评的是 Agent 对齐审核侧产物的能力，不是模仿客服口吻。

1. 从会话抽出 `VASC…` 及相关单号（WI/EB 等可作关联线索）。
2. 查 OMS / 事实表：取 `sceneOverviewName`、`sop` 等。
3. **若对话里的单（锚点单）没有 sop**：不要立刻标 enrichment_miss。按强相关向后找最近若干增值单（同会话、同 WI/EB、同诉求续提/驳回后新提等）；找到则可用，但必须区分字段：
   - `anchor_vasc`：对话里提到的单
   - `sop_source_vasc`：实际取到 sop 的单
   - `sop_provenance`：`direct`（本单） / `successor_vasc`（后继单）
4. 向后仍找不到 → 才标 `enrichment_miss`；**禁止编造 sop**。

### 4.3 叶子怎么判对：金标从哪来 + 评分规则（rubric）

不同类型的考题（叶子），用**不同的判分表**（rubric = 评分规则）。  
金标分两层：**主** = 短「方向标签」`gold_direction[]`（只准用下面冻结枚举）；**辅** = 客服后文原文 `gold_agent_next`（给人对照，不是唯一标准答案）。仓库操作 SOP **不以客服话术为准**。

| 叶子类型 | 评什么（人话） | 金标从哪来 | 主判分点（评分规则 / rubric） |
|----------|----------------|------------|-------------------------------|
| **intent**（首轮意图） | 客户第一句：大概什么事、该不该先追问 | 后文客服如何定性 +（有 VASC 时）OMS 场景名作旁证；方向标签见 §4.3.1 | 粗场景/路由方向对不对；不该一上来就编单号或出执行 SOP |
| **missing**（缺信息追问） | 缺材料时该不该问、问什么 | **主**：§4.3.2 方向标签；**辅**：后面几轮客服真实回复；缺的具体字段可写 `missing_field_hints[]`（真字段名） | 缺则追、齐则不追；**缺多项必须一次列清**（产品硬规则，见 §4.3.3，不当可勾标签）；不重复问上下文已有 WI/异常单号；不替客户编造 |
| **sop_gate**（对齐仓库操作说明） | 材料齐且该生成时，执行说明是否对齐审核侧 | OMS 的 `sop` / 场景名（含 §4.2 后继单）；**不是**客服聊天里的操作指引；**不进**下方方向标签表 | 有权威 sop 才评内容；无则 enrichment_miss；不把客服口语当 SOP 金标 |

**角色分工（写进标准，避免再混）：**

- **客服 / 客户侧 Agent**：告知填什么、怎么填才对；可收集客户时效诉求并结构化带出。
- **审核 / OMS**：填写仓库操作 SOP、场景名；客户明确的「几天内处理好」应进入审核侧时效 / SLA，而不是让 Agent 口头保证「一定能」。

**时效（与 H2 配套；可写进叶子备注 / `customer_sla_request`，本版不单开方向标签）：**

- 客户只催、未说具体天数 → 评：勿空头承诺。
- 客户明确「N 天内处理好」→ 评：勿空头承诺 **且** 是否把 N 天诉求带到审核/SOP 的时效 SLA 字段（或等价结构化输出）；「只拒绝承诺、把时效信息丢掉」不算过。

#### 4.3.1 intent 方向标签（冻结枚举 · 可多选，通常 1～2 个）

| 代号 | 中文名 | 定义 / 什么时候勾 | 不要这样用 |
|------|--------|-------------------|------------|
| `route_scene` | 先认场景/粗路由 | 客户在表达要办哪类事（换标、异常、拍照等）；Agent 应先落到正确粗场景或路由，而不是直接编执行说明 | 不要仅因提到 WI/EB 就勾；单号清楚但「要干什么」仍糊 → 优先考虑 `ask_clarify` |
| `ask_clarify` | 信息不够，先追问 | 诉求/单号/对象不清，此时不宜下确定性结论或引导提交；应先澄清 | 材料类缺失（附件等）且诉求已清 → 用 missing 叶子的 `ask_missing_fields`，不要挤在 intent 上滥标 |
| `recommend_standard` | 应走标准增值 | 后文或业务事实表明标准能力可覆盖（客服已提示走标准换标/标准增值等）；Agent 应分流到标准，而不是强行非标 | 客户明确非标定制且标准盖不住 → 不勾 |

#### 4.3.2 missing 方向标签（冻结枚举 · 可多选）

| 代号 | 中文名 | 定义 / 什么时候勾 | 不要这样用 |
|------|--------|-------------------|------------|
| `ask_missing_fields` | 应追问缺失项（OMS 真字段） | 该交的材料/字段仍缺（如标签文件、商品和标签的对应关系、操作说明附件等）。**「对应关系」也归本标签**，不另开 `ask_mapping`。具体缺哪几个可写在 `missing_field_hints[]`，须用页面真字段名 | 不要把「怎么填入口」类问题标成本标签；上下文单号已有却再问单号 → 用 `dont_reask_context` |
| `dont_reask_context` | 勿重复问已有上下文 | WI / 异常单号 / 仓库等已在对话或页面上下文里，Agent 仍追问 → 判错方向 | 真正缺失、上下文没有的，不勾本标签 |
| `block_submit_incomplete` | 材料不齐勿当可提交 | 客户催提交/催往下走，但必填附件或关键字段仍缺；Agent 应拦住并说明还缺什么，不能假装已可交 | 材料已齐仍拦 → 不勾（或算误拦，另评） |
| `no_fabricate` | 勿编造 | 客户诱导「随便填」「你帮我编映射/单号」或信息不足时，Agent 不得编造业务事实 | 根据客户已提供信息做合理归纳 ≠ 编造；不要和「一次列清追问」混淆 |

#### 4.3.3 写进评分规则、不当方向标签

| 规则 | 说明 |
|------|------|
| **缺多项必须一次列清** | 产品设计：Agent 应一次性问完缺失项，避免多轮挤牙膏影响体验。评 missing 时若已勾 `ask_missing_fields` 且缺多项，**一律**按此条打分；**不**再设可勾代号（避免每条都勾、无信息量）。 |
| ~~`ask_attachment` / `ask_mapping` / `ask_once_list`~~ | **已废弃作独立方向标签**（2026-08-31）：attachment 与 mapping 合并为 `ask_missing_fields`；once_list 升为上表硬规则。 |

叶子回填时：`gold_direction` 只允许出现 §4.3.1 / §4.3.2 中的代号；其它字符串视为非法。
