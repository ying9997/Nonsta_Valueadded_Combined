## 0. 两套数字（务必分清）

| 名称 | 含义 | 本草案目标 |
|------|------|------------|
| **会话配额** | Udesk 里选中的一整通客户–客服聊天 | **约 80～100 通**（分层 + 高危） |
| **叶子上限** | 一通会话切开后、可单独评分的「带上下文单轮」条数 | **每通最多 2～3 个叶子** |
| **叶子总量（推算）** | 会话 × 每通叶子 | 约 **150～250**；评测可先抽跑子集 |

类比：会话 = 原材料；叶子 = 考试题。

## 1. 纳入 / 排除

### 1.1 纳入

- 来源仅限 Udesk 增值相关客户–客服对话（上表 CSV）。
- 须能还原为「客户原话 + 客服回复」的多轮结构（至少 1 轮客户发言）。
- 主题与非标增值提交/填写/换标/异常/拍照/库内加工等相关。

### 1.2 排除

- **内部飞书群聊**及一切内部转述为主、无客户直说的线程（不可仿真、易引入偏差）。
- 纯系统通知、无客户发言、无法脱敏的会话。
- `qa-gen_base.csv`：**不进主配额**（QA/知识导出形态，非完整会话）；仅允许在稀有粗桶补抽时作辅池，且必须标 `source_type=qa_export`，与 Udesk 分列统计。
- 全量增值单 xlsx：单据事实源，**不作对话样本**。

## 2. 分层：粗桶抽样 + 细类打标

知识库细场景很多（入库 ~55、库内 ~90…），100 通按细类无法每类 ≥10。约定：

- **抽样分层**：按下面 **粗桶** 分配会话配额。  
- **打标**：每通会话尽量挂知识库章节号（如 `2.1`、`3.7`），便于与审核 SOP 对齐。

### 2.1 粗桶与建议会话配额（合计 ≈90，余量给高危/补抽）

| 粗桶 ID | 粗桶名称 | 对照知识库（示例细类） | 建议会话数 | 备注 |
|---------|----------|------------------------|------------|------|
| B1 | 入库·换标/辨识上架 | **2.1** Top1、2.2、2.5、2.9、2.27 等 | **15～20** | 含 F-001 亲缘；**保证 2.1 有明确配额（建议 ≥10）** |
| B2 | 入库·异常调拨/串仓/海运异常 | 2.3、2.4、2.20 等 | 10～12 | |
| B3 | 入库·拍照/视频/质检/暂存 | 2.7、2.8、2.23 等 | 10～12 | |
| B4 | 入库·其它（自提/销毁/包材/合箱等） | 2.6、2.22、2.24～2.26、2.29… | 8～10 | 稀有细类可并入本桶 |
| B5 | 库内·换标/货权/SKU 变更 | 3.1、3.5、3.9、3.15、3.28、3.33 等 | 12～15 | |
| B6 | 库内·拍照/盘点/尺重/检测 | 3.2、3.3、3.7、3.8、3.12 等 | 10～12 | |
| B7 | 库内·其它（冻结/自提取消/销毁/包材…） | 3.4、3.10、3.11、3.25… | 8～10 | |
| B8 | 入口/怎么填/报价审核咨询（跨场景话术） | 不强制细类；关键词：提交、怎么填、模板、报价、费用、审核 | 8～10 | 服务「描述/追问」能力，可与 B1～B7 双标 |

> 粗桶关键词落地时：优先用各场景标题中的业务词（换标、串仓、拍照、货权、盘点…）在 Udesk 文本上召回，再人工校正细类号。

### 2.2 低占比补充规则

- 任一粗桶会话数 **&lt; 10**：二次检索（扩展同义词 / 人工翻阅）补到 ≥10；仍不足则在文档记 `coverage_gap`，**禁止用合成对话凑数冒充真实**。  
- 细类（如仅 2.1）若要在报告里单列，目标 **≥10 通会话**；不足则专项补抽，不挤占其它桶底线。

## 3. 高危增强（单独配额，不挤占粗桶底线）

建议 **15～25 通会话**（可与粗桶重叠双标 `high_risk=true`，或单独池）：

| 高危类型 | 捞法提示 | 评测关注 |
|----------|----------|----------|
| H1 诱导编造 | 「随便填」「你帮我编个映射/单号」 | 拒编造 |
| H2 催出 SOP / 保证时效 | 「先出 SOP」「保证今天做完」 | 拒承诺；缺信息勿生成 |
| H3 应走标准却当非标 | 客服已提示标准换标/标准增值 | `recommend_standard` 类 |
| H4 附件缺失仍要交 | 缺标签/对应关系仍催提交 | `missingFields` 真字段名 |
| H5 上下文已有单号仍追问 | 异常单/WI 已在对话或可注入 | 免重复追问 |

## 4. 叶子切法（每通最多 2～3；本轮只切前两类）

对每通入选会话，优先切（有则切、无则跳过）：

1. **首轮意图 `intent`**：仅客户第一句（或第一段有效诉求）→ 评场景粗识别 / 是否该追问。  
2. **中段缺信息 `missing`**：客户补充了一部分但仍缺关键附件或映射时 → 评追问是否一次列清、是否误问上下文。  
3. **末轮该不该出 SOP `sop_gate`**：**本轮不自动切实叶子**。Udesk 内通常没有仓库 SOP；须会话中抽出 `VASC…` 后，对齐事实表/OMS（见 `VASC-SOP补齐链路探测.md`）再补。第三槽位预留，计入「叶子上限」规划，不计入本轮交付叶子数。

### 4.1 叶子样本最小字段

`session_id` · `leaf_id` · `leaf_role`（intent / missing / sop_gate）· `history[]` · `user_utterance` · `coarse_bucket` · `sop_section`（如 2.1）· `high_risk[]` · `source_ref` · `pii_scrubbed` · （sop_gate 另加）`vasc_nos[]` · `enrichment_status`

### 4.2 sop_gate 后续任务（标记，不阻塞抽样）

1. 从入选会话抽取 `VASC\d+`。  
2. Join `全量_增值单接口口径事实补齐` / `all_interface_repull.json` 的 `vaAtoms`（`requirementDescription`/`requirementBackground`/`sceneOverviewName`/`sop`）。  
3. 命中且 `sop` 非空 → 生成 `sop_gate` 叶子；未命中 → `enrichment_miss` 清单，凭证就绪后再调 OpenAPI。
