# Agent 评测方法论：6 节点全链路检查法

---

## 方法论概述

评测一个 Agent，按其完整执行链路从输入到输出逐节点检查，一共 6 个环节：

---

## 示例：评测【旅行规划】Agent

### 第一，意图理解

用户说「帮我安排下周末去杭州的两日游」，Agent 需要正确识别任务类型是【旅行规划】，并提取出关键实体：目的地=杭州、时间=下周末、天数=2天。

### 第二，任务拆解

Agent 应该把这个需求拆成若干子任务，比如查天气、查交通、规划 Day1 行程、规划 Day2 行程、推荐住宿，并且确定执行顺序和依赖关系。

### 第三，工具调用

每个子任务对应具体的工具调用。比如天气工具传参「杭州+下周末日期」、景点搜索工具传参「杭州+用户偏好」。这里重点看参数是否准确、工具是否选对。

### 第四，多步执行与状态管理

看执行顺序是否合理（比如先查天气再决定室内外行程），以及多轮对话中 Agent 是否记住了「杭州」「周末」这些上下文，不丢失不混淆。

### 第五，异常恢复

这是 Agent 评测里很关键的一环。比如天气接口超时，Agent 是重试、降级还是告知用户？某个景点满员，是否自动推荐备选？参数缺失时是否主动追问？重点看它的容错和自愈能力。

### 第六，最终输出

看是否输出了完整的 2 日行程，内容质量上行得通、不冲突，用户体验上格式清晰可读，安全上不推荐危险活动。

---

## 总结

这 6 个节点全部检查通过，这个 Agent 的评测才算覆盖完整。

| 节点 | 检查什么 | 核心关注点 |
|---|---|---|
| 1. 意图理解 | 任务类型识别 + 关键实体提取 | 准确性、完整性 |
| 2. 任务拆解 | 子任务划分 + 执行顺序 + 依赖关系 | 合理性、完整性 |
| 3. 工具调用 | 工具选择 + 参数传递 | 正确性、精确性 |
| 4. 多步执行与状态管理 | 执行顺序 + 上下文保持 | 一致性、不丢失 |
| 5. 异常恢复 | 超时/失败/缺失时的容错 | 鲁棒性、自愈能力 |
| 6. 最终输出 | 内容质量 + 格式 + 安全 | 可用性、合规性 |
