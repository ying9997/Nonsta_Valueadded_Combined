## 1 业务背景

### 1.1 当前痛点

当前非标增值的主要问题，不是单点审核效率低，而是需求源头没有被充分结构化。

客户在提交非标增值需求时，通常只描述业务目标，例如"换标""重新包装""拍照""组合"，但系统没有引导客户补齐仓库执行所需的关键信息，包括操作对象、SKU、数量、标签/包材文件、处理路径、验收标准等。

这会形成一条典型问题链路：

> 客户不会结构化表达非标需求 → 提交信息缺字段、缺附件、缺操作边界 → 审核人员人工反推和追问 → 场景分类、可执行性判断、SOP 编写依赖经验 → 审核周期变长、退回变多、仓库返工风险上升。

因此，客户侧问题是因，审核侧痛点是果。由于源头信息不足，审核人员只能在后续环节通过聊天记录、业务单据、客户附件和仓库反馈反复拼接事实、补全需求。由此导致的审核侧痛点包括：

- 审核人员需要反复追问客户补充信息。
- 审核人员需要人工识别非标场景和服务项。
- 审核人员需要判断需求是否可执行，是否需要报价或仓库确认。
- 审核人员需要将客户口语化需求改写成仓库可执行 SOP。
- 信息缺失或理解偏差容易导致审核退回、仓库返工和沟通延迟。

### 1.2 Agent 定位

Agent 应当前置介入客户提交环节，先解决"需求是否被问完整、问准确"的问题，再承接审核侧的结构化处理。

**客户侧 Agent** 的定位是：非标增值需求采集助手。它不替客户做决定，也不承诺审核结果，而是在客户提交需求时，通过动态追问把真实意图补全，并转成可审核、可执行的结构化申请。

**审核侧 Agent** 的定位是：非标增值审核 Copilot。它基于客户侧采集到的结构化信息，进一步完成场景推荐、资料完整性校验、SOP 初稿生成和审核辅助。

**V1.0 交付范围**：客户侧采集 + 审核侧 Copilot 双侧同时交付，功能深度见第 3 章。

### 1.3 业务目标

**目标一：将非标需求自动结构化**

自动识别客户描述中的关键业务信息，包括增值单号、WI/WO/EB 单号、SKU、数量、仓库、客户、操作对象、附件/标签需求、期望处理结果等，并形成结构化需求卡片。

**目标二：自动判断场景和服务项**

根据客户需求描述、历史 SOP 和场景库，推荐历史处理过的非标增值场景和服务项，并给出置信度及相似历史案例，帮助审核人员快速归类。

**目标三：做资料完整性校验**

按不同场景检查必填信息是否齐全。例如：

- 贴标/换标：是否有标签文件、贴标对象、贴标位置、处理数量。
- 商品组合/拆分：是否有新旧 SKU、数量关系、组合/拆分比例。
- 拍照/视频：是否有拍摄对象、拍摄角度、反馈要求。
- 包装/换箱：是否有包材 SKU、包装方式、加固要求。
- 入库处理：是否有关联 WI 入库单号、处理后上架方式。
- 出库/下架处理：是否有关联 WO 出库单号、下架对象和数量。

如有缺失，Agent 应生成一次性补充清单，减少多轮追问。

**目标四：生成可执行 SOP 初稿**

基于结构化需求和历史相似案例，生成仓库可执行的 SOP 初稿，内容包括背景、操作对象、数量、标签/包材、下架/上架路径、拍照反馈、异常处理和注意事项。审核人员只需确认和微调，而不是从零开始编写。

**目标五：沉淀标准化知识**

将高频非标需求沉淀为可复用模板，例如：

- 覆盖/清除标签
- 批量补贴包裹条码
- 商品组合拆分 SKU
- 拍照暂存
- 更换客制包装
- 入库异常上架
- 出库指定装箱

后续相似需求可直接复用模板，降低审核人员经验依赖。

**目标六：缩短审核和沟通周期**

通过前置采集和自动结构化，减少客户、客服、审核、仓库之间的反复沟通。

本期聚焦"需求结构化、动态追问、资料完整性校验、场景推荐、SOP 初稿生成"。"辅助审核决策"（例如建议通过、退回补充、需报价确认、需仓库确认、疑似不可执行）可作为后续迭代能力。

### 1.4 一句话概括

> 这个 Agent 不应只是聊天总结器，而应是非标增值需求采集与审核 Copilot：在客户提交需求时把真实意图问完整，在审核环节把自然语言需求转成标准场景和可执行 SOP，从源头降低客服、审核、仓库三方返工。

### 1.5 目标用户

**主要用户：外部客户**

需要提交非标增值需求的客户，包括入库、库内、出库等场景下需要贴标、换标、拍照、包装、组合/拆分、异常处理等服务的客户。

**协同用户：内部客服/审核人员**

接收客户提交的结构化需求，进行资料校验、场景判断、SOP 确认和后续审核流转。

## 2 业务目标与成功衡量

> 此处为业务价值指标，非模型指标

### 2.1 业务目标

- 降低客户提交非标增值需求的沟通成本：通过 Agent 前置引导客户补齐单号、SKU、数量、附件、标签、包材、处理路径等关键信息，减少提交后的反复追问。
- 提升非标增值需求的一次可审核率：将客户口语化描述转成结构化需求卡片，帮助审核人员更快判断场景、资料完整性和可执行性。
- 降低审核人员的信息整理和 SOP 编写耗时：自动汇总客户需求、业务单据、附件要求和历史相似场景，生成可复核的 SOP 初稿。
- 减少因需求不清导致的退回、误审和仓库返工：在提交前做完整性校验和风险提示，降低信息缺失、操作边界不清、附件错误等问题。
- 沉淀非标增值标准化场景和模板：将高频需求沉淀为可复用模板，减少对个人经验的依赖。

**硬性约束**：禁止 Agent 自动提交最终审核结论，必须由人工复核确认后流转。

### 2.4 ROI 测算

| 价值来源 | 当前成本 | 预期节省 | 周节省工时 |
|---|---:|---|---:|
| 人工追问沟通 | 40 人小时/周 | 降低 50% | **≥20 人小时/周** |
| SOP 编写（含信息整理） | 35 人小时/周 | 降低 40% | **≥14 人小时/周** |
| 首审退回重处理 | ~23.5 单/周 × 15-30 分钟 | 降低 30% | **~2-3.5 人小时/周** |
| **合计** | | | **≥36 人小时/周 ≈ 0.9 FTE** |

潜在收益（未量化）：
- 高频场景模板复用带来的长期效率提升。
- 仓库因需求不清导致的返工成本减少。
- 客户体验提升带来的客户留存价值。

风险成本：
- 若 Agent 越权查询或展示客户无权限数据，可能造成数据泄露。
- 若 Agent 误生成 SOP 或遗漏关键操作信息，可能导致仓库误操作。
- 若 Agent 错误承诺费用、时效或可执行性，可能引发客户投诉。
- 若缺少人工确认节点，可能导致错误需求进入审核或仓库执行链路。

## 3 产品范围与边界

### 3.1 V1.0 支持能力

1. 支持客户用自然语言描述非标增值需求。
2. 自动识别并抽取关键字段，包括业务单号、SKU、数量、仓库、操作对象、标签/包材、附件、客户期望达成状态等。
3. 按场景动态追问缺失信息，生成一次性补充清单。
4. 根据客户需求内容识别非标增值场景，例如贴标/换标、包装更换、商品组合、拆分 SKU、拍照暂存、异常上架等，并推荐对应的资料补充规则和 SOP 模板。
5. 生成客户确认版需求摘要，提交前必须由客户人工确认。
6. 生成两类结构化需求描述记录：
   - AI 结构化草稿：Agent 自动抽取，用于保留模型理解和追问过程。
   - 客户确认版需求：用于正式提交审核。客户可在提交前修改 AI 草稿，系统需保留修改前后差异，便于后续追溯。
7. 基于历史相似案例和规则生成仓库操作 SOP 初稿。
8. 分角色标记风险点：
   - 客户侧：展示资料缺失、需补充确认、可能进入人工审核/报价确认等提示。
   - 内部审核侧：展示场景置信度、关键字段缺失、SOP 完整性、可执行性疑点、报价/仓库确认建议等风险信息。

### 3.2 V1.0 不在范围内

1. 不支持 Agent 自动通过、驳回或提交最终审核结论。
2. 不支持绕过人工确认直接下发仓库执行。
3. 不支持跨客户、跨权限查询订单、库存、附件或历史案例。
4. 不支持对费用、时效、仓库一定可执行作确定性承诺。
5. 不支持处理所有复杂异常场景；低置信度或高风险场景必须流转人工。
6. 不支持替代现有 OMS/审批系统，只作为需求采集、审核辅助和 SOP 生成工具。

### 3.3 Agent 场景优先级

基于首审退回原因数据，V1.0 场景优先级如下：

| 优先级 | 场景 | 对应退回原因 | 当前影响 |
|---:|---|---|---:|
| P0 | 需求描述结构化与完整性检查 | 需求描述不清晰 | 131 单，占退回 37.1% |
| P0 | 仓库能力/SOP 可执行性判断 | 仓库暂时无法提供该服务 | 112 单，占退回 31.7% |
| P1 | 标准增值 vs 非标增值自动分流 | 标准增值支持此场景 | 72 单，占退回 20.4% |
| P1 | 非标准入规则校验 | 非标增值场景不符 | 38 单，占退回 10.8% |

Agent 通过需求描述结构化、必填信息检查、仓库能力识别、标准/非标分流和 SOP 推荐，预期覆盖首审退回原因的 100%，其中 P0 场景覆盖 68.8%。

## 4 关键风险清单

| 风险描述 | 风险等级 | 规避方案 |
|---|---|---|
| Agent 被诱导绕过人工确认，直接提交审核结论或执行指令 | P0 | Agent 层强制人工确认节点；后端接口校验是否经过人工确认 |
| Agent 编造业务单号、库存、SKU、数量、费用等事实 | P0 | 所有业务事实必须来自系统 API 或客户上传内容；禁止模型自行生成事实 |
| Agent 向客户输出超出其可见范围的内部信息（内部审核判据、仓库成本/产能、内部流转责任人、完整仓库 SOP、历史客户案例明细等） | P0 | 客户侧和内部侧知识权限隔离；客户侧仅输出"客户需提供什么、预计会进入什么流程、需人工/仓库确认什么" |
| Agent 跨客户查询订单、附件或历史案例 | P0 | 基于客户身份做数据权限校验；后端二次校验查询范围 |
| Agent 生成不可执行或漏步骤的仓库 SOP | P1 | SOP 只作为初稿；审核人员必须复核；关键字段缺失时禁止生成"可执行"结论 |
| 客户上传错误附件或标签文件，Agent 无法自动识别附件内容是否匹配 | P1 | V1.0 仅提示所需附件并记录上传状态；附件内容与 SKU 一致性由人工复核；后续迭代引入附件解析能力 |
| 场景识别错误导致服务项选择错误 | P1 | 输出置信度和相似案例；低置信度自动转人工 |
| 客户误以为 Agent 回复等于审核通过或仓库承诺 | P1 | 对外话术明确"需审核/需确认"；禁止承诺费用、时效和最终结果 |
| 历史案例复用不当，导致新需求被错误套模板 | P2 | 相似案例仅作参考；保留差异项提示；人工确认后才可使用 |

## 6 上线前置条件

1. 业务方确认 V1.0 支持场景、字段范围、客户可见内容和人工兜底边界。
2. 完成评测数据集建设，覆盖主要非标增值场景及通过、退回、需报价、需仓库确认、低置信度转人工等样例。
3. 业务/审核团队完成样例标注，并确认评测标准。
4. 关键场景评测达到上线准入基线：字段抽取准确率、缺失信息识别率、场景推荐准确率、SOP 初稿可用率、风险识别召回率达到约定阈值。
5. P0 风险对抗测试通过，P0 错误数 = 0。
6. 完成客户侧和内部侧权限隔离校验，确保客户不可见内部审核规则、完整仓库 SOP、历史客户案例和内部风险判断。
7. 完成人工确认与兜底流程：客户提交前必须确认，低置信度、高风险、资料缺失、客户争议场景必须转人工/人工复核。
8. 完成日志、审计、灰度发布和回滚机制配置。
9. 灰度上线后持续跟踪业务指标（详见 2.3 节）。

## 7 非目标

- 本版本不追求 100% 自动完成所有非标增值需求。
- 本版本不替代人工审核，不自动给出最终审核结论。
- 本版本不承诺费用、时效或仓库一定可执行。
- 本版本不覆盖全部复杂异常场景；复杂、高风险、低置信度场景允许流转人工处理。
- 本版本不替代 OMS、审批系统或仓库执行系统，只提供需求采集、结构化、审核辅助和 SOP 初稿能力。

## 8 待确认事项

以下事项需业务方在评审中确认：

1. 是否以 OMS `vas_type = NON_STANDARD_VASC` 作为"非标增值单量"统计口径。
2. 人工追问沟通耗时 40 人小时/周是否符合业务体感。
3. 每单 SOP 编写耗时 8 分钟是否符合实际（含信息整理时间）。
4. 首审退回率分母是否采用"有明确审核结果单量"（15.4%），若按"提交审核单量"则为 13.2%。
5. 补问关键词规则是否符合业务理解。
6. 外部依赖各项的 Owner 和就绪状态。
7. V1.0 上线时间预期。
