# 非标页 AI 智能引导 Agent 指引框 5 套方案

> 交付范围：基于万邑联现有非标增值 Step 2 页面做内嵌 AI 指引框原型。  
> 页面基准：`增值配置AI化/增值单ai指引助手/万邑联-处理异常-第二步-填写增值产品信息（核心-非标增值）.html`  
> 本次只输出页面原型与技术落点，不改原线上页面快照。

## 0. 固定业务与前端规则

本批原型统一遵守：

- `vascType` 只允许 `standard` / `nonstandard` / `unknown`。`unknown` 对应 `routeBranch = manual_fallback`，渲染为人工兜底提示态，提示“候选类型无法自动确认，请联系客服或人工选择服务项”，禁用所有 `fill_field` 类 `pageActions`。
- 废弃 `sopTemplateMatched`，统一使用 `matchState` + `matchConfidence`。
- `pageActions` 由后端下发数组控制页面按钮展示、可用状态和目标字段。
- SOP 匹配阈值：`matchConfidence >= 0.82` 为 `matched`，`0.62 <= matchConfidence < 0.82` 为 `partial`，`matchConfidence < 0.62` 为 `none` 并触发兜底引导。
- 多轮状态仅按当前页面 `localStorage` 缓存，key 包含 `location.pathname` 和 `eventNo`，不做跨页面持久化。
- 所有容器禁止内部滚动，页面只依赖 body 纵向滚动。
- 表单卡片一行多列紧凑排布。
- 指引点位统一使用 `data-guide-point`，注入字段使用 `data-bind-field`。
- 保留现有业务字段 ID：`vaAtoms_OW01V1602_attributes_VAS_ATTR_REL_RD_attributeValue`、`vaAtoms_OW01V1602_attributes_BEOR_attributeValue`、`vaAtoms_OW01V1602_vasFiles_VAS_ATTR_REL_AOOI`。

## 1. 方案一：顶部全宽嵌入式 AI 指引框

代码文件：`prototype_01_top_inline_panel.html`

### 1.1 方案名称 & 核心定位

顶部全宽嵌入式 AI 指引框。  
一期可落地，适合所有进入非标 Step 2 的客户先描述需求，再由 AI 分流到 2d/2a/2b。

### 1.2 指引框内嵌挂载物理位置

挂载在 `增值产品信息` 卡片上方、Step 2 步骤条下方、原业务表单之前。  
锚点：`data-guide-point="ai-top-inline-panel"`。

### 1.3 交互触发规则

- 默认展示空态输入框。
- 用户输入后点击【发送】触发。
- 可通过模拟按钮切换 2d、2a、2b、低置信兜底。
- `matchConfidence < 0.62` 时，在同一指引框内展示兜底话术。

### 1.4 优缺点、干扰度、工作量、维护成本

| 项 | 结论 |
|----|------|
| 优点 | 入口明显，客户进入页面第一时间知道先描述需求；三类路由展示最完整。 |
| 缺点 | 占用页面首屏高度，表单整体下移。 |
| 对原表单干扰度 | 中，改变页面首屏信息密度，但不遮挡字段。 |
| 前端改造工作量 | 中，需在表单前新增完整组件。 |
| 后期维护成本 | 低，挂载点固定，和字段 DOM 解耦。 |

### 1.5 边界风险

- 不遮挡填写框。
- 不影响保存草稿/提交按钮。
- 无弹窗层级冲突。
- 风险是首屏变长，移动端客户需先滑动才能看到部分字段。

### 1.6 本期不做能力

- 不接真实接口。
- 不做自动提交。
- 不做跨页面会话持久化。
- 不做复杂附件内容识别。
- 不做视频 SOP 解析。

## 2. 方案二：表单右侧伴随式 AI 指引列

代码文件：`prototype_02_right_companion_column.html`

### 2.1 方案名称 & 核心定位

表单右侧伴随式 AI 指引列。  
一期可落地但依赖页面宽度，适合桌面端、客服/销售协助客户边填边看。

### 2.2 指引框内嵌挂载物理位置

挂载在 `增值产品信息` 卡片右侧，与原业务表单组成左右两列。  
锚点：`data-guide-point="ai-right-companion-column"`。

### 2.3 交互触发规则

- 默认展示右侧 AI 输入区。
- 客户点击【判断】手动触发。
- 后端 `pageActions` 控制右侧动作按钮是否可用。
- 低置信度时在右侧列展示兜底追问，不影响左侧字段填写。

### 2.4 优缺点、干扰度、工作量、维护成本

| 项 | 结论 |
|----|------|
| 优点 | 表单和指引同屏，字段填入反馈清晰；不压缩纵向流程。 |
| 缺点 | 小屏宽度不足时会自动上下堆叠，桌面端收益更高。 |
| 对原表单干扰度 | 中，改变表单容器栅格。 |
| 前端改造工作量 | 中高，需要调整 Step 2 主区域布局。 |
| 后期维护成本 | 中，需跟随响应式布局维护。 |

### 2.5 边界风险

- 不使用 fixed 侧栏，不遮挡字段。
- 不影响提交按钮。
- 无弹窗层级冲突。
- 风险是宽屏适配和列宽压缩导致表单列过窄。

### 2.6 本期不做能力

- 不做悬浮右侧栏。
- 不做跨页面会话同步。
- 不做自动滚动和高亮。
- 不做真实附件读取。

## 3. 方案三：字段旁内联微指引

代码文件：`prototype_03_field_inline_guides.html`

### 3.1 方案名称 & 核心定位

字段旁内联微指引。  
一期可局部落地，适合客户已经知道选择“入库其他服务需求”，但不知道如何写 `需求描述` / `需求背景说明` 的场景。

### 3.2 指引框内嵌挂载物理位置

挂载在 `需求描述` textarea 下方、`需求背景说明` textarea 上方。  
锚点：`data-guide-point="ai-description-inline"`。

### 3.3 交互触发规则

- 客户聚焦到字段或手动点击生成按钮触发。
- 只围绕字段写入动作展示按钮。
- 2d 命中时提示不要继续填非标字段。
- 低置信度时只在字段旁展示模板追问。

### 3.4 优缺点、干扰度、工作量、维护成本

| 项 | 结论 |
|----|------|
| 优点 | 对原页面首屏影响小，和字段落点强绑定。 |
| 缺点 | 对 2d/2a 路由前置教育弱，客户可能先选错服务项。 |
| 对原表单干扰度 | 低，只插入目标字段附近。 |
| 前端改造工作量 | 低到中，主要在字段块内插入组件。 |
| 后期维护成本 | 中，字段 DOM 改名或排序会影响挂载点。 |

### 3.5 边界风险

- 不遮挡字段。
- 不影响提交。
- 无弹窗层级冲突。
- 风险是字段附近信息密度变高，长文案会拉长服务要求列。

### 3.6 本期不做能力

- 不做整页路由前置强引导。
- 不做字段自动聚焦、自动滚动。
- 不做跨字段复杂联动。

## 4. 方案四：低置信度页内强提醒

代码文件：`prototype_04_low_confidence_inpage_notice.html`

### 4.1 方案名称 & 核心定位

低置信度页内强提醒。  
一期可作为风险控制组件落地，适合 AI 判断不稳定、`matchConfidence < 0.62` 时强制提示客户补充 SOP 模板字段。

### 4.2 指引框内嵌挂载物理位置

挂载在 Step 2 步骤条下方、增值产品表单上方。  
锚点：`data-guide-point="ai-low-confidence-force-notice"`。

### 4.3 交互触发规则

- 默认可自动触发低置信度提醒。
- `matchConfidence < 0.62` 时强制展示兜底追问。
- 2d/2a/2b 正常命中时，提醒区降级为普通状态说明。
- 不使用弹窗，不阻塞表单填写。

### 4.4 优缺点、干扰度、工作量、维护成本

| 项 | 结论 |
|----|------|
| 优点 | 对低置信风险收口明确，能防止 AI 编造 SOP。 |
| 缺点 | 不是完整主入口，更多是风险兜底组件。 |
| 对原表单干扰度 | 中，低置信时提醒强但仍在文档流内。 |
| 前端改造工作量 | 中，需要接入置信度状态并控制展示样式。 |
| 后期维护成本 | 低，阈值和话术集中维护。 |

### 4.5 边界风险

- 不遮挡填写框。
- 不阻止提交，只提示不建议直接提交。
- 无弹窗层级冲突。
- 风险是客户可能忽略提醒后仍提交，本期不做强制拦截。

### 4.6 本期不做能力

- 不做提交强拦截。
- 不做人工客服自动转接。
- 不做完整 SOP 编辑器。

## 5. 方案五：提交前底部复核式 AI 指引框

代码文件：`prototype_05_bottom_pre_submit_review.html`

### 5.1 方案名称 & 核心定位

提交前底部复核式 AI 指引框。  
一期可低侵入落地，适合客户先按原流程填写，最后在保存草稿或提交前检查字段完整性。

### 5.2 指引框内嵌挂载物理位置

挂载在底部 `上一步 / 保存草稿 / 提交` 按钮上方。  
锚点：`data-guide-point="ai-bottom-pre-submit-review"`。

### 5.3 交互触发规则

- 默认不打断填写。
- 点击【提交前复核】手动触发。
- 低置信度时提示“请先补齐 SOP 模板字段后再提交”。
- `pageActions` 可生成填入按钮或复制建议。

### 5.4 优缺点、干扰度、工作量、维护成本

| 项 | 结论 |
|----|------|
| 优点 | 对原页面干扰最小，适合快速灰度。 |
| 缺点 | 引导时机偏晚，客户可能已经投入较多填写成本。 |
| 对原表单干扰度 | 低。 |
| 前端改造工作量 | 低，只需在底部按钮上方插入组件。 |
| 后期维护成本 | 低。 |

### 5.5 边界风险

- 不遮挡填写框。
- 不改变提交按钮逻辑。
- 无弹窗层级冲突。
- 风险是无法提前纠偏 2d 标准增值路径，用户可能到最后才发现应返回标准增值。

### 5.6 本期不做能力

- 不做保存草稿/提交前强制校验拦截。
- 不做自动提交。
- 不做跨页面缓存。

## 7. 一期 MVP 首选方案

首选：方案一“顶部全宽嵌入式 AI 指引框”。

理由：

- 最符合“客户进入非标页后先自然语言描述需求”的主线目标。
- 能完整承载 2d 标准纠偏、2a 命名非标直选、2b 其他服务需求 + SOP 三类分支。
- `pageActions`、字段填入、附件提示、低置信兜底都能在同一组件中闭环。
- 不使用弹窗、不遮挡表单、不改提交逻辑，风险可控。

一期 MVP 建议范围：

- 落地方案一。
- 同步保留方案四的低置信兜底样式作为方案一内部状态。
- 暂不做自动滚动、高亮、提交拦截、跨页面缓存、视频 SOP 解析。

## 8. 二期迭代升级路径

1. 二期 A：在方案一基础上增加字段定位能力，对 `data-bind-field` 目标字段做轻量高亮和定位。
2. 二期 B：桌面端引入方案二右侧伴随列，满足客服/销售协助场景。
3. 二期 C：对高频字段补充方案三字段旁微指引，用于减少字段填写阻力。
4. 二期 D：对 `matchState = none` 的低置信场景接入人工确认或客服转接，但仍不自动提交。
5. 二期 E：独立开展视频 SOP 解析，不并入本期原型。
