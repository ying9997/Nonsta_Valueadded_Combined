# 20260728_candidate-normalize-contract 候选清单归一化契约切片

> 目标：基于万邑联创建增值订单 Step 2 原始业务表单，增量新增 AI 指引 Agent 模块。  
> 原则：左侧服务勾选、中间 5 个输入项、右侧附件按钮、底部操作按钮的 DOM 结构、字段 ID、列宽比例不重构。

## 0. 原始页面结构锁定

四套 HTML 原型均保留同一套业务表单骨架：

| 区域 | 保留内容 |
|------|----------|
| 左侧增值服务 | `包裹串仓异常调拨`、`入库其他服务需求` 两个勾选框 |
| 中间服务要求 | `包裹条码`、`商品条码`、`上架入库单号`、`需求描述`、`需求背景说明` 纵向排列 |
| 右侧增值文件 | `操作说明附件`、`商品和标签的对应关系`、`包裹和标签的对应关系`、`标签文件` |
| 底部按钮 | `上一步`、`保存草稿`、`提交` |

字段绑定：

- `data-guide-point`：所有 AI 挂载点和业务锚点。
- `data-bind-field="description"`：`需求描述`。
- `data-bind-field="background"`：`需求背景说明`。
- 原始字段 ID 保留：`vaAtoms_OW01V1602_attributes_VAS_ATTR_REL_RD_attributeValue`、`vaAtoms_OW01V1602_attributes_BEOR_attributeValue`、`vaAtoms_OW01V1602_vasFiles_VAS_ATTR_REL_AOOI`。

业务规则：

- `vascType`：`standard` / `nonstandard`。
- 不使用 `sopTemplateMatched`。
- 使用 `matchState` + `matchConfidence`。
- `pageActions` 控制按钮可用状态。
- 置信度基线：`FALLBACK_THRESHOLD = 0.7`；低于 0.7 触发 SOP 模板追问。
- 多轮会话只写当前页 `localStorage`，key 包含 `location.pathname` 和当前 `eventNo`。

## 1. 方案1：顶部标题栏内嵌版

完整 HTML：`prototype_01_titlebar_inline.html`

### 摆放点位说明

挂载在 `增值产品信息` 大标题正下方、业务表格上方。  
锚点：`data-guide-point="ai-titlebar-inline"`。

### 交互逻辑

- 页面加载自动展示。
- 客户先输入自然语言需求，再点击【判断】。
- 同一通栏承载 2d 标准纠偏、2a 命名非标直选、2b SOP 判断、低置信兜底追问。
- `pageActions` 控制【填入需求背景说明】【填入需求描述】【复制建议】。

### 用户体验干扰度

中。AI 模块占用表单上方一行空间，但不改变原业务表格列宽和字段顺序。

### 前端工作量

中。需要在标题栏下新增一块 AI 通栏组件，并接入候选清单归一化结果与 `pageActions`。

### 一期是否推荐

推荐 P0。它最适合承载完整前置分流。

### 优缺点

| 优点 | 缺点 |
|------|------|
| 入口明显，客户进入页面即可看到；三类分支都能前置处理；不遮挡表单。 | 首屏高度增加，表单整体略向下。 |

## 2. 方案2：右侧侧边常驻抽屉版

完整 HTML：`prototype_02_right_fixed_drawer.html`

### 摆放点位说明

挂载在页面最右侧，附件栏右边的独立窄边栏。  
锚点：`data-guide-point="ai-right-fixed-drawer"`。

### 交互逻辑

- 默认展开，也可点击【AI】收起。
- 客户边填写表单边查看 AI 判断。
- 完全不改变业务表格宽度，业务表格仍为 1180px 固定宽。
- 低置信时在右侧面板展示 SOP 模板追问。

### 用户体验干扰度

低到中。对表单 DOM 零侵入，但窄屏下右侧固定面板需要页面可视宽度足够。

### 前端工作量

中。需要新增固定右侧面板、展开收起状态和响应式安全边界。

### 一期是否推荐

P1。适合桌面端和运营辅助场景，不作为唯一 MVP。

### 优缺点

| 优点 | 缺点 |
|------|------|
| 表单主体完全不动；客户可以边填边看；不挤压中间输入框。 | 对屏幕宽度敏感；固定面板需要处理小屏安全区。 |

## 3. 方案3：表单项跟随悬浮弹窗版

完整 HTML：`prototype_03_field_follow_popover.html`

### 摆放点位说明

精准挂靠在【需求描述】输入框下方。  
锚点：`data-guide-point="ai-description-field-anchor"`。

### 交互逻辑

- 聚焦【需求描述】时弹出。
- 失去焦点后自动收起。
- 当 `matchConfidence < 0.7` 时强制保持展开，提示按 SOP 模板补齐。
- 只针对 `需求描述` 和 `需求背景说明` 两个核心字段给出填入动作。

### 用户体验干扰度

中。只影响需求描述附近，但属于局部悬浮层，需要控制高度和文案长度。

### 前端工作量

中。需要绑定字段聚焦/失焦事件和低置信强制展开状态。

### 一期是否推荐

P1。不建议作为第一入口，适合作为字段补写增强。

### 优缺点

| 优点 | 缺点 |
|------|------|
| 精准围绕核心字段；不会影响左侧服务勾选和右侧附件控件。 | 不适合做前置 2d 标准纠偏；局部面板文案过长时容易压迫字段区。 |

## 4. 方案4：底部悬浮唤起按钮兜底版

完整 HTML：`prototype_04_bottom_fab_modal.html`

### 摆放点位说明

右下角悬浮小圆按钮，点击后弹出居中模态对话框。  
锚点：`data-guide-point="ai-bottom-fab"`。

### 交互逻辑

- 用户主动点击【AI】唤起。
- `matchConfidence < 0.7` 时按钮红点角标提醒。
- 弹窗内执行判断、生成字段建议、复制兜底追问。
- 对原表单零侵入，不改任一业务字段位置。

### 用户体验干扰度

低。默认只显示右下角按钮，不影响正常填写；打开后模态会覆盖页面，但由用户主动触发。

### 前端工作量

低到中。实现简单，但要处理弹窗层级、焦点和关闭行为。

### 一期是否推荐

P2。适合作为兜底入口，不适合作为主引导入口。

### 优缺点

| 优点 | 缺点 |
|------|------|
| 对页面侵入最低；实现快；适合灰度试水。 | 引导弱，客户可能不点击；弹窗打开时会临时覆盖页面。 |

## 6. MVP 一期推荐

推荐优先使用：方案1 顶部标题栏内嵌版。

原因：

- 能在客户填写前完成 2d/2a/2b 路由判断。
- 不改变原业务表格列宽和输入框顺序。
- 不使用弹窗遮挡。
- 可以承载需求描述前置引导、SOP 判断、低置信兜底追问和 `pageActions` 字段注入。

一期落地建议：

1. 主方案采用方案1。
2. 将方案4的红点低置信提醒作为后续兜底入口保留，不进入第一版主流程。
3. 暂不做自动提交、强制拦截、跨页面缓存、前端动态改阈值、附件内容识别。

## 7. 二期路径

- 二期 A：在方案1基础上补字段轻量高亮，但仍不移动原字段。
- 二期 B：桌面端补方案2右侧常驻抽屉，提升边填边看效率。
- 二期 C：核心字段补方案3字段跟随微指引。
- 二期 D：方案4作为低置信兜底入口，接人工确认或客服转接。
