# 候选清单归一化契约

> 模块：非标页内嵌智能引导  
> 切片：Agent 运行时候选输入归一化契约  
> 范围：仅定义中间层输出给 Agent 的候选输入数据规范；不定义页面原型、接口联调逻辑、评测用例或中间层拼接实现代码。  
> 基准：本模块 `README.md` / `HANDOFF.md` 的 2d、2a、2b 分支定义，以及 `value-add-service-guide` 的 SCHEMA、source-references、relationship-mappings、normalized 数据快照范式。

## 1. 契约目标

1. 本契约定义 `systemScopedVascList[]` 中单个候选对象的归一后结构。
2. 本契约供 Agent 在运行时读取候选输入，不供 Agent 反向推断候选类型。
3. 本契约约束中间层必须输出 `vascType` 和 `serviceKind`。
4. 本契约不承诺中间层如何调用、拼接或缓存 `listAllVasc`、`getVascInfo`、`getVasList`。
5. 本契约不替代 `relationship-mappings/` 中对业务适用性、支持条件和实体关系的权威判断。

## 2. 当前接口现状

| 接口 | 当前可用字段 | 当前缺失字段 | 本契约处理 |
|------|--------------|--------------|------------|
| `pms.vasc.listAllVasc` | `vascCode`、`vascName`、`vascAttributeMap` 等候选产品基础字段 | 原生无 `vascType`；原生无 `serviceKind` | `vascType`、`serviceKind` 必须由中间层补充注入；不得由 Agent 根据名称猜测 |
| `pms.vasc.getVascInfo` | 单个 VASC 详情、原子列表等详情字段 | 原生无 `vascType`；原生无 `serviceKind` | `vascType`、`serviceKind` 必须由中间层补充注入；不得由 Agent 根据服务名称猜测 |
| `wh.va.order.getVasList` | 已下单增值原子列表；响应中存在 `vasType` / `vasTypeName` | 不是 Step 2 候选清单的权威来源 | 可作为历史或已下单数据参考；不得直接替代 Step 2 候选清单的 `vascType` 注入 |

## 3. 顶层结构

```json
{
  "candidateListVersion": "candidate-normalization-v1",
  "normalizationGeneratedAt": "2026-07-28T18:00:00+08:00",
  "systemScopedVascList": []
}
```

| 字段 | 类型 | 必填 | 取值或格式 | 说明 |
|------|------|------|------------|------|
| `candidateListVersion` | string | 是 | 固定 `candidate-normalization-v1` | 候选归一化契约版本 |
| `normalizationGeneratedAt` | string | 是 | ISO 8601 时间 | 中间层生成候选快照的时间 |
| `systemScopedVascList` | array | 是 | `NormalizedCandidate[]` | 当前页面和系统上下文圈定的候选清单 |

## 4. 归一后候选对象字段定义

### 4.1 必填字段

| 字段 | 类型 | 必填 | 枚举/格式 | 来源责任 | 说明 |
|------|------|------|-----------|----------|------|
| `candidateId` | string | 是 | `${vascCode}:${serviceCode}` 或 `${vascCode}:__vasc__` | 中间层生成 | 候选对象稳定 ID，同一快照内唯一 |
| `vascCode` | string | 是 | 非空字符串；未知时固定 `UNKNOWN_VASC` | 原始接口或中间层兜底 | 增值产品编码 |
| `vascName` | string | 是 | 非空字符串；未知时固定 `未知增值产品` | 原始接口或中间层兜底 | 增值产品名称 |
| `serviceCode` | string | 是 | 非空字符串；产品级候选固定 `__vasc__`；未知固定 `UNKNOWN_SERVICE` | 原始接口或中间层兜底 | 增值服务项/原子编码 |
| `serviceName` | string | 是 | 非空字符串；产品级候选可等于 `vascName`；未知固定 `未知服务项` | 原始接口或中间层兜底 | 增值服务项/原子名称 |
| `vascType` | string | 是 | `standard` / `nonstandard` / `unknown` | 中间层补充注入 | 标准/非标类型；`listAllVasc`、`getVascInfo` 原始接口无法直接获取 |
| `serviceKind` | string | 是 | `standard_service` / `named_nonstandard` / `other_service_request` / `unknown` | 中间层补充注入 | 服务语义类型；禁止 Agent 仅凭名称猜测 |
| `sourceApi` | string | 是 | 见 5.4 | 中间层填充 | 候选主来源接口或中间层标准化来源 |
| `normalizationStatus` | string | 是 | 见 5.5 | 中间层填充 | 当前候选归一化状态 |
| `routeBranch` | string | 是 | `2d_standard_redirect` / `2a_named_nonstandard_direct` / `2b_other_service_sop` / `manual_fallback` | 中间层按枚举映射填充 | Agent 可使用的分支提示，不代表最终命中结果 |
| `originalFields` | object | 是 | key/value object | 中间层填充 | 原始字段追溯；必须保留已读取到的原字段名和值 |
| `normalizationNotes` | array | 是 | string[] | 中间层填充 | 归一化说明；无说明时为空数组 |

### 4.2 可选字段

| 字段 | 类型 | 必填 | 枚举/格式 | 说明 |
|------|------|------|-----------|------|
| `serviceDomain` | string | 否 | `inbound` / `in_warehouse` / `outbound` / `return` / `unknown` | 服务场景域；2b 其他服务需求必须填写 |
| `sourceFieldMap` | object | 否 | key/value object | 标注标准字段来自哪些原始字段或中间层规则 |
| `rawSourceApis` | array | 否 | string[] | 同一候选合并过的原始来源接口列表 |
| `relationshipMappingRefs` | array | 否 | string[] | 可追溯的关系映射路径或映射 ID |
| `confidence` | number | 否 | 0 到 1 | 中间层对归一结果的置信度；不得由 Agent 改写 |
| `isCandidateSelectable` | boolean | 否 | true / false | 当前页面是否可选择该候选 |
| `candidateScope` | string | 否 | `current_page` / `system_scoped` / `history_reference` / `unknown` | 候选作用域 |

## 5. 枚举定义

### 5.1 `vascType`

| 枚举值 | 含义 | 可路由分支 | 通过条件 |
|--------|------|------------|----------|
| `standard` | 标准增值产品或标准服务候选 | 仅允许进入 2d | 中间层已从配置、关系映射或可信来源确认其为标准增值 |
| `nonstandard` | 非标增值产品或非标服务候选 | 可进入 2a 或 2b | 中间层已从配置、关系映射或可信来源确认其为非标增值 |
| `unknown` | 标准/非标类型无法确认 | 仅允许 `manual_fallback` | 中间层无法确认；Agent 不得根据 `vascName` 或 `serviceName` 自行推断 |

### 5.2 `serviceKind`

| 枚举值 | 含义 | 可路由分支 | 判定责任 |
|--------|------|------------|----------|
| `standard_service` | 标准增值可覆盖的服务 | 2d 标准增值纠偏 | 中间层注入 |
| `named_nonstandard` | 命名类具体非标服务项；不是“其他服务需求” | 2a 命名/具体非标服务直选 | 中间层注入 |
| `other_service_request` | 入库/库内/出库其他服务需求类兜底服务项 | 2b 其他服务需求 + SOP | 中间层注入 |
| `unknown` | 服务语义类型无法确认 | `manual_fallback` | 中间层注入；Agent 不得猜测 |

### 5.3 `serviceDomain`

| 枚举值 | 含义 | 适用约束 |
|--------|------|----------|
| `inbound` | 入库类其他服务需求 | `serviceKind = other_service_request` 时可用于 2b SOP 分支 |
| `in_warehouse` | 库内类其他服务需求 | `serviceKind = other_service_request` 时可用于 2b SOP 分支 |
| `outbound` | 出库类其他服务需求 | `serviceKind = other_service_request` 时可用于 2b SOP 分支 |
| `return` | 退货类服务需求 | 本模块默认不作为核心分支；如出现应进入人工兜底或另行定义 |
| `unknown` | 场景域无法确认 | 不得自动进入 2b；进入 `manual_fallback` |

### 5.4 `sourceApi`

| 枚举值 | 含义 | 使用边界 |
|--------|------|----------|
| `pms.vasc.listAllVasc` | 前端候选产品列表来源 | 原生无 `vascType`、`serviceKind` |
| `pms.vasc.getVascInfo` | 单个 VASC 详情来源 | 原生无 `vascType`、`serviceKind` |
| `wh.va.order.getVasList` | 已下单增值原子列表来源 | 有 `vasType`，但不是 Step 2 候选权威来源 |
| `middleware.normalizedCandidateList` | 中间层归一后的候选清单 | 推荐作为 Agent 运行时唯一输入来源 |
| `unknown` | 来源无法确认 | 必须进入 `manual_fallback` |

### 5.5 `normalizationStatus`

| 枚举值 | 含义 | Agent 处理 |
|--------|------|------------|
| `raw_passthrough` | 字段直接来自原始接口，未做语义补充 | 可读取基础编码和名称；不得自动使用缺失的类型字段 |
| `middleware_enriched` | 中间层已补齐 `vascType`、`serviceKind` 等语义字段 | 可参与 2d/2a/2b 路由判断 |
| `middleware_mapped_from_reference` | 中间层依据关系映射、配置快照或标准数据集完成映射 | 可参与路由；需保留 `relationshipMappingRefs` 或来源说明 |
| `missing_required_type` | 缺少 `vascType` 或 `serviceKind` | 不得自动路由；进入 `manual_fallback` |
| `conflict` | 多来源字段冲突 | 不得自动路由；进入 `manual_fallback` 并提示人工确认 |
| `unsupported_source` | 来源不在本契约支持范围内 | 不得自动路由；进入 `manual_fallback` |

### 5.6 `routeBranch`

| 枚举值 | 含义 | 前置字段要求 |
|--------|------|--------------|
| `2d_standard_redirect` | 标准增值纠偏候选 | `vascType = standard` 且 `serviceKind = standard_service` |
| `2a_named_nonstandard_direct` | 命名/具体非标服务直选候选 | `vascType = nonstandard` 且 `serviceKind = named_nonstandard` |
| `2b_other_service_sop` | 其他服务需求 + SOP 候选 | `vascType = nonstandard` 且 `serviceKind = other_service_request` 且 `serviceDomain` 为 `inbound` / `in_warehouse` / `outbound` |
| `manual_fallback` | 人工兜底或继续人工确认 | 任一关键字段为 `unknown`、缺失、冲突或不支持 |

## 6. 归一化规则

### 6.1 基础字段规则

1. `vascCode` 优先取原始接口同名字段；若原始字段为空，固定填 `UNKNOWN_VASC`。
2. `vascName` 优先取原始接口同名字段；若原始字段为空，固定填 `未知增值产品`。
3. `serviceCode` 优先取服务项或原子编码字段；若候选为产品级候选，固定填 `__vasc__`；若缺失且不是产品级候选，固定填 `UNKNOWN_SERVICE`。
4. `serviceName` 优先取服务项或原子名称字段；若候选为产品级候选，可等于 `vascName`；若缺失，固定填 `未知服务项`。
5. `candidateId` 必须由 `vascCode` 和 `serviceCode` 组成；同一快照内不得重复。

### 6.2 类型字段规则

1. `vascType` 必须由中间层输出。
2. `serviceKind` 必须由中间层输出。
3. `listAllVasc` 原始响应没有 `vascType` 和 `serviceKind` 时，中间层必须从可信配置、关系映射或预置字典补齐；不能补齐时填 `unknown`。
4. `getVascInfo` 原始响应没有 `vascType` 和 `serviceKind` 时，中间层必须从可信配置、关系映射或预置字典补齐；不能补齐时填 `unknown`。
5. `getVasList` 的 `vasType` 只可作为已下单数据参考；如用于候选归一化，`sourceApi` 必须标注为 `wh.va.order.getVasList`，`candidateScope` 必须标注为 `history_reference` 或说明非 Step 2 权威候选。
6. Agent 禁止根据 `vascName`、`serviceName`、中文关键词、相似服务名称或历史对话自行推断 `standard` / `nonstandard`。

### 6.3 其他服务需求规则

1. `serviceKind = other_service_request` 时，`serviceDomain` 必须为 `inbound`、`in_warehouse`、`outbound` 三者之一；否则必须进入 `manual_fallback`。
2. 入库其他服务需求：`serviceDomain = inbound`，可进入 2b。
3. 库内其他服务需求：`serviceDomain = in_warehouse`，可进入 2b。
4. 出库其他服务需求：`serviceDomain = outbound`，可进入 2b。
5. 其他服务需求不得被 Agent 当成命名类具体非标服务项。

### 6.4 路由关联规则

| 条件 | 路由分支 | Agent 行为边界 |
|------|----------|----------------|
| `vascType = standard` 且 `serviceKind = standard_service` | `2d_standard_redirect` | 可建议返回标准增值路径；不生成非标 SOP 字段建议 |
| `vascType = nonstandard` 且 `serviceKind = named_nonstandard` | `2a_named_nonstandard_direct` | 可建议选择候选内命名非标服务项；不进入 SOP 长追问 |
| `vascType = nonstandard` 且 `serviceKind = other_service_request` 且 `serviceDomain` 有效 | `2b_other_service_sop` | 可进入 SOP 模板匹配、结构化追问、客户确认、字段建议 |
| `vascType = unknown` 或 `serviceKind = unknown` | `manual_fallback` | 不得自动分流；提示缺少类型字段，需要中间层或人工确认 |
| `normalizationStatus = conflict` | `manual_fallback` | 不得自动分流；提示多来源冲突 |
| `sourceApi = unknown` 或 `normalizationStatus = unsupported_source` | `manual_fallback` | 不得自动分流；提示来源不受支持 |

## 7. 来源追溯规则

1. 每条候选必须保留 `sourceApi`。
2. 每条候选必须保留 `originalFields`，至少包含原始 `vascCode`、`vascName`、`serviceCode`、`serviceName` 中可获得的字段。
3. 每条由中间层补充类型字段的候选，必须在 `sourceFieldMap.vascType` 和 `sourceFieldMap.serviceKind` 标注补充来源。
4. 如归一化依据关系映射或配置快照，必须在 `relationshipMappingRefs` 或 `normalizationNotes` 标明依据。
5. 接口文档只能作为字段名、响应结构和来源依据；业务适用性仍以关系映射、配置或人工确认后的字典为准。

## 8. 严格禁止项

1. 禁止 Agent 仅凭 `vascName` 或 `serviceName` 猜测 `standard` / `nonstandard`。
2. 禁止 Agent 仅凭“其他服务需求”等名称自行决定入库、库内或出库域。
3. 禁止 Agent 推荐 `systemScopedVascList` 候选外服务。
4. 禁止把 `wh.va.order.getVasList` 的 `vasType` 直接当作 Step 2 候选清单的权威类型字段。
5. 禁止在 `vascType` 或 `serviceKind` 缺失时继续自动进入 2d、2a、2b。
6. 禁止本契约承诺接口拼接、页面写入、自动提交、审核通过、费用预估、附件解析或评测通过。
