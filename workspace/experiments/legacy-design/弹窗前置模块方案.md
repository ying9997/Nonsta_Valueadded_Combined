# 弹窗前置模块方案 — 标准页 AI 下单指引

> 日期：2026-07-29
> 模块：Track B — 标准页 AI 下单指引弹窗
> 定位：方案乙前置模块，服务于标准页到非标页的智能分流
> 依赖：`design/方案文档.md` §2.5 已定义定位/行为/输出
> 本文档补齐：prompt 决策树、输出 schema、评测集设计、前端交互边界

## 1. 弹窗核心任务

用一句话概括：**判断客户的真实处理目标是否能由当前候选内的标准增值覆盖。**

- 能覆盖 → 在弹窗内给出操作路径参考（选哪个处理方式/标准产品），不跳转
- 不能覆盖 → 引导客户点击【我要提非标增值】，跳转非标页并传 popupContext

## 2. 决策树

```text
输入 =
  客户自然语言（弹窗内输入）
  + 异常单上下文（eventCode, exceptionNode, exceptionObject）
  + systemScopedVascList（中间层注入，含标准+非标候选）

1. 意图理解
   - 提取客户处理目标关键词
   - 匹配意图三元组（参照 references/rules/intent-routing/*.md）

2. 标准增值覆盖判定
   - 遍历 systemScopedVascList 中 vascType="standard" 的候选
   - 判断客户目标是否与某个标准候选的意图匹配
   - 若匹配 → routeDecision = "standard"
   - 若不匹配或信息不足 → 进入步骤 3

3. 信息补充（可选追问）
   - 若客户描述模糊，最多追问 1 轮
   - 追问方向：处理方式（上架/销毁/自提/其他）、是否需要换包装/贴标
   - 追问后仍无法判定 → routeDecision = "nonstandard"

4. 输出
   - standard: 弹窗内展示操作路径参考 + 不跳转
   - nonstandard: 展示【我要提非标增值】按钮 + 跳转时传 popupContext
   - uncertain: 提示"建议咨询客服"或让客户自行选择路径
```

## 3. Prompt 骨架

```markdown
## System Prompt — 标准页 AI 下单指引弹窗

你是万邑联增值服务下单助手。客户正在查看一个异常单的处理方式。
你的任务是判断客户的处理需求能否由标准增值服务覆盖。

### 上下文
- 异常单编码：{{eventCode}}
- 异常节点：{{exceptionNode}}
- 异常对象：{{exceptionObject}}
- 当前候选服务清单：{{systemScopedVascList}}

### 候选中的标准增值产品
{{standardCandidates}}
（仅列出 vascType="standard" 的候选，含 vascName 和简要描述）

### 你的判断规则

1. 如果客户的需求可以明确对应某个标准增值产品：
   - 输出 routeDecision = "standard"
   - 告诉客户建议选择哪个处理方式和产品
   - 不要代替客户操作，只提供参考

2. 如果客户的需求无法由任何标准增值覆盖（如特殊加工、非标拍照、自提等）：
   - 输出 routeDecision = "nonstandard"
   - 告诉客户需要走非标增值流程
   - 展示【我要提非标增值】引导

3. 如果信息不足，无法判断：
   - 追问一个最关键的问题（最多追问 1 轮）
   - 追问后仍不确定 → 输出 routeDecision = "nonstandard"（宁可让客户走非标流程，不误导走标准）

### 禁止
- 不推荐 systemScopedVascList 之外的产品
- 不代替客户点击或提交
- 不承诺审核结果或费用
- 不解释仓库内部操作细节
```

## 4. 输出 Schema（弹窗 Agent 结构化输出）

```json
{
  "routeDecision": "standard | nonstandard | need_more_info",
  "confidence": 0.85,
  "standardRecommendation": {
    "vascCode": "VASC202407031503503",
    "vascName": "原单上架",
    "suggestedAction": "建议选择"原单上架"处理方式，仓库会帮您更换包装后上架。",
    "relatedCardLabel": "原单上架"
  },
  "nonstandardReason": "客户需求涉及条码对应关系换标，标准增值不含此能力。",
  "followUpQuestion": null,
  "customerMessage": "根据您的描述，建议选择"原单上架"...",
  "popupContext": {
    "conversationId": "popup_conv_001",
    "customerInput": "商品确认没问题，更换包装后用原入库单继续上架",
    "routeDecision": "standard",
    "systemScopedVascList": [],
    "exceptionContext": {
      "eventCode": "EVENT_001",
      "exceptionNode": "IN_BOUND",
      "exceptionObject": "包裹"
    },
    "dialogHistory": [
      {"role": "agent", "content": "请问这批异常货物您希望怎么处理？"},
      {"role": "user", "content": "商品确认没问题，更换包装后用原入库单继续上架"}
    ]
  }
}
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `routeDecision` | string | 是 | `standard`=标准可覆盖 / `nonstandard`=需走非标 / `need_more_info`=需追问 |
| `confidence` | number | 是 | 0-1，判定置信度 |
| `standardRecommendation` | object | 条件 | routeDecision=standard 时必填 |
| `standardRecommendation.vascCode` | string | 是 | 推荐的标准增值产品编码 |
| `standardRecommendation.vascName` | string | 是 | 推荐的标准增值产品名称 |
| `standardRecommendation.suggestedAction` | string | 是 | 建议客户执行的操作描述 |
| `standardRecommendation.relatedCardLabel` | string | 否 | 对应页面决策树卡片的标签（如"原单上架"） |
| `nonstandardReason` | string | 条件 | routeDecision=nonstandard 时必填，说明为什么标准不覆盖 |
| `followUpQuestion` | string | 条件 | routeDecision=need_more_info 时必填 |
| `customerMessage` | string | 是 | 弹窗中展示给客户的完整文案 |
| `popupContext` | object | 是 | 跳转非标页时传递的上下文（routeDecision=standard 时仍生成但不触发跳转） |

## 5. 与现有决策树卡片的交互规则

| 场景 | 弹窗行为 | 页面卡片行为 |
|------|---------|-------------|
| 弹窗判定 standard，推荐"原单上架" | 弹窗内展示建议，含 `relatedCardLabel` | 卡片不自动高亮/选中；客户需自行点击 |
| 弹窗判定 nonstandard | 弹窗展示【我要提非标增值】按钮 | 卡片无变化；点击按钮后跳转非标页 |
| 客户未使用弹窗，直接点卡片 | 弹窗未触发，无影响 | 正常走原有流程 |
| 客户先用弹窗再点不同的卡片 | 弹窗建议不具强制性 | 以客户实际点击为准 |

**前端实现要点：**
- 弹窗和卡片完全解耦，弹窗不修改卡片状态
- 弹窗的 `relatedCardLabel` 只是文案提示，不是 DOM 操作指令
- 客户关闭弹窗后可正常使用所有卡片

## 6. 评测集设计

### 6.1 分类覆盖

| 分类 | 最小用例 | 验证重点 |
|------|---------|----------|
| 标准增值可覆盖 | 至少 3 条 | 正确识别标准产品 + 给出操作路径参考 + 不跳转 |
| 非标需求（明确） | 至少 3 条 | 正确判定标准不覆盖 + 给出原因 + 触发跳转 |
| 信息不足 / 边界 | 至少 3 条 | 正确追问 or 保守判定 nonstandard |

### 6.2 用例示例

**Case B-STD-001（标准可覆盖）：**
```json
{
  "caseId": "B-STD-001",
  "eventCode": "B0102E23",
  "exceptionContext": {"exceptionNode": "IN_BOUND", "exceptionObject": "包裹"},
  "systemScopedVascList": ["原单上架", "新单上架（客户创建入库单）", "上架前销毁", "入库非标增值（特批）"],
  "customerInput": "商品没问题，帮我换个包装用原来的入库单上架就行",
  "expected": {
    "routeDecision": "standard",
    "standardRecommendation.vascName": "原单上架",
    "nonstandardReason": null
  }
}
```

**Case B-NS-001（非标需求）：**
```json
{
  "caseId": "B-NS-001",
  "eventCode": "B0102E23",
  "exceptionContext": {"exceptionNode": "IN_BOUND", "exceptionObject": "包裹"},
  "systemScopedVascList": ["原单上架", "新单上架（客户创建入库单）", "上架前销毁", "入库非标增值（特批）"],
  "customerInput": "这批货的条码打错了，需要按我给的对应关系重新贴标再上架",
  "expected": {
    "routeDecision": "nonstandard",
    "standardRecommendation": null,
    "nonstandardReason": "包含'按对应关系重新贴标'，属于非标换标需求，标准上架产品不含此能力"
  }
}
```

**Case B-EDGE-001（信息不足）：**
```json
{
  "caseId": "B-EDGE-001",
  "eventCode": "B0102E23",
  "exceptionContext": {"exceptionNode": "IN_BOUND", "exceptionObject": "包裹"},
  "systemScopedVascList": ["原单上架", "新单上架（客户创建入库单）", "上架前销毁", "入库非标增值（特批）"],
  "customerInput": "帮我处理一下",
  "expected": {
    "routeDecision": "need_more_info",
    "followUpQuestion": "请问您希望这批货物怎么处理？比如继续上架、退回、销毁，或者有特殊处理需求？"
  }
}
```

### 6.3 评分维度

| 维度 | 判定 |
|------|------|
| routeDecision 是否正确 | 与 expected 一致 |
| 标准推荐是否在候选内 | vascCode 存在于 systemScopedVascList |
| 非标原因是否合理 | 人工判断描述是否准确 |
| 追问是否有价值 | 追问后能区分 standard/nonstandard |
| 是否违反禁止项 | 不推荐候选外产品、不代替操作、不承诺审核 |

## 7. 弹窗 Coze 包独立性

方案文档 §1.3 明确："后续若做 Coze 智能体，应独立建包或独立智能体，不复用或污染其他方案包。"

因此：
- 弹窗 Agent = 独立 Coze Bot（不是非标页 Agent 的子流程）
- 弹窗 Bot 的知识库：异常类型说明 + 标准增值产品能力描述
- 非标页 Bot 的知识库：SOP 模板 + 非标服务项详情
- 两个 Bot 通过 `popupContext` JSON 传递上下文，不共享会话

## 8. 上线节奏

| Phase | 内容 | 依赖 |
|-------|------|------|
| Phase 1（先上） | 非标页 Agent 含 2d 纠偏，独立运行 | 无依赖弹窗 |
| Phase 2（后上） | 标准页弹窗上线，经弹窗进入非标页的流量跳过 2d | 非标页 Agent 已验证稳定 |

Phase 2 上线前需验证：弹窗 → 跳转 → 非标页正确接收 popupContext → 跳过 2d → 2a/2b 正常工作。
