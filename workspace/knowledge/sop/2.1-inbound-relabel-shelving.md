## 运行边界

- 本文件用于非标路径的**上下文免追问**、**附件完整性校验**，以及字段齐全后的**两类草稿**生成规则，不是运行时产品扩推依据。
- 产品范围仍以 `enrichedContext.systemScopedVascList` 为权威；若系统候选不含非标/特批候选，不得凭本场景编造 VASC。
- 客户确认草稿只用于确认处理方式与表单填写内容，**不等于审核通过**，不替代人工审核。
- 对客输出不得倾倒仓内系统操作细步骤全文；仓库 SOP 写可执行业务动作，不写系统配置/费用/SLA 承诺。
- **禁止**把非 OMS 表单字段编成校验 fieldKey（例如自造「是否补包裹标」「sku_mapping」作为完整性槽位）。业务语义可写进需求描述自然语言，但不能冒充页面校验字段。

## 场景定义

到仓商品条码与系统登记不符，需仓库按客户提供的实物条码与新 SKU/商品条码对应关系，补贴新标签后上架到客户指定入库单。

典型触发：

- 商品条码与包裹条码不对应。
- 同一包裹内混多个 SKU，需要按实物补贴标签。
- 供应商贴错条码，客户要求辨识后更换商品标签。
- 标准增值覆盖不了，或系统候选仅剩非标/特批候选。

典型入口（试点默认）：**入库异常 → 处理异常 → 增值产品信息**（`vaSource=UNUSUAL` / `entryScene=UNUSUAL_INBOUND`）。

## 两层字段模型

### A. 上下文层（页面/接口注入 — 有则免追问）

从 `pageContext` / `enrichedContext` 读取；**不得**再向客户追问已注入值。缺失时提示「上下文获取失败 / 请刷新或从异常处理入口重进」，**不是**对客业务追问槽。

| 字段（接口/上下文） | 页面含义 | 示例 |
|--------------------|----------|------|
| `eventNo` | 异常单号 | EB0326062258 |
| `businessOrderNo` | 关联入库单（WI） | WI46673588 |
| `warehouseCode` / `warehouseName` | 仓库 | USLA / 美国洛杉矶仓 |
| `customerCode` / `customerName` | 客户 | （脱敏） |
| `exceptionType` + 异常图片 URL 等 | 异常事实（开场话术用） | 包裹条码异常 |

说明：新建入库等其它入口若无 `eventNo`，不得伪造；本场景试点以异常入口为主。

### B. 校验层（仅 OMS 真实增值文件 — 白名单）

完整性校验 **只允许** 下列 5 个真实字段名（与线上「增值文件」区一致）。不得增删改名。

| 真实字段名（OMS） | fieldKey（校验用，与页面文案一致） |
|-------------------|-------------------------------------|
| 操作说明附件 | `操作说明附件` |
| 商品和标签的对应关系 | `商品和标签的对应关系` |
| 包裹和标签的对应关系 | `包裹和标签的对应关系` |
| 视频拍摄SOP（中文+英文） | `视频拍摄SOP（中文+英文）` |
| 标签文件 | `标签文件` |

### B.1 尺重换标必填子集（模拟 · 待业务覆盖）

权威勾选仍以业务签批为准。工程干跑暂用下列**模拟规则**（详见 `agent-inventory-assist/03_evaluation/F-001-SIMULATED-BUSINESS-RULES.md`）：

| fieldKey | required（模拟） |
|----------|------------------|
| `操作说明附件` | **是** |
| `商品和标签的对应关系` | **是** |
| `标签文件` | **是** |
| `包裹和标签的对应关系` | 否（默认） |
| `视频拍摄SOP（中文+英文）` | 否（默认） |

完备条件：三必填均已上传 → 可生成两类草稿；缺任一必填 → 只追问缺失必填项（真字段名）。

客户口语中的映射表、数量、是否补包裹标等：可进 `customerIntent` → 写入 **需求描述** 自然语言；**不**进入 `missingFields` 的独立 fieldKey，除非未来产品把对应控件做成页面真字段。

## 对客补齐顺序（仅针对校验层缺失项）

1. 先列 `missingFields`（白名单内、且业务已标必填、且当前未上传的附件），一次性问清。
2. 不追问上下文层已有单据/仓库。
3. 自然语言细节（映射行、件数、是否补包裹标）可在对话中澄清，写入需求描述草稿，但不得伪造成附件 fieldKey。

## 字段齐全后的两类产出（必拆分）

缺任一「业务已确认必填」的白名单附件时：只输出缺失项追问，**不得**生成下列可确认/可回填草稿。

### ① 客户侧表单（OMS 回填）

| 表单字段 | PRD / 输出字段 | 写什么 |
|----------|----------------|--------|
| 需求背景说明 | `requirementBackground` | 为何需要本次非标：异常/条码不符背景、处理目标一句话 |
| 需求描述 | `requirementDescriptionAiPolished` | 用上下文单据 + 客户意图写清对象、映射、数量、已传附件、期望处理结果；供确认后写入增值单 |

### ② 仓库操作 SOP

| 产出 | PRD / 输出字段 | 写什么 |
|------|----------------|--------|
| 仓库操作 SOP | `sopDraft`（可含 `sopStepsZh`/`sopStepsEn`） | 定位异常货物 → 按对应关系辨识/补贴标签 →（如描述要求）补包裹标 → 按入库单上架 → 关闭/推进异常单 |

对客确认时须提示：确认仅代表客户认可表单内容与处理方式，**不等于审核通过**；最终以审核和仓库可执行性为准。

## 2.1 示例（拆分示意 · 异常入口）

已知上下文（免追问）：

- 异常单：`EB0326062258`
- 关联入库单：`WI46673588`
- 仓库：美国洛杉矶仓

已知附件（按模拟必填：三件已上传；包裹对应关系/视频 SOP 未传也不阻断）：

- 操作说明附件、商品和标签的对应关系、标签文件

客户补充意图（自然语言）：

- 实物条码 `M010000000006730489` → 新条码 `M010000000006945932`；不需要补贴新入库单包裹标签。

**需求背景说明（示例）：**

```text
到仓商品条码与系统登记不符，需按客户提供的实物条码与新商品条码对应关系补贴新标签后，上架到关联入库单。
```

**需求描述（示例）：**

```text
异常单 EB0326062258 / 入库单 WI46673588：按已上传的「商品和标签的对应关系」及「标签文件」，将实物条码 M010000000006730489→M010000000006945932 补贴新商品标签后上架；不需要补贴新入库单包裹标签；操作说明见「操作说明附件」。
```

**仓库操作 SOP（示例）：**

```text
1. 根据异常单 EB0326062258 定位待处理货物；
2. 按客户提供的条码对应关系与标签文件补贴新商品标签；
3. 不补贴新入库单包裹标签；
4. 使用入库单 WI46673588 扫描上架；
5. 完成后关闭/推进异常单。
```

**对客确认句（示例）：**

```text
请您确认：以上「需求背景说明 / 需求描述 / 仓库操作 SOP」是否准确，是否按此提交非标增值申请？该确认不等于审核通过；最终仍以增值审核和仓库可执行性为准。
```
