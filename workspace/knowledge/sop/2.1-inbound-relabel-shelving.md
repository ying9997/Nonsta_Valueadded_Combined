## 运行边界

- 本文件只用于非标路径的追问和客户确认用 SOP 摘要，不是运行时产品扩推依据。
- 产品范围仍以 `enrichedContext.systemScopedVascList` 为权威；若系统候选不含非标/特批候选，不得凭本 SOP 编造 VASC。
- 客户确认用 SOP 摘要只用于确认处理方式，不等于审核通过，不替代人工审核。
- 对客输出不得倾倒仓内系统操作细步骤全文。

## 场景定义

到仓商品条码与系统登记不符，需仓库按客户提供的实物条码与新 SKU/商品条码对应关系，补贴新标签后上架到客户指定入库单。

典型触发：

- 商品条码与包裹条码不对应。
- 同一包裹内混多个 SKU，需要按实物补贴标签。
- 供应商贴错条码，客户要求辨识后更换商品标签。
- 标准增值覆盖不了，或系统候选仅剩非标/特批候选。

## 客户需补充字段（填写层）

| 字段 | 是否必填 | 用途 | 示例 |
|------|----------|------|------|
| 异常单号 / eventNo | 必填 | 定位异常货物；固定代发句中通常已带入 | EB0125080621704137 |
| 新入库单号 | 必填 | 指定上架目标入库单 | WI45165946 |
| 实物条码 → 新 SKU/商品条码对应关系 | 必填 | 仓库按对应关系补贴新商品标签 | M010000000006730489 → M010000000006945932 |
| 处理对象范围 | 必填 | 明确处理哪些包裹/商品/数量 | 包裹号、商品条码、SKU、数量 |
| 标签附件 | 必填 | 提供需补贴的新商品标签；如需包裹标签也需提供 | 商品标签 PDF / 图片 |
| 是否需要补贴新入库单包裹标签 | 必填 | 判断是否同时补贴包裹标签 | 是 / 否 |
| 特殊要求或无法辨识处理方式 | 可选 | 约束异常分支 | 无法对应时先暂存并回传照片 |

## 对客追问顺序

1. 先确认新入库单号。
2. 再收集实物条码与新 SKU/商品条码对应关系。
3. 再确认处理对象范围和数量。
4. 再确认标签附件是否齐全，以及是否需要补贴新入库单包裹标签。
5. 最后确认特殊要求：无法辨识、对应关系不一致、标签缺失时是否先暂存等待确认。

## 客户确认用 SOP 摘要结构

输出给客户时使用以下结构：

1. 处理目标：按客户提供的对应关系更换商品标签，并按指定新入库单上架。
2. 客户已提供信息：列出异常单号、新入库单号、对应关系、处理范围、附件。
3. 拟处理方式摘要：定位异常货物；按对应关系补贴新商品标签；如客户要求则补贴新入库单包裹标签；按新入库单上架；处理后关闭/推进异常单。
4. 需客户确认：是否按上述方式提交非标增值申请；确认不等于审核通过，最终以审核和仓库可执行性为准。
5. 缺失项：如仍有字段缺失，只列缺失字段，不输出完整确认稿。

## 2.1 示例摘要

已知信息：

- 异常单：`EB0125080621704137`
- 新入库单：`WI45165946`
- 商品条码对应：
  - `M010000000006730489` → `M010000000006945932`
  - `M010000000006549903` → `M010000000006945947`

客户确认用摘要：

```text
本次需求将按“入库尺重/标签辨识后换标上架”非标场景处理：仓库先根据异常单定位待处理货物，再按您提供的实物条码与新商品条码对应关系补贴新商品标签；如您确认需要补贴新入库单包裹标签，也会按附件标签一并处理。处理完成后，货物将上架到新入库单 WI45165946。

请您确认：是否按以上处理方式提交非标增值申请？该确认仅代表您确认处理方式和已提供信息，不等于审核通过；最终仍以增值审核和仓库可执行性为准。
```
