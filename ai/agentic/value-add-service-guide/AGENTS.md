# AI 使用说明

> 本文件是给 AI Agent 阅读的知识库使用规则，不是给人工用户看的系统操作手册。

## 知识库目标

本知识库用于帮助 AI 理解和回答「入库异常与增值服务之间的关系」。

AI 应使用本知识库回答以下问题：

- 某个入库异常是什么意思？
- 客户遇到该异常后应该怎么处理？
- 该异常可以选择哪些 VASC 增值产品？
- 某个 VASC 增值产品下有哪些增值服务项（增值原子/增值事件）？
- 某个增值服务项需要配置哪些字段？
- 字段有哪些枚举、文件要求、校验规则和填写限制？
- 如果用户不是从异常提问，而是从 VASC 产品、增值服务项、字段或流程提问，应该如何组合答案？

## 首次读取规则

AI 使用本知识库前，应按以下顺序确认上下文：

1. 先读 [README.md](README.md)，确认知识库范围和定位。
2. 新增、修改或校验文件时，必须读 [SCHEMA.md](SCHEMA.md)。
3. 检索内容时，以 [index.md](index.md) 作为导航入口，不要依赖记忆中的旧路径。
4. 遇到规则新旧不一致、疑似废弃或待核实时，查看 [log.md](log.md)。

后续如果 `index.md` 改为脚本生成，AI 应把它视为导航入口，而不是业务事实本身。

## 查询路由规则

本知识库不是固定顺序的流程树。不要强制把所有问题都套入「入库 -> 异常 -> VASC 产品 -> 增值服务项 -> 字段」。

AI 应根据用户问题的起点选择入口：

| 用户问题起点 | 优先查询 | 继续交叉查询 |
|---|---|---|
| 异常编码或异常名称 | 异常实体页 | 关系映射、VASC 产品、增值服务项、字段 |
| 异常怎么处理 | 流程页或异常实体页 | 关系映射、VASC 产品、客户动作 |
| 某个 VASC 增值产品 | VASC 产品实体页 | 产品与服务项映射、适用异常、配置字段 |
| 某个增值服务项、增值原子或增值事件 | 增值服务项实体页 | 服务项与字段映射、所属 VASC 产品 |
| 某个配置字段 | 字段实体页 | 使用该字段的服务项、枚举和校验规则 |
| 某个 VASC 能否处理某异常 | 关系映射表 | 异常详情页、VASC 产品详情页 |
| 怎么选择或填写配置信息 | 增值服务项页和字段页 | VASC 产品页、关系映射表 |
| 术语、编码、状态、枚举 | 术语表或编码字典 | 相关实体页 |
| 接口字段、接口返回、系统查询链路 | 接口来源参考 | 对应实体页、配置字段页、关系映射表 |
| 数据覆盖率、原始快照、规范化数据 | 数据证据包 | 关系映射表、实体页、字段页 |

如果用户表达不清晰，AI 应通过词形判断实体类型：

- 异常编码通常类似 `B01E1315`、`B0102E21`。
- VASC 产品通常是一个场景级服务方案，对应“增值服务产品”，常见产品编码以 `VASC` 开头。
- 增值服务项也叫增值原子、增值事件，是构成 VASC 产品的基本单位，也是仓库动作、计费、成本的主要承载点，例如贴标、换包装、拍照、销毁、采集条码。
- 配置字段通常是客户需要填写的参数、上传的文件、枚举选项、尺寸规格或校验条件。

## 回答组装规则

AI 应按用户问题需要组装答案，不必每次都输出完整链路。

回答异常类问题时，优先包含：

1. 异常含义。
2. 客户需要判断或执行的动作。
3. 可选的 VASC 产品或处理路径。
4. 相关增值服务项和配置字段。
5. 不支持场景、特殊限制、待核实说明。

回答 VASC 产品类问题时，优先包含：

1. 产品解决什么问题。
2. 适用场景和可处理异常。
3. 产品下可选或必选的增值服务项。
4. 需要填写的配置字段。
5. 选择建议和已知限制。

回答增值服务项或字段类问题时，优先包含：

1. 定义。
2. 使用场景。
3. 必填项、可选项、枚举、上传文件和校验规则。
4. 关联的 VASC 产品和异常。

## 来源优先级

当不同文件存在冲突时，按以下优先级判断：

1. 明确的关系映射表。
2. 高置信度实体详情页。
3. 可追溯的规范化数据证据包。
4. 流程说明页。
5. 原始快照、接口文档和保留型参考页。
6. 旧备注、低置信度草稿或待核实内容。

如果冲突无法解决，AI 不得静默合并规则，应在回答中说明冲突，并标记为待核实。

## 来源标记边界

本知识库后续只针对 `value-add-service-guide/` 目录做迁移、索引、校验和检索处理。因此，AI 标记来源时只能标记 `value-add-service-guide/` 内已经沉淀的文件。

- `value-add-service-guide/` 外的 `kb/`、旧项目目录、接口原目录、临时导出目录可以阅读和参考，但不能写入 `source_refs`、索引、关系映射来源或实体页来源。
- 如果目录外资料需要成为可追溯来源，必须先复制、摘要或规范化到 `value-add-service-guide/source-references/` 或其他项目内目录，再引用项目内相对路径。
- 回答、日志和来源说明中不得以目录外路径作为正式依据；最多只能说明“已参考外部原始资料，正式来源已沉淀到项目内快照”。
- 后续迁移后，AI 应能只依赖 `value-add-service-guide/` 内文件继续检索和维护。

## 禁止编造规则

AI 不得凭经验编造以下内容：

- 异常编码。
- VASC 产品名称或编码。
- 增值服务项、增值原子、增值事件的名称或编码。
- 配置字段、枚举值、校验规则。
- 仓库支持范围。
- 产品是否标准、非标、规划中、已生效或已废弃。

如果知识库中没有对应信息，AI 应明确说明「当前知识库尚未沉淀该信息」，并指出缺少的是异常、VASC 产品、增值服务项、字段还是映射关系。

## 关系推理规则

关系是本知识库的一等知识。一个可靠答案可能需要组合多个文件：

- 异常 -> 可选 VASC 产品。
- VASC 产品 -> 可选或必选增值服务项。
- 增值服务项 -> 配置字段。
- 字段 -> 枚举值和校验规则。
- 产品或增值服务项 -> 支持的操作对象层级，例如订单、包裹、商品、单品、SKU、托盘。

关系映射表用于判断「能不能选、该不该选、什么条件下选」。实体详情页用于解释定义、字段和注意事项。

接口文档只能作为字段、编码、状态、查询链路和校验来源。AI 不得只凭接口文档判断某个异常是否支持某个 VASC 产品；此类结论必须回到关系映射表或实体详情页确认。

数据证据包可以作为尚未生成正式业务文档前的取证来源。使用 `source-references/exception-vas-data-package/` 时，应遵守以下规则：

- `data/normalized/` 可用于生成异常到 VASC、VASC 到增值服务项的关系映射。
- `data/raw/` 只作为原始证据，不人工改写。
- `data/reports/` 用于判断覆盖率和缺口。
- 字段级、附件级和模板级结论必须有 `vaAtomAttrs`、`vaAtomFiles` 或等价来源支撑；不能把空字段或未覆盖记录解释为“不需要配置”。
- `legacy-root-files/` 仅用于追溯旧数据包，不覆盖当前根目录规则。

### normalized 数据同步规则

`source-references/exception-vas-data-package/data/normalized/` 是当前第一批关系映射的上游数据。任何 normalized JSON 新增、替换、重命名或内容变更，都必须触发以下同步检查：

1. 重新生成或差异审查 `relationship-mappings/inbound-exception-to-vasc-product-mapping.md`。
2. 重新生成或差异审查 `relationship-mappings/vasc-product-to-service-item-orchestration-mapping.md`。
3. 重新生成或差异审查 `relationship-mappings/service-item-config-field-evidence-coverage.md`。
4. 同步检查 `relationship-mappings/README.md` 中的覆盖统计和来源说明。
5. 同步检查根 [index.md](index.md) 中的映射入口和统计说明。
6. 同步检查受影响的异常、VASC 产品、增值服务项实体页；如果实体页尚未创建，应在日志中说明暂无对应实体页。
7. 在 [log.md](log.md) 记录 normalized 数据版本、映射重建结果、差异摘要和未解决问题。

如果 normalized 更新后字段级证据仍不完整，AI 不得自动生成确定版 `service-item-to-config-field-mapping.md`；只能更新字段证据覆盖状态。

## 写入规则

新增或修改内容时：

1. 遵守 [SCHEMA.md](SCHEMA.md)。
2. 所有目录名和文件名使用英文小写 kebab-case。
3. 页面标题和正文可以使用中文。
4. 所有可迁移引用必须使用相对于 `value-add-service-guide/` 的项目内路径，不得写入本机绝对路径、用户目录、盘符路径或 `value-add-service-guide/` 外部路径。
5. 每个业务目录必须包含 `README.md`，用于说明目录定位、收录口径、子目录和维护规则。
6. 外部系统、脚本、运行环境和目录外资料只记录用途和边界；可沉淀的输出必须复制进本项目后再引用。
7. 用显式链接表达关系，不要大段复制其他文件内容。
8. 不得只完成单文件修改后结束任务；凡变更影响检索、关系判断、路径引用或回答组装，必须执行“AI 维护闭环规则”。
9. 重要变更记录到 [log.md](log.md)。
10. 后续有索引脚本后，新增或改名文件后重建 [index.md](index.md)。

## AI 维护闭环规则

本知识库不依赖人工手动维护索引和关联内容。任何 AI 新增、修改、移动、删除业务文件或来源文件时，必须主动完成关联更新。

### 触发条件

出现以下任一变化，即触发维护闭环：

- 新增、删除、重命名或移动 Markdown、JSON、CSV、图片、来源快照。
- 修改 frontmatter 中的 `title`、`entity_type`、`tags`、编码、状态、来源或路径。
- 修改异常、客户动作、VASC 产品、增值服务项、配置字段之间的关系。
- 修改目录结构、命名规范、标签体系、实体类型或关系类型。
- 修改来源证据、覆盖率结论、字段证据状态或待核实状态。
- 修改或替换 `data/normalized/` 中的规范化数据。

### 必查对象

触发维护闭环后，AI 必须检查并按需更新：

1. 根 [index.md](index.md)。
2. 所属目录 `README.md` 或目录级索引。
3. `relationship-mappings/` 中相关映射表。
4. 相关实体页的正向链接和反向链接。
5. `glossary/` 中相关术语、状态、对象层级、编码或标签说明。
6. `source_refs`、来源说明、证据状态和覆盖率说明。
7. [log.md](log.md)。

如果某一类对象尚未创建，AI 应在本次变更说明或日志中标注“当前暂无对应文件”，而不是假装已经更新。

### 闭环完成标准

AI 完成变更前必须确认：

- 新增或移动后的路径全部使用项目内相对路径。
- 被改名或移动的文件没有残留旧路径引用。
- 实体页、映射表和索引之间不存在明显断链。
- 关系结论有来源；无来源的内容标记为 `pending_verification` 或低置信度。
- `log.md` 记录本次变更、同步更新对象和未完成事项。

若存在自动索引脚本，应优先运行脚本；若暂无脚本，AI 必须手动完成等价的索引和关联更新。

## 不适用范围

AI 不应使用本知识库回答以下问题：

- 与入库异常无关的纯出库增值问题。
- 系统代码、数据库字段、VPN、脚本、故障排查。
- 与入库异常或 VASC 选择无关的客服话术。
- 未核实的口头规则，除非已标记 `confidence: low` 且 `status: pending_verification`。
