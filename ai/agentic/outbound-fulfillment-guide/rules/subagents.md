# 子 Agent 规则

## 适用场景

只有任务天然可拆、子任务相互独立且并行能明显减少时间或上下文噪音时使用。

适合并行：

- 来源只读盘点。
- 不同业务主题探索。
- 独立的语义、结构、安全和发布契约审查。
- 测试结果复核。

谨慎或禁止并行：

- 多个 Agent 同时修改同一文件。
- Canonical 与其生成视图由不同 Agent 独立写入。
- 删除、移动、Git 历史和外部发布。
- 责任边界不清的跨模块重构。

## 写入责任

- 默认由主 Agent 写入和整合。
- 确需并行写入时，为每个 Agent 指定互斥目录或文件。
- 子 Agent 不得提交、推送、删除或发布，除非 Henry 对该具体操作明确授权。

## 验收

主 Agent 必须：

1. 读取子 Agent 结论。
2. 复核实际文件和命令证据。
3. 检查冲突、遗漏和过度声称。
4. 运行统一的最终校验。
5. 只把已验证事项写入 ROADMAP 和交付结论。
