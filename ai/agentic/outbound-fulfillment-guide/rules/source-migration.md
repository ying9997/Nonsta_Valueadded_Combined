# 来源迁移规则

## 原则

- 外部资料始终作为只读输入。
- 不在来源目录修错字、脱敏、重命名或重排结构。
- 正式项目只复制与结论有关的最小证据闭包。
- 外部根路径只作为一次性命令参数，不写入仓库内容。

## 盘点

盘点必须记录：

- collection ID 和显式观察日期。
- 安全逻辑相对路径、大小、媒体类型和 SHA-256。
- 图片、附件、嵌入对象和本地链接依赖。
- 可读性、重复、版本、范围和敏感等级。

路径本身也参加敏感扫描。受限路径只在可提交清单中保存安全占位或不可逆哈希。

## 来源状态维度

分别记录：

- `scope_class`
- `workflow_status`
- `source_lifecycle`
- `temporal_status`
- `readability_status`
- `sensitivity`
- `duplicate_of`

这些维度可以组合，不能压缩成一个单值状态。

## 当前范围门禁

- 当前只选择订单创建至仓库出库交接的来源证据。
- last-mile、`LAST_JOURNEY`、服务中心尾程资料及交接后的轨迹、POD、查件、索赔和派送失败内容统一标记 `scope_class: out_of_scope`。
- 范围外来源只允许进入排除清单和计数报告，不复制快照、不抽取业务事实、不创建 Canonical 或运行时关系。
- 承运商和派送产品来源只有在能独立证明面单、仓库出库或交接要求时，才允许按最小证据闭包选择。

## 快照闭包

每个来源使用稳定 `source_id`。原件、脱敏件和 manifest 分离；原件与附件的相对结构必须保留。

受限原件默认不进入 Git。业务事实只能引用项目内可访问、已批准的安全证据。

## 容器文件安全

处理归档、文档和表格容器前：

- 拒绝路径穿越。
- 限制文件数、单文件大小、总大小和压缩比。
- 不自动解密或递归展开未知嵌套归档。
- 检查宏、外部链接、嵌入对象和可执行内容。
- 对展开文件逐个计算哈希并关联父来源。

无法安全解析时标记为不可读或加密，不猜测内容。

## 禁止事项

- 不把来源文件数当作业务覆盖率。
- 不把启用字段自动解释为所有场景都支持。
- 不先写结论再补来源。
- 不复制凭证、客户数据或未脱敏截图进入 Git。
- 不因来源与出库订单有关就把交接后的尾程内容纳入当前范围。
