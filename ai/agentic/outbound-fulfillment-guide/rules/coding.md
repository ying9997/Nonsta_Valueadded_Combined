# 编码规则

## 运行时基线

- 使用项目声明的 Node.js 和 npm 版本。
- 依赖写入 `package.json` 和 `package-lock.json`。
- 不依赖全局安装或未声明工具。
- 新增依赖前先说明必要性、维护和安全影响。

## 脚本原则

- 默认使用 Node.js 标准库完成 Phase 0 工具。
- 输入、输出和错误均使用明确契约。
- 路径通过项目根解析并验证，禁止逃逸根目录。
- 外部来源路径只能作为一次性参数，不持久化。
- 排序、JSON 序列化、换行和摘要必须确定性。
- 写文件使用原子替换；失败不能留下半成品。
- 校验命令不得修改权威输入。

## 错误和退出码

- `0`：全部通过。
- `1`：业务或校验失败。
- `2`：参数或配置错误。
- 其他非零：内部异常。

错误对象包含稳定 code、可读 message 和可选 path，不把凭证或敏感内容写入日志。

## 测试

- 先测试路径边界、规则引用和报告契约。
- 对未实现能力返回非零，不用空函数制造假成功。
- 对生成脚本提供只读 `--check` 模式。
- 变更脚本后运行相关命令，并检查生成报告内容而不只看退出码。
