# 交付规则

## 结论先行

交付先说明实际结果，再说明关键验证和边界，不用过程堆砌掩盖未完成项。

## 必须说明

- 实际创建、修改或验证了什么。
- 哪些文件是权威输入，哪些是生成物。
- 运行了哪些命令，结果是否通过。
- 发现并保留了哪些冲突、缺口或风险。
- 哪些状态仍是待确认。

## 状态分层

必须分别说明：

1. 本地文件已修改。
2. 本地验证已通过。
3. Git 已初始化或已有提交。
4. Git 已推送远程。
5. 发布包已生成和验证。
6. 下游项目已导入。
7. Coze 或其他平台已发布。
8. 线上真实问题已验证。

任一层成功不能证明后续层完成。

## 证据边界

- 命令返回成功不自动等于业务结果正确。
- 导出成功不等于外部系统已导入或发布。
- 测试样例通过不等于全量来源覆盖。
- 无法验证时说明限制、已做检查和剩余风险。
