# DECISIONS

## D-001：各业务知识库独立

- 状态：accepted
- 日期：2026-08-04

本项目使用独立目录、独立 Git 和独立知识版本。父级知识库目录不建立统一 Git 仓库。

## D-002：Canonical 是唯一事实源

- 状态：accepted
- 日期：2026-08-04

实体、事实、关系和受控词表只在 `data/canonical/` 审查。业务 Markdown、映射、glossary 和 index 由其生成，禁止双事实源。

## D-003：知识项目与 Expert 消费分离

- 状态：accepted
- 日期：2026-08-04

本项目不保存 Expert 路由、Prompt、API 编排或 Coze 实现。下游以固定版本复制 runtime artifact，并单独验证导入、导出、发布和线上效果。

## D-004：Phase 0 工具基线

- 状态：accepted
- 日期：2026-08-04

使用 Node.js `24.16.0` 和 npm `11.13.0`。Phase 0 只真实现骨架校验；未实现能力必须返回 `not_implemented` 和非零退出码。

## D-005：独立 RMA 排除

- 状态：accepted
- 日期：2026-08-04

客户主动发起的独立退货或 RMA 不属于本项目。派送失败后的退回或其他处置同样属于交接后尾程，按 D-006 在本次范围中延期。

## D-006：本次范围止于仓库出库交接

- 状态：accepted
- 日期：2026-08-04

本次知识库覆盖出库资格、订单创建、校验、库存分配、波次、拣货、复核、增值、包装、打托、称重量方、面单、仓库出库和交接。承运商和派送产品只保留面单、出库与交接所需知识。

承运商或客户完成交接后的轨迹、首扫、在途、派送、妥投、POD、查件、索赔和派送失败处置全部延期，不进入当前来源迁移、Canonical、生成视图、测试范围或运行时发布包。现有尾程目录仅作为延期占位，不代表当前范围或已规划内容。
