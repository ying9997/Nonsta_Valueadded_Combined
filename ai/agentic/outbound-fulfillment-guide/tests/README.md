# 知识库测试

## 目录定位

本目录保存检索、答案组装、边界、披露和测试 fixture，用于证明知识结构和生成结果满足声明的契约。测试通过不等于来源全量覆盖或业务规则已经可发布。

Phase 0 只允许空业务库和工程骨架测试，不使用占位业务事实制造通过结果。

## 子目录

- [retrieval](retrieval/)：查询入口、实体命中和消歧测试。
- [answer-assembly](answer-assembly/)：答案结构、条件、例外和证据状态测试。
- [boundaries](boundaries/)：范围、实时数据、敏感披露和反幻觉测试。
- [fixtures](fixtures/)：最小、脱敏、可复现的测试输入。

## 收录口径

- 正向用例、反向用例、边界条件和冲突用例。
- 订单、库存作业、波次、拣货、包装和交接状态域分离等关键防误用用例。
- 交接后的轨迹、POD、查件、索赔和派送失败问题必须命中范围边界，不能误召回仓内规则。
- agent internal 与 customer safe 内容的禁止披露用例。
- 生成漂移、断链、无来源关系、未知范围和过期规则用例。

## 维护规则

- fixture 不是来源证据，不得进入 Canonical 或运行时切片。
- 测试不得依赖本机绝对路径、网络状态或未声明的外部资料。
- Schema、Canonical、生成器或发布契约变化时同步更新相应测试。
- 测试结果必须说明校验 profile 和业务内容状态，不能把 Phase 0 成功描述为业务验收。
