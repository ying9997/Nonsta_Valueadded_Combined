# 来源证据

## 目录定位

本目录保存进入项目证据闭包的来源快照、派生抽取和来源治理报告。来源用于支持事实和关系，但来源陈述不自动等于当前有效业务规则。

Phase 0 不迁移外部资料，不包含正式来源快照或业务证据。

后续来源选择只覆盖订单创建至仓库出库交接。尾程资料只允许在报告中标记 `out_of_scope`，不得进入 snapshots、extracts 或正式 `source_refs`。

## 子目录

- [snapshots](snapshots/)：按 source ID 保存不可修改的项目内证据快照。
- [extracts](extracts/)：OCR、表格、字段等派生抽取，必须反向指向快照。
- [reports](reports/)：盘点、覆盖、冲突、缺口、敏感信息和图片依赖报告。

source-registry.json 是来源台账入口。Phase 0 只允许符合 Schema 的空台账。

## 收录口径

- 外部资料必须先盘点、计算哈希、分类和敏感扫描，再决定是否进入证据闭包。
- 原件、脱敏派生件和抽取结果必须分开，并通过 source ID、哈希和 locator 关联。
- 路径名本身参与敏感扫描；受限路径、凭证、真实客户和订单信息不得进入 Git。
- 接口资料可支持字段和查询链路，但不能单独证明业务支持关系。
- 承运商和派送产品资料只采用能证明面单、仓库出库或交接要求的最小证据闭包；交接后的轨迹、POD、查件、索赔和派送失败资料不收录。

## 生成与维护

- 快照一经登记不得原地修改；变化必须创建新来源记录或明确版本关系。
- extracts 和 reports 必须可追溯到输入快照及生成工具版本。
- 正式事实引用只能指向项目内来源，不得保存本机绝对路径或目录外依赖。
- 来源变化后同步检查 Canonical、冲突、覆盖率、生成视图和测试。
- 运行时发布包默认不包含原始证据，只携带经批准的来源映射。
