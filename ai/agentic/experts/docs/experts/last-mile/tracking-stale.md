## 一、业务处理流程

```mermaid
flowchart TD
    A[开始：用户咨询轨迹长时间未更新] --> A1[通过 delivery-status 获取轨迹数据]
    A1 --> B{是否识别到异常结果?}
    B -- Y --> C[基于识别到异常结果及处理方式回复] --> Z[结束]
    B -- N --> D{确认是否有ascan且3天内无轨迹更新?}
    D -- Y --> E[回复：有ascan且3天内无轨迹更新的话术] --> Z[结束]
    D -- N --> F{是否超10天以上未更新?}
    F -- N --> G[不符合索赔标准 → 使用不符合索赔标准的回复话术] --> Z[结束]
    F -- Y --> H{是否有索赔服务?}
    
    H -- N --> I[无索赔服务 → 使用无索赔服务回复话术] --> Z[结束]
    H -- Y --> J{是否国内件?}
    
    J -- Y --> K[国内件有索赔服务 → 使用国内件回复话术] --> L{客户是否确认提交索赔?}
    J -- N --> M[国际件有索赔服务 → 使用国际件回复话术] --> L{客户是否确认提交索赔?}
    
    L -- Y --> N[引导客户按索赔流程提交索赔] --> Z[结束]
    L -- N --> O[超过10天以上未更新 → 使用"超10天未更新"回复话术] --> Z[结束]
```

## 二、判定节点说明

| 判定节点 | 判定条件 | 分支逻辑 |
|---------|---------|---------|
| **是否识别到异常结果** | 根据系统已有异常识别结果 | 有 → 直接回复识别出的处理方式；无 → 继续判断 |
| **是否有 ascan 且 3天内无更新** | 存在首条扫描记录，但之后超过3天无新轨迹 | 是 → 使用特定话术回复；否 → 继续判断 |
| **是否超 10 天以上未更新** | 从最后一条轨迹开始计算超过10天 | 否 → 不符合索赔标准，回复话术结束；是 → 继续判断 |
| **是否有索赔服务** | 当前渠道是否提供丢失索赔服务 | 仅明确 `false` 才回复“无索赔服务”；明确 `true` 继续判断目的地；未知必须转人工核实 |
| **是否国内件** | 目的地是否为派送国内 | 国内件 → 国内话术；国际件 → 国际话术 |
| **客户是否确认提交索赔** | 用户是否确认要走索赔流程 | 是 → 引导提交；否 → 回复超10天话术 |

## 三、客服SOP话术整理

### 3.1 不同天数不同情况的标准回复

#### 场景 A：确认有 ascan 且仅 1 天无轨迹更新
> **话术**：
> ```
> 您好,该订单仅一天未更新轨迹,目前还是正常的;包裹运输中在不同的城市站点运转,未到达派送站点前可能还未扫描包裹更新的,您可继续等待.
> ```

#### 场景 B：确认有 ascan 但超 3 天以上未更新轨迹（国内件+有索赔服务）
> **话术**：
> ```
> 您好,根据以往经验该订单有可能出现派送中丢失的情况,为避免货物丢失最后超过索赔时效，建议您先提交索赔，索赔期间供应商也会去定位货物情况，若确认丢失则会直接进入索赔。
> ```

#### 场景 C：确认有 ascan 但超 3 天以上未更新轨迹（国内件+无索赔服务）
> **话术**：
> ```
> 您好,根据以往经验该订单有可能出现派送中丢失的情况，建议您先提交查件我们与供应商核实确认，若丢失您那边可跟买家协商是补发还是退款。
> ```

#### 场景 D：确认有 ascan 但超 3 天以上未更新轨迹（国际件+有索赔服务）
> **话术**：
> ```
> 您好,您这单是国际件,有可能是因为不同国家运输出现轨迹暂停的情况,比如在清关或者是转运中,建议您继续等待.
> ```

#### 场景 E：超过 10 天以上未更新（通用推荐话术）
> **话术**：
> ```
> 您好,超过10天未更新轨迹丢失的概率比较高,为避免货物丢失最后超过索赔时效，建议您先提交索赔，索赔期间供应商也会去定位货物情况，若确认丢失则会直接进入索赔。
> ```

### 3.2 按索赔服务分类话术

| 情况 | 话术 |
|-----|------|
| **有索赔服务且在时效内** | 您好，此单已经10天以上没轨迹产生了，大概率是丢失，为避免货物丢失最后超过索赔时效，建议您先提交索赔，索赔期间供应商也会去定位货物情况，若确认丢失则会直接进入索赔。 |
| **有索赔服务但已超过索赔时效** | 您好，此单已经10天以上没轨迹产生了，大概率是丢失，但此单已超过索赔时效了，建议您先提交查件我们与供应商核实下，同时您与买家协商，若丢失的话是补发还是退款。 |
| **有索赔服务但未到索赔提交时效** | 您好，此单已超过10天以上没轨迹产生了，大概率是丢失，但目前还未到可索赔，可提交索赔时间为`x月x号`，建议您先提交查件我们找供应商核实下，有可能是漏处理了，同时您与买家协商，若丢失的话是补发还是退款。 |
| **无索赔服务（仅明确事实）** | 仅当 `hasClaimService === false` 或已确认平台面单时使用：您好，此单超过10天以上没轨迹产生了，大概率是丢失了，但当前事实已明确该渠道无索赔服务，建议先提交查件核实并与买家协商后续方案。 |
| **索赔能力未知** | 不得套用“无索赔服务”话术；标记缺少 `hasClaimService` 并转人工核实。 |

### 3.3 常见问题 FAQ

#### Q: 派送时供应商为什么不能提前电话联系买家？
> A: 国外大多数的尾程派送商都支持安全点/邮箱妥投，不需要收件当面签收。尾程供应商为了提高派送效率，一般不支持派送前电话联系、指定时间派送、指定收件人，如果收件人不在家又无安全点妥投，包裹一般会转自提点或重新派送。如有您有特殊需求，可让买家致电供应商确认是否可操作。

#### Q: 尾程派送延迟可以申请索赔吗？
> - **如是 WF 尾程物流，有购买时效保服务**：您好，此单查询您有购买时效保服务，对应如有时效延迟，会有保险赔付 5USD/单
> - **如是 WF 尾程物流，没有购买时效保服务**：您好，此单查询您没有购买时效保服务，暂无运输延迟赔付，如您有需要，后续您可以购买时效保服务，对应如有时效延迟，会有保险赔付 5USD/单。
> - **如不是 WF 尾程物流**：供应商对外公布的时效，是根据供应商历史 95% 订单可达标的时效标准而定。此时效仅作为您下单选择的参考值，不排除有一定比例的订单会有派送超时的现象。少数延迟现象属于供应商的服务缺陷，无法避免，我们无法进行赔付。同时我们会有数据监控，如果某一个服务长期不达目标，我们也会考虑替换供应商。

#### Q: 为什么包裹会超时效派送完成？
> A: 由于包裹在实际派送中可能出现不可预料，非供应商可解决的不可抗力因素，可能导致少数包裹出现超时效派送的情况。常见原因：
> - 收件人地址有误/模糊，需要确认正确地址并安排重派
> - 收件地址为商业地址，派送时间不在开放时间内，需延后
> - 必经区域/转运方式出现封路/暂停运营，导致顺延
> - 按收件人特殊要求，指定日期派送
> - 包裹破损/丢失，暂存等待确认处理方式

#### Q: 什么是 MSCAN（首条轨迹）？
> **首条轨迹承诺 (Mscan)**：首条轨迹指在供应商轨迹网站出现的第一条非打单信息，表示**实物 WINIT 已交货**或**供应商收货扫描**的轨迹，通常在 WINIT 订单状态更新为"派送中"后产生。
> 
> WINIT 承诺下单时间为当地时间 DAY0 X 时间前订单，Y 时间前产生首条轨迹。支持部分平台及自建站及时抓取最新交货轨迹。
> 
> **支持 MSCAN 的供应商：**
> - 美国：UPS、USPS（美南仓的 UPS 不支持）
> - 英国：HERMES、YODEL
> - 澳洲：MCS、AUPOST、Fastway
> 
> **注意：** wish 平台不传 Mscan，支持供应商以最新通知为准。

#### Q: 为什么第三方平台（如17track）轨迹和万邑通系统不一致？
> A: 是因为我们系统抓取供应商的轨迹有时间差，故会和第三方查询系统不一样。
> 
> **内部知识**：可到 TOM 系统的供应商 → 开发工具箱 → 轨迹任务中查询，系统每隔约 6 小时抓取一次（不同供应商可能不同）。

#### Q: 美国国际渠道派送到加拿大为什么没有轨迹回传？
> A: 根据邮政联盟的规定，包裹在当地加拿大不扫描不回传轨迹信息，因此，官网无法查询到包裹到达当地后的轨迹运输情况，建议收件人可直接与加拿大邮政联系。
> - 加拿大境内联系电话：1-866-607-6301, 1-877-632-6347
> - 加拿大境外联系电话：416-979-3033

#### Q: 收件人电话号码错误是否会影响派送？
> A: 快递类的包裹由于国外的派送商大多支持安全点妥投，极少电话联系收件人，电话号码错误或丢失一般不影响派送。
> 
> **例外**：托盘服务的包裹如果收件人电话号码错误或缺失，将会无法派送。因为大货在派送前，供应商需要和收件人预约派送时间。常见需要电话预约的：TOLL, XDP, DGF 等。

#### Q: 为什么会出现断更？
> A: 结合万邑通以往经验，一般有以下几种情况：
> 1. 某些目的地国家邮政不提供当地包裹物流轨迹
> 2. 面单在运输过程中发生了磨损，条形码无法扫描正常转运
> 3. 收件人地址信息不全/有误，无法转运
> 4. 包裹无法完成目的国清关
> 5. 包裹丢失

#### Q: 买家收到货物发现产品损坏，是否有赔付？
> | 情况 | 回复话术 |
> |-----|---------|
> | 渠道有赔付标准 + 包装无防损保护 | 您好，依据订单核实，渠道是有赔付标准的，您能够依照该赔付标准提交代客索赔申请。不过，从买家提供的相片来看，您这个产品的包装缺乏防护，在运输过程中很容易出现产品破损/被压坏的情况，像这种情形下提交尾程代客索赔的话，被拒赔的概率比较大，建议您日后对容易损坏的产品添加防护包装。 |
> | 渠道有赔付标准 + 包装有防损保护 | 您好，依据订单核实，渠道是有赔付标准的，您能够依照该赔付标准提交代客索赔申请。 |
> | 渠道无赔付标准 + 包装无防损保护 | 您好，依据订单核实，订单所选渠道没有赔付标准的，无法提供索赔，很抱歉；另外，从买家提供的相片来看，您这个产品的包装缺乏防护，在运输过程中很容易出现产品破损/被压坏的情况，像这种情形下就算提交尾程代客索赔的话，被拒赔的概率比较大，建议您日后对容易损坏的产品添加防护包装。 |
> | 渠道无赔付标准 + 包装有防损保护 | 您好，依据订单核实，订单所选渠道没有赔付标准的，无法提供索赔，很抱歉；若产品是易损的，建议您在外包装上贴上易损标签，防止运输中出现破损/压坏的情况；或可更换其他有索赔的渠道。 |

#### Q: Hermes/EVRi 收件人反馈需要取件码，如何获取？
> A: 订单销售平台为 eBay，收件人下单选择了**自提的交付方式**的场景下，eBay 将生成 eCP 号码。这个号码一般在下单时会体现在地址信息中，可在出库单详细地址查看（如果客户下单没有填写，则咨询 eBay）。

#### Q: 国外快递尾程派送是否会打电话给买家？
> A: 您好，国际快递尾程派送一般不会电话联系。受隐私政策及派送效率影响，国外快递员通常会按地址直接投递：无需签收的包裹会放置在门口或信箱，需签收的则会留下派送通知单。建议您及时关注物流官网的实时轨迹，以免错过包裹。

## 四、AI 处理要点

### 关键参数提取
AI 需要从用户问句和订单数据中提取：
1. **最后一条轨迹时间** → 计算天数差，判断是否超 3天/10天
2. **是否存在 MSCAN** → 首条扫描记录是否存在
3. **目的地是否国内** → 判断是国内件还是国际件
4. **渠道是否有索赔服务** → 优先使用上游显式布尔事实；平台面单固定为不支持；美国 Winit Fulfillment 7日达（含分区/定制变体）按维护中的赔付表识别为支持丢失类代客索赔；其余未知值转人工
5. **是否在索赔时效内** → 判断是否可以索赔

### 语料特点
- 大部分回复都是标准化话术，分支判断清晰，适合规则引擎 + 模板化回复
- 不需要复杂推理，按流程图走分支即可
- 需要结合**订单数据**（轨迹、渠道信息、目的地）而非仅依靠用户文字
- 当父级产品与实际订单产品不一致时，以 `orderWinitProduct*` 派生的实际产品事实为准。

### 异常处理
- 如果已经系统识别到异常结果，直接复用结果回复即可，无需重新判断
- 最终都要导向结束，没有复杂的多轮交互（是否提交索赔由客户决定后再进入下一流程）
