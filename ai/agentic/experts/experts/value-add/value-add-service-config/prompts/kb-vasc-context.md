# VASC 上下文层

本文件为 `value-add-service-config` 提供 VASC 与服务意图的上下文解释。它不推荐 VASC，只解释已知 VASC 的配置入口。

---

## 使用规则

- `vascCode` 是配置解释主键；命中下表后才能读取服务项编排。
- 未命中 `vascCode` 时输出 `missing_vasc` 或 `conditional`，不得按方向概念猜测服务项。
- `activeStatus=inactive` 的 VASC 只作历史或映射线索，不承诺页面可下单。
- `OSF` / 库内 / 出库相关 VASC 可作为关联事实解释，但入库异常链路中不得跨阶段套用。

## 方向概念速查

| VASC 方向 | 典型意图 | 对象层级 | 配置解释重点 |
|---|---|---|---|
| 原单上架 | 原单上架 | `package` / `product` | 原入库单关联、条码修复、异常货物继续上架 |
| 新单上架 | 新单上架 | `package` / `product` | 新入库单号、重新关联、条码修复 |
| 直接上架 | 原单/新单直接上架 | `package` / `product` | 只能在映射和规则支持时解释，不能因客户口述直接判断 |
| 销毁处理 | 销毁 | `package` / `product` / `item` | 销毁对象、数量、客户授权 |
| 拍照 / 视频 / 调查 | 拍照、视频、调查 | `package` / `product` / `item` | 多为调查或确认动作，后续仍可能需要继续处理 |
| 自提 / 调拨 / 非标 | 自提 / 调拨 / 非标 | `order` / `package` / `pallet` | 仓库限制、审批、人工确认 |

## handoff 使用规则

- `handoffToServiceConfig.vascCode` 是主键，优先级高于直接入参。
- `customerActionNormalized` 可作为 `serviceIntent` 默认值。
- `limitations` 写入 `configBoundaryNotes`，不自动等同于系统禁选。
- `objectLevel` 决定服务项解释口径：包裹级不承诺商品级配置，商品级不承诺整单配置。
- 当 handoff 只提供 `vascName` 未提供 `vascCode` 时，只能做方向级解释；不得输出确定服务项编排。
