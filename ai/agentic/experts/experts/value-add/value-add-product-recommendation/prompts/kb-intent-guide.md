# 客户意图导航 · VASC 候选推荐指引

本文件按**客户处理意图**组织 VASC 候选，每个意图独立成段，说明该意图的业务语义、适用条件、候选 VASC 方向和关键约束。

> 使用规则：以 `customerActionNormalized` 定位对应意图段；首选 VASC 需结合 `kb-mapping-table.md` 验证异常编码关系，并通过 `kb-vasc-constraints.md` 过滤启用态。

---

## 意图一：原单上架（USE_ORIGIN_INBOUND_ORDER）

### 业务语义

货物因异常无法正常上架，但**原入库单仍可继续操作**，客户希望修复异常后继续使用原单完成上架。

### 适用前提

- 原入库单状态为**可操作**（如「待上架」、验货未完成等，非已关闭/已完成）。
- 异常对象为包裹级或商品级，通过增值处理后可与原入库单关联上架。

### 关键确认项（blocking）

- **原入库单是否仍可操作**：必须确认；若入库单已关闭或已完成，原单上架不可行，应引导改为新单上架。

### 候选 VASC 方向

| 异常类型 | 典型 VASC 方向 | 核心操作 |
|---|---|---|
| 包裹条码异常 | 原单上架（包裹条码修复类） | 补贴/重打/换贴包裹条码，关联原入库单 |
| 商品/SKU 条码异常 | 原单上架（商品条码修复类） | 补贴原 SKU 条码或更换新 SKU 条码 |
| 混合条码异常（包裹+商品） | 原单上架（组合修复类） | 同时处理包裹和商品条码 |

### 流程复原路径

异常暂存区货物 → 增值贴标/换标 → 重新扫描关联原入库单 → S3 上架完成

## 意图二：新单上架（USE_NEW_INBOUND_ORDER）

### 业务语义

原入库单**无法继续操作**（已关闭、已完成或客户主动选择放弃），客户需要创建新的入库单并重新走上架流程。

### 适用前提

- 原入库单已不可操作，或客户明确表示不用原单。
- 客户能够（或已经）创建新入库单。

### 关键确认项（blocking）

- **新入库单号**：客户是否已创建；创建后才能触发增值关联。

### 候选 VASC 方向

| 异常类型 | 典型 VASC 方向 | 核心操作 |
|---|---|---|
| 包裹条码异常 | 新单上架（包裹条码类） | 补贴包裹条码，关联新入库单 |
| 商品条码异常 | 新单上架（商品条码类） | 补/换商品条码，关联新单 |
| 无条码/全异常 | 新单上架（综合类） | 重新制作完整条码体系后关联新单 |

### 流程复原路径

新建入库单 → 增值补码/贴标 → 关联新入库单 → S1→S3 重新走上架流程

### 与原单上架的互斥关系

同一异常同一时间只能选其一；选择新单上架后，原入库单关联关系断开，后续不再补充进原单。

## 意图三：销毁（DESTROY）

### 业务语义

货物异常严重（包装破损、质量问题、无经济回收价值），客户放弃货物，要求仓库按规定销毁并出具销毁证明。

### 适用前提

- 客户已明确确认放弃货物并授权销毁。
- 销毁对象须明确：包裹/商品/部分数量。

### 关键确认项（blocking）

- **销毁授权确认**：客户须在增值单中明确填写销毁对象和数量。
- **仓库限制**：部分目的仓对危险品/液体等有特殊销毁规定；需确认是否有特殊货型限制。

### 候选 VASC 方向

| 异常类型 | 典型 VASC 方向 |
|---|---|
| 包装严重破损/受潮 | 销毁处理 VASC |
| 商品质量明显异常（碎裂） | 销毁处理 VASC |
| 客户主动放弃 | 销毁处理 VASC |

### 流程复原路径

暂存货物 → 客户提交销毁增值单并授权 → 仓库执行销毁 → 出具销毁凭证 → 流程终止

## 意图四：自提（SELF_PICKUP）

### 业务语义

客户希望自行取走货物，不通过正常上架流程，由客户或指定提货人到仓提货。

### 适用前提

- 仓库支持客户自提（需确认目的仓是否开放自提）。
- 货物处于可提取状态（已到仓，异常已登记）。

### 关键确认项（blocking）

- **仓库是否支持自提**：部分海外仓不开放自提。
- **提货人信息**：姓名、证件、取货时间窗口。

### 候选 VASC 方向

| 场景 | 典型 VASC 方向 |
|---|---|
| 货物异常，客户不走上架改自提 | 自提处理类 VASC（非标服务） |
| 串仓后客户选择在当前仓自提 | 自提处理类 VASC |

### 流程复原路径

货物暂存 → 客户提交自提增值申请 → 仓库准备提货 → 客户/提货人到仓取货 → 流程终止

## 意图五：拍照 / 测量 / 质检（PHOTO / MEASURE / QC）

### 业务语义

客户不确定货物实际状态，或需要存证记录，申请拍照、测量尺寸重量或质量检查，辅助后续决策（是否上架、是否销毁、是否退回供应商等）。

### 适用前提

- 货物已到仓。
- 客户需要视觉存证或数据核实。

### 关键确认项（informational）

- **拍照维度**：包裹外观 / 商品内件 / 条码特写 / 全景。
- **测量项目**：尺寸 / 重量 / 体积重量。
- **质检标准**：是否有客户自定义质检表。

### 候选 VASC 方向

| 服务类型 | 典型 VASC 方向 | 说明 |
|---|---|---|
| 拍照 | 库前拍照 VASC | 货物到仓后，上架前对外包装/内件拍照存证 |
| 测量 | 库前测量 VASC | 核实实物尺重，解决尺重异常问题 |
| 质检 | 质检服务 VASC | 按标准或客户定制质检表逐件检验 |
| 综合（先拍照再决策） | 先拍照，再根据拍照结果决定是否上架/销毁 | 拍照不影响货物状态，可与其他 VASC 组合 |

### 流程复原路径

货物暂存/在库 → 增值拍照/测量/质检 → 客户查看结果决策 → 后续再触发上架/销毁/自提等意图

## 意图六：补/换条码 · 贴标 / 换标（LABEL / RELABEL）

### 业务语义

客户已明确知道需要补贴或更换条码，但**尚未确定是要原单上架还是新单上架**，处于「先修复条码，再决定上架方式」的阶段。

> 若客户已明确上架方式，应优先路由到意图一（原单上架）或意图二（新单上架），本意图作为过渡。

### 候选 VASC 方向

| 操作类型 | VASC 方向 |
|---|---|
| 补贴包裹条码 | 包裹贴标 VASC |
| 更换包裹条码 | 包裹换标 VASC |
| 补贴商品/SKU 条码（原 SKU） | 商品条码补贴 VASC |
| 更换商品条码（新 SKU） | 商品条码更换 VASC |
| 补贴第三方条码（FNSKU 等）关联 | 第三方条码关联 VASC |

### 与上架意图的联动

补换条码完成后，货物通常进入原单上架或新单上架流程。建议在提供本意图候选时，同步询问客户上架方式，以便在 `handoffToServiceConfig` 中提前注入上架意图。
