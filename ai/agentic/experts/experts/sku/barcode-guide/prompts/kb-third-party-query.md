# KB：查询第三方/单品条码及状态

来源压缩：OSWH `10` 查询第三方单品条码、`11` 查询商品的单品条码及其状态。

## 概念边界

- **第三方商品条码**：平台或供应商提供的外部码，需要与 Winit 中的商品编码正确绑定后，才能用于仓内识别商品。
- **第三方单品条码**：用于 SI 单品化场景下的单品识别与追踪，属于单品层级；相关查询和维护可能需要开通第三方单品条码管理权限。
- 两者层级不同，不得表述为同义概念，也不得推断两者字符串相同。
- **FNSKU** 属于第三方平台侧条码。用户询问 FNSKU 时应先澄清：要查看平台侧的 FNSKU，还是核对它在 Winit 中与商品编码的绑定关系；本专家只提供 Winit 侧绑定查询路径。
- **M 码是 Winit 系统内部唯一商品编码**；**S 码用于 SI 单品化下的单品追踪**。不得把 M 码和 S 码都解释为单品条码。

## 能查什么

### 1）第三方单品条码列表

- 查询条件：商品编码 + 单品条码 + 分页
- 返回：商品编码、规格、条码、中英文名、更新时间等
- 权限：需开通第三方单品条码管理；未开通引导联系客服

### 2）商品单品条码及状态

- 查询条件：商品编码（必填）；可选规格、条码、状态、分页
- 用于核对：某 SKU 下有哪些 S 码、当前状态是否可用

### 单品状态（常见，对客简述）

| 状态 | 含义（简述） |
|------|----------------|
| 准备中 | 尚未进入可用 |
| 在途 | 在途中 |
| 待发 / 可用 | 可作业相关 |
| 已出库 / 已拣选 / 已打包 | 出库流程中或已完成 |
| 丢失 / 销毁相关 | 异常终态 |

对客不背诵全部枚举；按查询结果解释「能不能用、是否已出库」。

系统查询状态为「待发 / 可用」只说明系统记录满足相应状态，**不等于仓库扫描已经生效**。需要确认实际识别效果时，应在查询绑定后请仓库复扫；不得省略仓库复扫就承诺绑定已生效。

## 对客自助路径

**万邑联 → 商品管理 → 单品/第三方条码查询**（或商品详情下的条码页签）。

## 本专家边界

- 首期**不接**只读 OpenAPI 插件；只教客户自助查与解读结果。
- 查不到码 + 仓内扫不上 → 结合 `kb-scan-fail`：可能未绑码或管理模式不匹配。
- 不能保证仅凭 S 码反查商品编码；需收集完整 S 码、出现页面和业务环节，自助路径无法确认时 `need_human`。
- 不能确认单个商品编码可绑定任意数量的第三方码；需核对码类型、实际维护页面与权限状态，必要时 `need_human`。
- 当前知识未定义 RM 前缀；需收集完整码值、出现页面和业务环节后 `need_human`，不得猜测。
