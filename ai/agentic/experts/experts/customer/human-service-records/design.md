# human-service-records Expert 设计

## 调用说明

### 定位与边界

本专家回答的是：**历史人工客服曾经怎么说、建议怎么做、或记录中能否确认某个处理结果**。

它不是完整聊天记录查看器，也不根据历史沟通判断当前业务的真实状态。

适用问法：

- “之前客服让我怎么处理入库异常？”
- “客服有没有提到这个订单？”
- “客服当时说会怎么处理？”
- “上次和客服主要沟通了什么？”
- “把客服上次发的图片给我。”
- “之前的附件链接是什么？”

不处理：跨账号查询、完整记录导出、实时转人工、新建工单，以及没有历史明确依据的当前状态判断。

## 输入设计

框架顶层必须传入 `username`，并以它匹配客户邮箱作为唯一权限硬过滤。`customerCode` 与 `customerName` 只可作诊断上下文。

`inputs` 只保留业务参数：

| 字段 | 说明 |
|---|---|
| `timeRangeText` / `timeStart` / `timeEnd` | 用户指定的历史时间范围 |
| `keywords` | 订单号、异常名或需要确认的关键词 |

不暴露消息数、会话数等摘要技术限额。无明确时间时查询截至昨天的最近 30 天；用户只说“查历史记录”时，摘要默认回顾最新一段实质会话。半年前以前和当天记录仍沿用既有边界。

## 数据拉取与证据流程

```text
身份校验 → 时间范围解析 → 全量分页拉取 → 消息级筛选
→ build-summary-evidence → 一次 LLM 摘要 → format-output 引用与附件链接校验
```

1. 数据源按 `客户邮箱 = username` 硬过滤并持续翻页；消息时间而非会话开始时间决定是否命中。
2. `build-summary-evidence` 不输出完整 transcript。它为每条证据生成稳定 ID，并保留会话 ID、时间、角色、说话方、文本与单条截短标记。图片、文件、视频和音频会被识别为附件事件；其 URL 只传给最终代码渲染节点，不传给 LLM。
3. 问题导向查询保留关键词命中消息、相邻问答和目标会话中最后一条客服实质答复；泛问只保留最近一次实质会话。
4. 证据包最多 24,000 字符。任一原始消息未进入证据包时标记 `relevant_subset`；数据源分页异常时标记 `partial_source`。内部同时记录数据源完整性、证据覆盖范围与附件扫描状态。
5. LLM 只读取证据包，一次生成直接答案、关键事实和未确认项。每个可陈述事实必须引用实际 `evidenceIds`。
6. `format-output` 只渲染有效引用；模型自由文本不直接对客输出。

## 输出设计

`analysis` 固定呈现：

1. **查询结论**：直接回答用户问题。
2. **关键依据**：最多 3 条事实，附日期和说话方。
3. **尚未确认**：仅当 `dataCompleteness = complete` 时展示。
4. **覆盖提示**：`partial_source` 或 `relevant_subset` 时明确本次摘要不覆盖全部沟通。
5. **历史附件**：当本次摘要已命中图片或附件发送事件时，由代码直接返回对应可点击链接及过期提示，最多展示 3 个最新链接；用户明确要求查看、打开、下载、获取链接时，最多展示 20 个。用户只问是否存在附件时，只说明类型、发送方和时间。

不得把客服建议写成已完成、把客户反馈写成客服结论，或把“未见明确确认”写成“未处理”。不得提及飞书、多维表、内部系统、身份核验或完整查询过程。

`structured` 的稳定字段：

- `answerStatus`、`requestType`
- `matchedConversationCount`、`matchedMessageCount`
- `evidenceConversationCount`、`evidenceMessageCount`
- `dataCompleteness`：`complete` / `relevant_subset` / `partial_source`
- `keyFacts`、`unconfirmedItems`、`evidenceRefs`
- `attachments`：用户明确索要附件，或本次摘要已命中附件发送事件时出现，包含类型、发送方、时间和原始链接

根级仍保持 `structured`、`analysis`、`outputContext`、`enrichedContext` 四字段合约。

## 异常与回退

- 缺少 `username`、查询超期、当天不可查、无记录、无相关命中和数据源失败均由代码返回固定对客说明。
- LLM JSON 无法解析、没有有效直接答案，或引用了不存在的证据 ID 时，不输出模型自由文本；返回“已找到相关记录，但无法生成可核验摘要”的安全提示。
- 负面结论只允许在完整证据范围内出现；部分来源或预算截短时仅说明覆盖限制。
- 附件链接只接受源记录中的 `http/https` URL，不下载、不识别、不转存附件内容；无可访问 URL 时说明该限制，不生成链接。
- “跟客服聊”等表述仅说明会话背景；只有“客服发给我的图片”“我发的附件”等明确发送方表达才按角色筛选附件。

## 验收

- 操作回忆保留客服明确步骤及日期依据。
- 结果类问题区分客服承诺和已完成确认。
- 泛问只回顾最近一次实质会话。
- 关键词和显式日期只向 LLM 传递相关证据。
- 超长结果不输出全文，标记 `relevant_subset`。
- 部分数据标记 `partial_source`，不作完整性承诺。
- 无效引用、空摘要或非法 LLM 输出均走受控回退。
- 附件存在性、客服/客户角色筛选、链接交付、失效/非法链接、部分来源与附件数量上限均有回归覆盖。
