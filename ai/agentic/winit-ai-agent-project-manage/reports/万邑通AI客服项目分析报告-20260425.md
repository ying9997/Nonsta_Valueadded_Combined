## 一、项目概述

万邑通AI客服项目旨在通过AI自动化处理海外仓客服咨询，提升客服效率，降低人工成本。项目核心目标是扩大AI覆盖范围，提升AI对话准确率和客户体验。

### 项目进度总览

- **项目阶段**：2026年Q1灰度放量阶段
- **当前覆盖客户**：累计灰度关闭"直达人工"按钮客户约 1400 + 889 = **2289家**
- **预计进一步灰度**：新增约 **1329家**（流失预警279 + 活跃-低32 + 活跃-中221 + 活跃-高95 + 正常合作77）

## 二、核心指标复盘（W16）

### 未解决客户反馈原因分布

### AI未能对接内部流程 — 业务细分

| 业务段 | 典型场景 | 数量 |
|-------|---------|------|
| 增值 | 直接查询增值单信息回复sla | 1 |
| 尾程 | 尾程地址校正、轨迹查询、面单获取等 | 9 |
| 索赔 | 索赔单进度查询 | 1 |
| 商品 | 根据商品条码查询对应sku | 1 |
| 入库 | 根据入库单预约到仓时间回复上架sla、入库催上架等 | 4 |
| 价卡/钱包 | 根据出库单回答附加费问题、计算尾程费用等 | 8 |
| 退货 | 查询退货单轨迹、根据sku查找退货单 | 3 |
| 出库 | 查看出库单记录、下单增值情况等 | 5 |
| 基础信息 | 仓库地址获取方式 | 4 |

**核心发现**：尾程（9）+ 价卡/钱包（8）+ 出库（5）是当前AI对接流程的主要瓶颈，合计占未对接的 ~64%。

## 八、技术问题讨论

### 近期问题（截至4月24日）

1. **名词混淆导致错误**
   - 索赔时效混淆："代客索赔"和"标准索赔"时效规则不同，AI混淆回复
   - 轨迹识别错误：派送失败/已到仓状态识别错误

2. **链接泄露问题**
   - AI错误返回内部飞书record链接给客户，存在信息安全隐患，已修复（4月24日晚计划发布）

3. **不必要转人工问题**
   - 客户已经提供新信息后仍然错误转人工，需要修复逻辑
   - 已知问题：转人工按钮点击后会隐藏，导致连续点击无法成功转人工，前端已修复

4. **模型质量问题**
   - Seed-mini模型质量差，已切换：Seed-mini → Seed-lite → Seed-pro
   - 之前因pro太慢使用mini，现在换回pro获得更好准确率

5. **前端界面调整**
   - 转人工按钮颜色调整：已调整为测试用紫色，匹配卖家网站系统色

6. **信息安全管控**
   - 已达成共识：禁止向客户透露团队内部在review对话数据
   - 竞对客户咨询内部信息时，AI不应泄露任何敏感信息

## 九、核心结论与建议

### 1. 主要瓶颈

| 瓶颈 | 影响 | 建议优先级 |
|-----|------|-----------|
| AI未能对接内部流程（占55%） | 大量咨询仍需人工 | 🔴 P0 |
| 业务术语混淆 | 导致分类和回答错误 | 🟠 P1 |
| 知识库不完整 | 持续产生不准确回答 | 🟠 P1 |
| 专家层能力覆盖不足 | 复杂业务场景无法处理 | 🟡 P2 |

### 2. 建议行动项

1. **优先推进尾程、价卡/钱包、出库业务流程对接**：这三个业务段占AI未对接流程的64%，改造后能显著降低人工转接率

2. **尽快完成业务术语字典**：解决"代客索赔/标准索赔"、"箱产品/子包裹"等名词混淆问题，能快速提升准确率

3. **维持每周周度review机制**：持续监控未解决原因分布，跟踪改进效果

4. **建立QA快速迭代通道**：目前遗留不准确回答482条，需要按优先级分批修复

5. **继续灰度放量**：当前已有2289家客户进入灰度，可按计划继续扩大覆盖，收集更多真实数据
