### 1.1 客户数统计口径

数据来自权限组编辑页 → **「个性化配置（客户群体/客户）」** 列表，接口 `OmsRacCustomerLimitService_queryCustomerLimits`，统计 **当前有效** 的个性化配置条数（`totalElements`）。

| 字段 | 含义 |
|------|------|
| **全局默认** | `允许`：新客默认开放该权限；`不允许`：须单独配置客户后才可用 |
| **个性化配置客户数** | 已在 TOM 中显式配置的客户（或客户群体）条数；**不是**全平台客户总量 |
| **全局默认允许 + 客户数 = 0** | 全员默认开放，无个性化覆盖记录（如 AU 仓） |
| **全局默认不允许 + 客户数 = N** | 仅 N 个客户（或群体）被单独开通（如 UKTW 仓 9,638） |

> 同一客户在不同权限组会重复计数；「已配置客户合计」为各权限组客户数 **直接相加**，不代表去重后的独立客户数。

## 8. AI 客服建设参考

与 `in-warehouse/入库环节计划.md`、`in-warehouse/需要研发支持的.md` 对齐的初步结论：

1. **入库咨询高频子域**：仓库能否入库（`INBOUND_WAREHOUSE`）、验货方式/包裹类型（`SELF_OR_OVERSEA_INSPECTION`）、混验多验（`OLD_SELF_STANDARD_INSPECTION`）——前三类与入库主线强相关。
2. **客户量差异大**：UKTW/USWC/USWC2 等入库仓个性化配置客户数达数千级；海外验类默认全员开放；退货质检/第三方退货整体配置客户极少（合计 23）。
3. **退货相关**：`RMA_QC_WAREHOUSE`、`RMA_OTHER_OUTBOUND_STANDARD` 更偏退货/出库交叉，若入库专家 scope 不含退货，可单独路由或后续波次建设。
4. **专家数据依赖**：回答「某客户能否入某仓 / 用某种验货方式」需 **客户维度权限查询接口**（tom-relay 或同类），并遵循订单/客户归属校验规约；不能仅用全局默认推断个体客户权限。
5. **知识库可覆盖部分**：各权限组的 **提示文案** 已含推荐仓、货品限制、申请路径，可直接沉淀为 KB；动态判断仍需接口。
6. **编码体系**：权限组编码 `QXxxxxx` 与 `typeCode` 可作为专家工具入参/路由标签，便于与 TOM 后台对齐。
