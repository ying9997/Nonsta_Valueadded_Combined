## 3. 阶段划分与产出

### 阶段 A — 数据与范围（P0）

**目标**：锁定「什么叫入库咨询」统计口径，拉齐可分析的数据源。

- **数据源**：人工会话 / 工单 / AI 转人工样本（字段：时间、渠道、客户、摘要、标签若有）。
- **范围定义**：入库单、预约到仓、收货异常、上架 SLA、催上架、增值与入库交叉等 — 与业务确认 **纳入 / 排除** 边界。
- **产出**：数据范围说明 + 抽样规则 + 体量预估（条数 / 占比量级即可）。

### 阶段 B — 场景分类（P0）

**目标**：形成可路由、可运营的 **taxonomy**（支持后续：专家 / 知识库 / 转人工）。

- **方法**：自上而下（业务域）+ 自下而上（聚类 / 高频问法）结合；与 `prompts/classifications.md` 中既有分类 **映射或增改** 需单独立项评审。
- **产出**：**入库咨询场景分类表**（分类 ID、名称、定义、典型问法、样例链接、当前是否可 KB 覆盖）。

### 阶段 C — 目标与处置矩阵（P1）

**目标**：每个场景对齐 **对客应达成目标**（能答什么、不能答什么、何时转人工）。

- **产出 1**：**场景–目标对齐纪要**（产品 / 业务 / 研发共识）。
- **产出 2**：**场景–处置方式矩阵** — 专家（含依赖接口）/ 纯知识库 / 混合 / 仅人工；粗估 **专家个数、KB 主题数、接口清单**。

### 阶段 D — 建设波次（P1 → P2）

**目标**：按优先级排 **迭代波次**（先做覆盖率与风险最高的子集）。

- **知识库**：SOP、时效话术、边界说明；与现有 qa-gen 流程衔接。
- **专家 / 工具调用**：依赖 **入库单 / 订单 / WMS 或中台** 只读接口的，在矩阵中单列依赖与联调窗口（可与 tom-relay 类能力类比管理，但系统域不同）。
- **观测**：上线后跟踪 **场景覆盖率子集、准确率、转人工率**，对照 `README` 中 KR-1 衡量指标。
