## 业务场景
**订单已出库申请尾程截单/改地址**

客户对已出库的尾程包裹申请截单（拦截）或改址，需要按照渠道支持情况和包裹当前状态进行处理。

## 二、关键判断规则

### 1. 支持截单的渠道范围
仅特定渠道支持尾程截单：
- **美国**：UPS、Fedex、OnTrac 等特定**地面服务**支持
- 其他渠道不支持

### 2. 是否可以截单的判断逻辑

| 条件 | 处理方式 |
|------|----------|
| 派送方式不支持截单 | 直接回复客户无法截单，建议联系收件人协商（如拒收） |
| 派送方式支持截单 | → 判断轨迹状态 |
| 轨迹 **无上网信息** 或 **已妥投** → 走查件流程 | 需要客户确认是否提交 |
| 轨迹正常在途 → 继续处理 | 进入费用确认环节 |

---

## 三、费用说明话术规则

AI需要**根据承运商类型播报具体费用标准**，然后请客户确认：

> **示例话术结构：**
> "您好，该尾程渠道（XXX）截单服务费为 XX 元/票。请问您确认需要申请截单吗？"

---

## 四、AI标准拒绝话术（渠道不支持时）

> **固定话术：**
> "您好，经核实您的订单不属于支持尾程截单的服务范围（仅美国UPS/Fedex/OnTrac等特定地面服务支持）。无法申请尾程截单，建议您联系收件人协商处理（如拒收）。"

---

## 五、处理节点总结

| 步骤 | 操作 | AI输出 |
|------|------|--------|
| 1 | 接收客户请求，获取单号 | - |
| 2 | 查询包裹状态和尾程渠道 | - |
| 3 | 判断派送方式是否支持 | 如果不支持 → 输出拒绝话术，结束 |
| 4 | 检查轨迹状态 | 无上网信息或已妥投 → 引导走查件流程 |
| 5 | 客户确认是否提交 | 不确认 → 结束 |
| 6 | 播报费用标准并确认 | 等待客户回复确认 |
| 7 | 根据客户确认 | • **确认截单** → 提交申请，结束<br>• **不确认** → 关闭对话，结束 |

## 六、需要对接的系统数据

| 数据项 | 来源系统 | 说明 |
|--------|----------|------|
| 包裹当前轨迹状态 | **delivery-status**（统一获取） | 轨迹状态已由 delivery-status 解析完成，包括无上网信息/已妥投等 |
| 尾程渠道信息 | 订单系统 / TOM | 判断渠道是否支持截单 |
| 承运商截单费用标准 | 价卡系统 / 配置表 | 播报给客户确认 |
