## 一、业务处理流程

```mermaid
flowchart TD
    A[开始：客户申请POD] --> B[客户提供快递单号/订单号] --> C[通过 delivery-status 获取轨迹]
    C --> D{包裹是否已妥投?}
    D -- N --> E[告知客户：包裹未妥投，没有POD] --> Z[End]
    D -- Y --> F[从系统POD库查询是否已有POD]
    
    F -- Y --> G[返回POD文件链接给客户] --> Z[End]
    F -- N --> H{是否支持在供应商网站获取?}
    
    H -- Y --> I[提供获取方式 OR 帮客户下载后提供] --> Z[End]
    H -- N --> J[提交"妥投未收到"/"申请POD"查件申请] --> Z[End]
    
    Z[结束]
```

## 二、SOP 关键信息整理

### 可直接在 TOM 获取 POD 的渠道/供应商

目前以下供应商的单号可以直接在 **TOM → 供应商 → 轨迹管理 → pod 界面** 查询：

| 供应商 | 说明 |
|--------|------|
| AU POST | 支持 |
| TOLL | Toll 纯数字跟踪单号支持 |
| PFL | PFL 订单支持 |
| DB | 支持 |
| DHL Paket | 支持 |
| Hermes | 支持 |
| OnTrac_Ground | 支持 |
| SWA | 支持 |
| UPS - Ground | 支持 |
| DE DPD | 支持 |

### 特殊情况处理

如果轨迹显示已妥投，但 TOM POD 库中没有：

1. 检查妥投时间：如果是**当天**，可能还未回传
   - 告知客户系统正在回传，建议等待
2. 如果**着急**：请查件同事加急向供应商索要

### 自助获取指引

- 部分供应商官网支持直接查询下载
- 引导客户自助查询，或由客服代为下载

## 三、流程节点说明

| 节点 | 处理动作 | 说明 |
|------|---------|------|
| **客户输入** | 提取快递单号/订单号 | 必须获取单号才能查询，没有则追问 |
| **轨迹获取** | 复用 delivery-status 获取的轨迹数据 | 无需自行查询，由 delivery-status 统一提交 |
| **妥投判断** | 从轨迹数据判断是否已妥投 | 只有已妥投包裹才有 POD |
| **POD库查询** | 查询系统缓存库是否已有POD | 有则直接返回链接 |
| **供应商支持判断** | 判断当前承运商是否支持官网获取 | 支持 → 协助客户获取；不支持 → 提交查件申请 |
| **提交申请** | 走内部查件申请流程 | 人工跟进处理 |

## 四、AI 处理要点

### 关键参数提取
1. **快递跟踪号** → 优先使用跟踪号查询
2. **订单号** → 没有跟踪号时用订单号查询
3. **客户紧急程度** → 判断是否需要加急处理

### 需要对接的系统数据
- **delivery-status** → 获取已解析的轨迹数据（主要是妥投状态判断）
- POD 文件缓存库 → 查询已缓存的妥投证明
- 供应商配置表 → 判断该承运商是否支持官网获取 POD

### 特殊规则
- **必须确认妥投**：未妥投包裹无法提供 POD，必须先告知客户
- **缓存优先**：先查系统缓存，减少人工操作
- **加急处理**：客户着急时，引导走加急查件流程
