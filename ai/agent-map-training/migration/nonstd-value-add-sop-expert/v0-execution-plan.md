## 1. ⭐ V0 必须回答的 7 个问题（非标增值 SOP expert 的"宪法"）

> **这部分必须人肉答，不能丢给 AI。** 这是整个 expert 的边界和灵魂。

### 1.1 对应哪个业务流程段？
- [ ] 填：非标增值 SOP 在入库后 / 履约中 / 售后哪个阶段触发？
- [ ] 填：典型用户触发场景（客服对话 / 工单 / 运营后台）

### 1.2 用户输入是什么？
- [ ] 填：用户会提供哪些信息？（订单号？商品信息？客户诉求？）
- [ ] 区分：哪些是确定事实，哪些是不确定需要追问的

### 1.3 可处理候选范围是什么？
- [ ] 填：哪些「非标场景」在 V0 范围内可以被 SOP 指引覆盖
- [ ] 填：哪些明确**不做**（不在 V0 内）

### 1.4 需要哪些 intent / route / branch？
- [ ] 填：V0 先定 2-3 个核心 intent（如：匹配SOP / 生成指引步骤 / 边界转人工）
- [ ] 填：每个 intent 对应什么 route 和 branch

### 1.5 输出契约是什么？
- [ ] 填：SOP 指引的输出格式（步骤列表？判断结论+依据？表格？）
- [ ] 填：输出给谁消费（客服看 / 用户看 / 下游系统）

### 1.6 哪些必须转人工？
- [ ] 填：SOP 冲突、客户特殊协议、金额超限、无匹配 SOP 等边界
- [ ] 填：need_human 分支的判断条件

### 1.7 V0 最小可跑通什么？
- [ ] 填：最小主链路节点序列（建议 4-6 个节点即可）
- [ ] 填：MVP 验收标准（什么算"能用"）

---

## 2. ⭐ 主链路设计（人定骨架 + AI 出草案）

> 基于 1.7 的最小主链路，让 AI 出草案，你改。

### 2.1 最小主链路建议（默认，可调整）
```
识别非标场景 → 匹配SOP库 → 生成指引步骤 → 标注依据 → 边界判断 → 转人工/输出
```

### 2.2 让 AI 做的事
> 把第 1 节的 7 个答案作为上下文，让 AI 按下方格式输出主链路节点设计。

```
请基于我上面定义的 7 个边界条件，为「非标增值 SOP 指引 expert」设计 V0 的
workflow 节点编排。要求：
1. 每个节点给出：节点名、职责、输入、输出、是否确定性
2. 区分：确定性处理（查数/匹配/格式化）/ LLM非确定性分析（生成指引步骤）
3. 必须包含：need_human 兜底分支
4. 每个节点的回答必须包含【结论】【思考过程】【依据】
5. 不要一次设计太多节点，V0 控制在 6 个节点以内
```

### 2.3 你必须亲自确认的 3 件事
- [ ] 节点数 ≤ 6（多了 V0 过重，后面再拆）
- [ ] 生成指引步骤的节点是 LLM 节点，不是确定性节点
- [ ] need_human 分支的条件你认可

---

## 3. ⭐ 节点点亮验收（挑主链路 3-4 个核心节点）

> 每个核心节点必须过「输入→输出→产物→验收」。

让 AI 按此格式输出，你逐条定验收：

```
请帮我点亮「生成指引步骤」这个节点，按以下格式：
7.1 当前要点亮哪个节点？→ 生成指引步骤
7.2 输入是什么？（前置条件）
7.3 输出是什么？
7.4 产物是什么？（具体样例输出一段）
7.5 什么情况下算点亮？（可操作的判定条件，不能模糊）
7.6 当前缺口？
7.7 被谁消费？
7.8 是否主链路必须？
7.9 是否可后置？
7.10 如何记录到纠偏日志？（给一条示例日志）
每个子问题包含【结论】【思考过程】【依据】
```

> **7.5 是重中之重**：验收标准必须可验证，不能写"理解了""差不多了"。

## 4. 🟡 可加速项（AI 出草稿 → 你 30 分钟 review）

> 这部分不阻塞，但能省你大量时间。**可以并行让 AI 做。**

### 4.1 让 AI 做的事（一次性）
```
基于 baseline expert（inbound-appointment-manage）的 design.md、workflow.json、
nodes/、prompts/ 结构，帮我为非标增值 SOP 指引 expert 生成：
A) 阶段3 系统分层建模（3.1-3.10），按【结论+思考过程+依据】格式
B) 阶段4 文件角色映射（4.1-4.10），绝大部分与 baseline 一致，只换业务词
C) 阶段6 概念四步法（涉及 concept：match_sop / generate_guide / need_human 等）
   每个概念按 6.1-6.4 四步法回答

注意：非标增值场景比预约管理简单，不要过度设计。V0 只保留核心概念。
```

### 4.2 你 review 时重点看
- [ ] 分层是否 6 层以内（业务/输入/候选/决策/知识/输出）
- [ ] 文件角色映射有没有把 baseline 的概念（如 booking.list）错误迁移过来
- [ ] 概念定义有没有"为了凑数"加无关概念

## 5. 🔴 最终交付物清单（V0 跑通的标准）

> **下面每一项都存在、且你亲手验收过，才算 V0 完成。**

- [ ] `design.md` — 非标增值 SOP expert 的设计说明（含 1.1-1.7 全部答案）
- [ ] `workflow.json` — 主链路节点编排（≤6 节点）
- [ ] `nodes/` — 核心节点实现（确定性 + LLM）
- [ ] `prompts/` — 指引生成 prompt（你亲手写过、调过的版本）
- [ ] `format-output` 节点 — 输出契约落地
- [ ] `need_human` 分支 — 兜底逻辑可验证
- [ ] `scripts/smoke-nonstd-value-add-sop.ts` — **仿照 baseline 的 smoke 脚本骨架**
  - [ ] 场景1：无匹配 SOP → 应转人工
  - [ ] 场景2：单 SOP 命中 → 应生成指引步骤
  - [ ] 场景3：多 SOP 冲突 → 应转人工或标注冲突
  - [ ] 场景4：超边界（如金额超限）→ 应转人工
- [ ] `logs/correction-log.md` — 至少 1 条纠偏记录（你自己写的）

## 6. 3 天执行时间表

### Day 1 上午（2h）：定"宪法"
- 答完 1.1-1.7（手写，不靠 AI）
- 把答案整理成 brief

### Day 1 下午（2h）：出草案
- 让 AI 做 2.2（主链路草案）+ 4.1（分层/文件/概念草稿）
- review，改主链路和验收方向

### Day 2 上午（2h）
- 让 AI 做 3（核心节点点亮，选 3-4 个）
- review，定死验收标准

### Day 2 下午 - Day 3（弹性）
- 让 AI IDE 按你定的 design.md 生成 V0 节点
- 写 smoke 脚本骨架，填场景预期
- 跑 smoke，看结果，记纠偏日志
- 对照第 5 节清单逐项勾选

## 8. 复用这套打法的模板（以后任何新 expert 直接套）

1. **先人肉答 7 个边界问题**（目标/输入/范围/路由/输出/兜底/MVP）
2. **让 AI 出草案**，人 review 改
3. **每个核心节点过「输入-输出-产物-验收」**
4. **写 smoke 脚本**，跑 4 个关键场景
5. **记纠偏日志**，把"我之前以为XX、后来发现YY"写下来

> 这套流程你已经跑通一遍了。下次遇到任何新 expert（产品推荐、仓储调度、售后策略……），直接复制本文件结构，替换业务词即可。
