- **场景**：异常单增值客户引导（决策层 / v2 Coze / 原型 HTML）

---

## 1. 失控轨迹（对照两份会话）

| 阶段 | 人在做什么 | 会话里的典型表现 |
|------|------------|------------------|
| **可控** | 结构化任务 | `# 任务：…只改…禁止…`（如修 P0/P1、做 v2 包、模块 2 按 GATE 执行） |
| **开始漂** | 中途问概念 | 「diagnosis 和 recommendation 区别？」「要不要 git push？」「会不会和线上冲突？」 |
| **加剧** | 路径/仓库混放或说错 | 推 experts 却贴 `value-add-service-guide.git`；参考 HTML 在 `增值配置AI化/…`，产物在 `_workflow/…`；又说写到「增值单ai指引助手方案文档」 |
| **失控** | 着急贴原始证据 | 连续截图、整段 Coze/节点 JSON（有次约 2 万字 dump）、一句「怎么填」/空图 |
| **回拉** | 再贴结构化回填 | 能拉回（HANDOFF 回填口令），但前面已绕一大圈 |

`019f7eac` 更早同构：结构化开场 → HTML 迭代 →「还有一种方案…参考某某路径」→「除此以外还要扩写 N-M2-2」——**执行线程上叠方案扩写**。

---

## 2. 根因（按重要性）

### 2.1 模式混用（主因）

结构化 prompt 只在「执行回合」有效。人一问「是什么意思 / 怎么测 / 会不会冲突」，模型切到探索/教学态：扩大搜索、改表述、甚至改文件。

人以为在「暂停问一句」；Agent 以为「接到新任务」。

### 2.2 参考物未先入地图

新文件/截图/线上 HTML 从别的目录「扔进对话」，没有先钉：

- 真源路径 = X  
- 本任务只读 / 可改  
- 产物写 Y（哪一层）

路径不一致 → 模型在多棵目录树之间猜 → 越改越散。

### 2.3 着急时用「原始证据」代替「一句话症状」

整包 JSON、连续截图、半截终端错误：**信息量大、指令密度低**。模型先消化 dump 再猜意图，主线被淹没。

### 2.4 同一会话承载过久

早期「禁止改正式包 / 只改 rules」被后面几十轮 git / Coze / 截图冲淡；越补一句越像新支线。

### 2.5 着急节奏本身

打断（turn_aborted）、连发截图、边测边问「写到哪个文档」——**目标未冻结就换目标**。不是模型能力问题，是协作节奏问题。

---

## 3. 不是根因的（避免误归因）

- 不是「结构化 prompt 没用」——DO 回合它很好用。  
- 不是「没有 Ask 按钮就无法控场」——用消息头 `【模式=ASK｜只解释不改】` 即可（见 [playbook.md](../playbook.md)）。  
- 不是「参考文件绝对不能跨目录」——可以跨，但必须先登记再执行。

---

## 4. 改法（下轮怎么做）

1. **一会话一模式**：DO / ASK / FIX；解释与纠错优先 ASK 短会话或消息头锁死「不改文件」。  
2. **新参考先登记三行**再给任务（路径 / 只读可改 / 落哪一层）。  
3. **纠错只贴症状 + 期望 + 只改路径**；禁止整包 Coze dump。  
4. **模式切换 ≥2 次就新开聊天**；首条 = 主线文档 + 一条合法下一步。  
5. **着急熔断**：发消息前写清——主线标准还是非标？成功长什么样？当前 DO/ASK/FIX？  
6. **答疑助手会话** 与 **HANDOFF 交付执行会话** 隔离：搞懂了再回 DO 窗下指令。

可复制口令见 [`../playbook.md`](../playbook.md)。

---

## 5. 和业务主线的边界

- 业务进度、口径、合法下一步 → 只认模块 `HANDOFF.md`。  
- 本文只复盘「人和 Agent 怎么说话才不失控」，**不替代 HANDOFF**。  
- 若协作规矩要挂到项目上，可在 HANDOFF §3 链到 `learn(xuexi)/agent_collaboration/playbook.md`，避免两处全文双写。

---

## 6. 一句话

失控看似是「解释太多 / 路径放错」；更深一层是：**把「搞懂」和「做完」放在同一条执行线程里，又用原始证据代替明确指令。**
