# 维度 C：不确定性分级处理

> 核心问题：当 LLM 的输出不是 100% 确定时，如何分级利用而非一刀切？
> 当前层级：**L2**（入门——只有"进人工"一条退路）
> 目标层级：**L3**（熟练——同一系统中 ≥3 种不确定性处理策略）

---

## 五级阶梯详解

### L1 感知：知道 LLM 会出错

**标志**：在设计中加"禁止编造"约束。
**我的通过实证**：
- 库存健康度 SOP："禁止编造数据、禁止乱改口径"
- 增值配置设计："绝不静默造码、绝不替人新建"
- 增值知识库 AGENTS.md："AI 不得凭经验编造异常编码/VASC 产品名称"

### L2 入门：二值分流（确定→自动，不确定→人工）

**标志**：设计了"确定性分级"但只有两种处理方式。
**我的当前实证**：
- 增值配置 MVP 确定性分级：A→自动 / B→半自动 / C→"强制 needs_review"（本质还是→人工）
- 非标增值引导 inference-rules："无法推断→追问"（只有一种退路）
- 价卡三路并行："多源冲突→进清单"（不尝试自动化解冲突）
- MKS 附件解析："统一模板→自动 / 非模板→人工"

**我在此阶段的局限**：
- 非标会议纪要中李颖说"积累了大量案例后可以免审"——但我的设计中没有从"带审"到"免审"的渐进机制
- 增值引导 system-prompt 写"客户描述模糊时才追问"——但"模糊"没有量化标准
- 增值配置 A2 "近似匹配走 LLM+阈值，低置信一律进人工"——低置信和高置信之间的灰色地带没有设计

### L3 熟练：分级置信度 + 多种降级策略 ← 下一目标

**标志**：同一系统中，对不同置信度区间有不同处理策略（不全是→人工）。

**L3 的 5 种不确定性处理策略（至少掌握 3 种）**：

| 策略 | 适用场景 | 示例 |
|---|---|---|
| 自动执行 + 后置抽检 | 高置信（>90%）+ 低风险 | 属性名精确匹配→自动填，月底抽 5% 验 |
| AI 出草稿 + 人工只看标红 | 中置信（70-90%）| 非模板附件解析→标红低置信字段 |
| AI 提供选项 + 人工选择 | 中低置信（50-70%）| 近似匹配→给 Top3 候选，人选一个 |
| AI 预判 + 人工确认 | 低置信（30-50%）+ 高风险 | 费用项创建建议→人工确认 |
| 直接转人工 | 极低置信（<30%）或极高风险 | 价格拍板、系统操作 |

**我已有的 L3 萌芽（可以扩展）**：
- 增值配置 A2 字典分流器的"精确匹配→近似匹配→需新建"三级——这就是 3 种策略的雏形！
- inference-rules `IR-B03E03-001`："描述已明确则推断；描述模糊才追问"——条件式自动推断

**升级到 L3 的具体练习**：

1. 在增值引导中，为 inference-rules 每条规则加 `confidence_score` 计算逻辑：
   - 关键词完全命中 + 客户描述结构化 = 高置信 → 直接推荐
   - 关键词部分命中 + 描述含歧义信号 = 中置信 → 推荐 + 提示"如不符合可修改"
   - 无关键词命中 = 低置信 → 追问

2. 在增值配置 MKS 附件解析中，把"非模板→人工"拆为：
   - 非模板但表头结构相似度 >0.8 → AI 自动解析 + 标"建议核对"
   - 相似度 0.5-0.8 → AI 生成草稿 + 标红每个不确定字段
   - 相似度 <0.5 → 只标记"此附件需人工读取"

3. 为增值配置整体设计一个"每个输出字段带 confidence 标签"的机制：
   - 输出的 `generated.xlsx` 每个单元格旁有一列 `source_confidence`
   - validation_report 按 confidence 分组展示（而非按"类型"分组）

### L4 精通：置信度校准 + 自适应阈值 + 监控反馈

**标志**：
- 置信度是通过数据校准的（"我标 80% 的结果，真实对的概率确实是 80%"）
- 阈值根据场景风险动态调整（金额大→严格 / 属性名→宽松）
- 人工修正结果回流到评估集，持续更新阈值

**学习关键词**：
- `calibration plot / reliability diagram`
- `expected calibration error (ECE)`
- `risk-adjusted threshold`

### L5 创造：渐进式信任框架

**标志**：设计出一套通用的"冷启动→信任积累→自动化提升"框架
- 新场景/新客户默认 100% 人工
- 积累 N 个 case 无错 → 自动提升该场景的自动化比例
- 一旦出错 → 自动降级该场景的阈值
- 整套机制可配置、可观测

## 补齐知识的学习路径

### 入门读物（理解概念）
- 搜索：`selective prediction machine learning` —— 什么时候该说"我不知道"
- 搜索：`LLM confidence calibration` —— 如何知道 LLM 有多确信
- 搜索：`cascading classifiers / cascading AI systems` —— 多层过滤系统如何设计

### 工具实践（动手做）
- 在任何一个 LLM 调用上加 `logprobs` 参数，观察 token 概率分布
- 用 LLM 自己做 self-eval（"你对这个答案有多确信？1-10分"），验证与人工判断的相关性
- 用 promptfoo 或类似工具，对同一 prompt 跑 N 次，统计结果一致性

### 项目实战（嵌入工作）
- 增值引导下一版迭代时，在推断逻辑中加入 confidence 分级
- 增值配置下一个新服务（不是审计盘点）时，尝试不同置信区间用不同策略
