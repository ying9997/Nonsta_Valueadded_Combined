# 维度 D：反馈闭环与渐进式信任

> 核心问题：如何让系统从"上线时的质量"持续进化到"越用越好"？
> 当前层级：**L2**（有验证能力，但无持续迭代机制）
> 目标层级：**L3**（有可运行的评估集 + 回归机制 + 量化对比）

---

## 五级阶梯详解

### L1 感知：知道需要验证

**标志**：在设计文档中写"需要验证"但没有具体方法。
**通过实证**：库存健康度 SOP 中写"spot-check 某一品类温度计与 L1 手工透视一致"——知道要验，但方法是 ad-hoc 的。

### L2 入门：能做一次性验证

**标志**：有验证动作，但是手工/一次性的，无法重复运行。
**我的当前实证**：

1. **probe 脚本渐进探测**（增值配置 `runs/dbhub_mks_probe1~34.py`）
   - 说明我知道用代码探测数据链路
   - 但 34 个脚本是线性追加的，不是一个可重跑的 test suite
   - 每次新发现后手工写新 probe，而不是把断言固化为回归

2. **验收集隔离**（增值配置 `01_技术设计_MVP.md` §3）
   - 明确写了"OSF6V1829/OSF6V1787 的配置产物 = goodcase"
   - 设计了"AI 不得读取验收集"的防透题规则
   - 但验收只在"跑完对比"时发生一次，不是持续的

3. **价卡数值级还原验证**（`价卡数据链路实证_20260717.md`）
   - 逐仓对数：AU=60✓、CA=52✓、DE=30✓、UK=30✓、US=45✓
   - 发现 DENW3 差异（24≠27）并明确记录
   - 这是高质量的一次性验证，但做完就结束了

**我在此阶段的局限**：
- 没有 `pytest` 或等价的自动化回归机制
- 规则变更后没有自动重跑验证（手工决定"要不要再验一次"）
- 没有在线监控（上线后人工修正了什么，我不知道）

### L3 熟练：可重复的评估 + 人工修正回流 ← 下一目标

**标志**：
- 有一个可重复运行的 golden set + 自动化对比脚本
- 每次 prompt/规则变更都能量化"前后差异"
- 人工修正的结果能回流成新的 golden case

**L3 的最小实现方案（适合我当前项目）**：

```
评估集构建：
  goodcase 行 63/41/191-291/8（已有）
  + 增值引导的 test_prompt 系列（已有 B0102E23）
  + 每次人工修正后追加新 case

回归脚本：
  输入：规则/prompt 的当前版本
  执行：对评估集逐条跑一遍
  输出：命中率表 + diff（哪些 case 从对变错 / 从错变对）

触发时机：
  - 每次修改 inference-rules.md → 自动跑
  - 每次修改 system-prompt.md → 自动跑
  - 每次新增 golden case → 自动跑
```

**从 L2 升到 L3 的进步实证（我已有的萌芽）**：
- `inference-rules.md` 有 `来源状态` 列（`copied_from_test_prompt` / `structured_from_matrix_acceptance_fix`）= 规则有版本追踪
- 增值配置设计了"逐字段命中率 + 三类清单查全率"作为回归指标 = 知道需要量化
- 非标增值会议共识"先上→迭代→积累案例→免审"= 认知上接受了渐进式信任

### L4 精通：数据飞轮 + 自适应系统

**标志**：
- 系统使用量越大→评估集越丰富→模型/规则越准→用户越信任→使用量越大
- 自动识别"哪些场景/客户的修正率高"→自动降级这些场景的自动化程度
- 阈值不是写死的，而是随数据自动校准

**关键概念**：
- Data Flywheel（数据飞轮）
- Active Learning（主动学习——让系统主动选择"最值得问人工"的 case）
- Concept Drift Detection（分布漂移检测——发现规则失效）

### L5 创造：信任框架产品化

**标志**：设计出通用的"AI 系统信任度管理"框架
- 每个"决策点"有独立的信任度状态
- 信任度随正确决策增加、随错误决策衰减
- 运营可以配置"哪些决策点允许免审"和"回退条件"
- 整套机制对业务透明可解释

## 补齐知识的学习路径

### 入门读物
- 搜索：`evaluation-driven development for LLM` —— 用评估驱动 prompt 迭代
- 搜索：`LLM observability (LangSmith / Braintrust / Phoenix)` —— 在线监控工具
- 搜索：`data flywheel AI product` —— 数据飞轮的产品设计

### 工具实践
- `promptfoo`：最轻量的 prompt 回归测试工具，YAML 配置 + CLI 运行
- 在增值配置的 `runs/` 中，把 probe 脚本重构为 `pytest` 形态（assert 语句）
- 为增值引导写 3 个 golden case 的 JSON fixture，每次改 prompt 跑一遍

### 项目实战
- 增值引导上线后，设计一个"人工修正日志"格式（哪条推荐被改了→改成什么→为什么）
- 每周从修正日志中提取 1-2 条追加到评估集
- 一个月后看：规则迭代 N 次后，评估集命中率趋势是上升还是平的
