## 二、需要改进的（有实证）

### 1. 严重问题：三份学习目录重复且无主从关系

**实证**：

| 路径 | 内容 | 备注 |
|---|---|---|
| `learn(xuexi)/` | agent_collaboration, experiment, working-habits | 根目录 |
| `_learning/` | agent_collaboration, ai-customer-service-value-add-guide | 根目录 |
| `learning_records/` | 合并了上面两个（独立 git repo） | 根目录，有自己的 `.git/` |

三个目录存放相似内容（如 `agent_collaboration/retros` 在 `learn(xuexi)` 和 `_learning` 中都有），但没有一个是明确的 "权威源"。

**问题**：`learning_records/` 是独立 git repo 嵌套在主 repo 中（非 submodule），操作混乱——主 repo 的 git status 看不到它的变更。

**建议**：确定一个为主，其余要么删要么变为指向主的 symlink。

### 2. 严重问题：知识库/专家系统有大面积文件重复

**实证**：

| 重复对 | 文件数 | 说明 |
|---|---|---|
| `agentic/value-add-service-guide/` vs `_kb0702/value-add-service-guide/` | 224 vs 224（完全相同） | 两处各 224 个文件 |

## 四、模式总结

**你的好习惯**（值得保持）：
- 一旦确定规范就严格执行（`_workflow/` 27 个目录零违规）
- 成熟项目有清晰的分层架构（Inventory 的 shared/platform/projects）
- 设计类项目起步就分离 configs/schemas/prompts/rules/golden_cases

**你的坏习惯**（需要改）：
- "先占坑再说"——建了空目录/重复目录但不清理
- "快照式备份"——copy 一份整个目录做备份而非用 git 分支
- "根目录暂存"——临时文件放根目录后忘记归位
- "多处编辑"——同一份知识库在两个位置都能编辑，没有单一事实源

---

*下次新建目录时自检：1) 这个位置是否已有同类内容？ 2) 是否有唯一权威路径？ 3) 名称是否符合既有命名模式？*
