## 对 pipeline 的优化建议（按优先级）

1. **补齐异常事件字段进审核输入**：对增值单拉 `getEventOrders`，稳定注入 `eventName`/`eventObj`（当前 `_oms_cache` 无此列；T14 details 仅有 EB 占位）。覆盖率不够时，名称规则会统计失真。
2. **不要把「名称→场景」做成唯一硬规则**：时间修正后「批量异常→§2.33」仍 ✗；改为「名称+对象 → 候选场景集合 + 权重」，再用需求描述/属性消歧（与 ACTION_SCENE_MAP 协同）。
3. **优先用「非时间」高相关特征做软信号**：`req_len`、描述关键词、`va_source`、NWEON/LF/条码属性是否具备、仓码；**不要**把 `order_doy` 当业务特征。
4. **§2.1 兜底要显式标注**：低置信度落到尺重换标时，trace 写明 `fallback`，避免与真实命中混淆。
5. **全窗口复验后再固化强约束**：对入库窗口单补拉 events，重跑交叉表；并请业务确认「应然映射」是否要求纠偏历史实操。
