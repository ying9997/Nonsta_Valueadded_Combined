## 3. 正向识别信号

必须同时有：**指定对象（商品/包裹）+ 拍照/拍摄 + 暂存 / 等客户确认后再处理**。缺去向不能强行 B。

### strong positive signals

- 「指定商品拍照暂存」或「异常包裹需拍照核实后再决定处理方式」
- 数字标识（01、02…）且与包裹/商品一一对应
- 写明拍照内容（外箱 / 内物标签 / 数量 / 正反面）+ 回传命名
- 「拍照后放入**暂存区**」「等客户确认后再处理」「待客户辨识后处理」
- 标识拍照后保留，后续再下良品/不良品/上架增值

### weak positive signals

- 单独的「拍照」「拍摄」「回传照片」「拍照核实」
- 单独的「暂存」（拦截单也说「先放一边」）
- 「开箱拍照」「按包裹码命名」但未写暂存/后续处理
- 「入库非标拍照或提供视频」流程提示（`VASC000000307116`）
- 原子 `OW01V1602`

弱信号只够进候选；缺「暂存 / 客户确认后再处理」应 `ambiguous` 或 `unsupported`。

## 4. 反向排除信号

### 不是 F-001 的情况

- 辨识后**换标再上架**（尺重/绿标/对应关系）
- 本批 `348477`：撕标认 SKU → 换商品条码 → **上架**（即使有「见附件图片」，目的是换标上架不是拍照暂存）
- CASEBOOK 里完成的 F-001 换标单

### 不是场景 A 的情况

- 「包裹类异常 / 包裹条码正常、商品条码异常」+ 换商品标签 + 上架
- 拍照只是配角、主作业仍是换标上架（cache `VASC000000281031`：OMS 标了 B 名，正文主体是找出错贴 SKU **更换商品标签**，再套数字标识+暂存 → **脏标 / 复合**，不能当 B gold）

### 不是「拦截不上架 / 先放一边」

- 「拦截不上架 / 先放一边」且**无拍照要求**（本批 14 条）
- 禁止把「暂存」一词单独收成 B
- 现网 `match-template` 把「拍照且无换标」当 weighOnly 排除 F-001；v0.2 应改为「排除 F-001，但**仅当**同时有暂存/待客户处理才可进 B」，否则 14 条拦截会被误收

### 不是库内拍照 / 视频或其它库内场景

- 库内 #7「拍摄照片/视频」、`stock_photo_video`
- SOP 填写示例「库内库存验证拍照及视频记录」（库位下架拍摄、滞销库存证明）
- 库内「指定库位开箱拍照」「异常重新拍照」「辨识拍照后销毁」
- 标准产品「拍照暂存后上架」（本批 pagequery 里的库内标准服务名，不是入库非标 B）
- 退货拆分后「分开拍照暂存」的客诉（udesk 分层集，常是退货标准产品）

### 不是「称重拍照 / 称重暂存」

- CASEBOOK 第 7 组 `VASC000000205086`：异常货全部称重，反馈数据和照片
- CASEBOOK 第 8 组 `VASC000000218202`：指定包裹整箱称重、拍整体和秤面后暂存
- `rules.md` 规则 2：这不是换标，也**不是**指定商品拍照暂存

## 5. 与 F-001 的边界（保守处理）

B 与 F-001 **都可能包含「拍照 / 辨识 / 暂存」**。

| 信号 | 走向 |
|------|------|
| 拍照/辨识的目的是**认 SKU 后换标上架** | F-001（或 A），不是 B |
| 称重 + 拍秤面 / 反馈重量 | 排除 F-001 与 B（规则 2） |
| 指定对象 + 拍照核实 + **暂存、等客户再决定**（不上架、不换标） | 才允许高置信 B |
| 有拍照、无暂存/无「客户确认后再处理」 | **`ambiguous`**，不能强行 B |
| 「先不要上架」但是下一步仍是换标上架（oms-scene-f001 部分 SOP） | F-001 时序，不是 B |
| 「拦截 / 先放一边」无拍照 | `unsupported`，不是 B |

区分不了 → `ambiguous` 或 `manual_review`，`supported=false`。禁止为了召回 B 把 14 条拦截收进来。
