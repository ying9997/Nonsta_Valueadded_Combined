# 禁止使用：怎么验证、怎么盯私聊

## 先说清楚：现在拦得住吗？

| 场景 | 现在算不算生效 | 原因 |
|---|---|---|
| 巡检告警（群里有没有非万邑通） | 已生效 | 今天已经按白名单扫过，异常沟通 251 人外部人数 0 |
| 有人点卡片按钮 | 代码已拦 | listen 一直在收卡片；对方不在白名单会回「禁止使用」 |
| 有人私聊机器人 | **还没当场拦住** | `.env` 里没有打开 `LISTEN_IM=1`，listen 不收私聊 |
| 群里 @机器人 | **还没当场拦住** | 同上，不收普通文字消息 |

规则写进代码了，但私聊/群@要「来一句回一句」，必须让 listen 去听 `im.message.receive_v1`。

## 怎么验证（建议按这个做）

1. **先确认开放平台勾了事件**  
   增值咨询应用要订阅 `im.message.receive_v1`，否则听也听不到。

2. **打开 listen 的私聊开关**  
   本机 `.env` 加一行 `LISTEN_IM=1`，再重启 listen。  
   注意：飞书一个应用同时只能有一条事件总线；开 IM 时不要另开一个抢同一条线的进程。

3. **正向：不该拦的人**  
   你（万邑通）私聊机器人发一句「你好」。  
   过关：不要只回「禁止使用」（内部同事要能用）。

4. **反向：该拦的人**  
   找一个 **非万邑通**（个人飞书或客户）给机器人发一句「你好」。  
   过关：只回「禁止使用」，不要出现审核卡片、SOP、问场景。  
   群 @ 同理：必须是「群里有非万邑通的人」才该拦；【增值】异常沟通全是万邑通，@ 了也不该拦。

5. **回看有没有漏回**（不靠猜）  
   ```
   npx tsx internal-review-copilot/scripts/audit-p2p-access.ts
   ```  
   看 `result.md` 里有没有「外部且回了别的内容」。  
   注意：飞书给机器人的会话列表通常 **只给群、不给私聊**，所以这个回看可能是 0 条；私聊主要靠第 6 步的流水账。

## 怎么监控「非白名单私聊并且得到回复了」

两层：

1. **当场记账**（listen 打开后才有）  
   每次私聊判定、每次拦截，追加一行到  
   `internal-review-copilot/logs/access-audit.jsonl`  
   看 `allow=false` 是拦住了；若出现非万邑通 `allow=true` 就是漏了。

2. **每天扫一遍**（和巡检一起）  
   ```
   npx tsx internal-review-copilot/scripts/audit-p2p-access.ts
   ```  
   只要会话列表里出现私聊，就会标：没回过 / 只回了禁止使用 / **回了别的（漏）**。

要告警群每天看到「有没有人漏回」，把上面这条接到巡检定时任务即可。未点名部署 40 前，只在本机跑。
