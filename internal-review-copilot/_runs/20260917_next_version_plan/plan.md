## 4. 四刀怎么切、怎么算过

### 第一刀（主线，点名后才动手）— H17 方案 B：字 + 图闭环

做什么：

- 橙卡等待补充的单，用现成「改 SOP」那套 12 秒扫话题（只扫还在等补充的单，不全群扫）。
- 文字进「飞书补充」；图片下图 + 认图后再进。
- 齐了出 SOP；还缺更新同一橙卡。
- Excel/PDF：只回「收到文件，这轮不读表」。不假装已经齐了。

怎么验收（本机或隔离飞书，不进现网正式群）：

1. 人回一段字、不 @ → 约十几秒内再判；齐了能出 SOP。
2. 人丢一张标签/操作说明图、不 @ → 能用上图上文字再判。
3. 人丢 Excel/PDF → 只说收到文件，不读表、不因此判齐。
4. 还缺 → 同一话题更新橙卡，只 @ 销售/客服。
5. 反面：不 @ 李颖/何静/耿文文；不点审核通过；人工 SOP 已填仍只私聊金萤；`LISTEN_IM` 仍关。

依赖：本机 Ark 密钥；隔离飞书话题；现有写 OMS 门禁不动。

**不过门：不改代码、不上 40。**

### 第二刀 — H15：齐了 / 还不齐，判得更准

做什么：第一刀能「喂进补充」之后，再收紧「什么叫齐了」。该出 SOP 的不要卡死橙卡；不该出的不要因为补了一句闲话就出 SOP。

怎么验收：抽若干历史「该追问 / 不该追问」单，对照场景最小必要信息。误出 SOP、该出却不出，都要能说清。

依赖：第一刀已能把飞书字/图喂进 L2.5。

### 第三刀 — H9：少追问

做什么：每轮最多追 1～2 个最关键的。补过的不再重复问。卡片上能看出「已确认 / 待补充」。

怎么验收：同一单连续补两次。第二次不再把已填项再问一遍。销售侧体感是「越补越短」，不是「每次一长串」。

依赖：第二刀边界基本稳定，否则少问会漏关键项。

### 第四刀 — H14：Excel / PDF 正文（更后）

做什么：OMS 附件区、以及飞书里丢的表/PDF，真正读内容再判清晰。和第一刀的「只记收到」分开。

怎么验收：对照表能对上关键列（如 SKU/条码/操作说明要点），再决定齐不齐。

依赖：金萤点名「表也要读」。不挡前三刀的字/图体验。

## 5. 风险与硬约束

- **12 秒扫必须只扫「还在等补充」的单。** 橙卡一多，全量扫会打飞书接口。
- **认图会看错。** 第一刀验收要用真标签/圈注图，不能只拿公网风景图当过门。
- **飞书表格 ≠ 已齐。** 第一刀只记收到；真要算附件槽位，仍以 OMS 附件区 uploaded 为准（现网这条规则已通）。
- **禁止开 `LISTEN_IM`。** 会顶掉现网卡片按钮。禁止为了实时去改现有增值咨询应用。
- **补信息只 @ 销售/客服。** 不 @ 李颖 / 何静 / 耿文文。
- **不代点审核通过**，不调 `vaOrderReview`。待审核才写 SOP 草稿。
- **人工 SOP 已填：** 不建群话题，只私聊金萤（已上 40，落地时沿用，不重做）。
- **密钥不进仓库。** Ark 只用本机 `~/.secrets/volcengine-ark.env`。
- **未点名「可以部署 40」不上 40。** 上 40 前：本机（或本机连隔离飞书）端到端跑通，且与现网隔离。40 上只新建 slug / secrets / unit，不改现有增值咨询、不把新 EnvironmentFile 挂到旧服务。
- **飞书发消息 / 认图间隔 ≥12 秒。**
