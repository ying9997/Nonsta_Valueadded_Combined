# OSF8V1848：原子路由 + 独立 pipeline（只对齐，未改代码）

你已拍板：只收 OSF8V1848 询价增值单。不代点审核通过。不上 40。

库存弃置 / 仓内销毁 / 专业销毁 **不是增值原子**，是出库单上的万邑通产品（编码见 `outbound-destroy-products.md`）。Copilot 审询价单时，要读 WO 上客户选了哪个产品，再列出本单还能走哪些。

**补上会议里漏掉的一点：** 审核员现在要切出库单、再切商品页。Copilot 应把跨系统查到的事实 + 规则判断，写成自然语言结构化摘要，**回填到 OMS 的 SOP 文本框**，审核员打开增值单就能看。  
因此：**摘要里要写完整五条出库产品「能走/不能走」，以及客户已经选的那一条。**

上一版「第一刀不写 OMS SOP」作废，改成「写审核参考摘要 + 保留询价三步；仍不点通过」。

## 2. 新 pipeline 节点（按审核员实际在干的事）

```
runDestructionInquiryPipeline
  1. pickDestroyAtom                     只认 OSF8V1848 询价增值单
  2. bind-vas-header                     仓 / 国家 / 客户 / WO
  3. fetch-outbound-order                读出库单 winit_product（客户选了哪条路）+ SKU
  4. resolve-product-master              商品特性、TS 备案（查不到写未查到）
  5. site-destruction-capability         这个仓允许哪些万邑通产品（美才有仓内）
  6. list-eligible-outbound-products     能走哪些 vs 客户选了哪个（价格先占位）
  7. compose-audit-brief                 上面全部写成 SOP 摘要
  8. write-oms-sop                       回填 SOP 文本框
  9. notify-if-cheaper                   仅当允许集合里有更便宜项才发卡；否则不发
```

节点 6 / 9 用人话（对照录像，不是绿橙红口号）：

- **6 不是「只自动判两刀」。** 用前面查到的仓+商品，列出本单**允许**的出库万邑通产品（库存弃置 / 仓内销毁 / 普货专业销毁 / 危废专业销毁 / TS合规专业销毁），再对照 WO 上客户已经选的那一个。危废、TS 也列进「能走 / 不能走」，不是标完「需人工」就结束。
- **9 不是每张单都发卡。** 允许集合里存在比客户所选更便宜的路 → 建话题问销售客服「现在这个贵，要不要换便宜的」。没有更便宜的允许项 → **不发卡**。价格第一刀用占位排序，你拿到价卡后再换成真价格。

和现网入库节点的对照：

| 现网节点 | OSF8 新 pipeline |
|---|---|
| pickAllowedAtom（三码） | 独立 pickDestroyAtom，**不要**并进三码白名单 |
| validate-input / L1 需求描述 | 不跑（描述为空是正常的） |
| match-template 场景卡 | 不跑 |
| SKU 一致 / T1 / L2.5 | 不跑 |
| llm-generate-sop（入库仓库操作） | **换成** compose-audit-brief（审核参考摘要） |
| writeDraft | 复用写入通道，但换一套 OSF8 守卫（见下） |
| 飞书卡 | **有更便宜允许项才发**；不是每张橙卡 |

## 3. SOP 文本框里到底写什么

分两块，**一块给审核员看事实，一块给仓库办事**。LLM 只负责把 JSON 说成人话，不许编单号、不许把「未查到」写成「普货」。

```
【审核参考摘要】（系统根据出库单/商品主数据拼装，供审核核对，不等于已审核通过）

一、系统事实
- 增值询价单：OSF8V1848 / VASC…
- 出库单：WO…
- 仓库 / 国家：USKY5 / 美国
- 客户已选出库产品：普货专业销毁（OSF831009111）
  （不要写成增值属性「销毁方式=物理销毁」）
- 商品：SKU / M码 / 品名 / 带电；其它特性未查到要写明
- TS 备案：有 / 无 / 未查到

二、本单能走哪些出库产品（规则，价格先占位）
- 库存弃置：能 / 不能 + 原因
- 仓内销毁：能 / 不能 + 原因（非美或金属/液体/电子 → 不能）
- 普货专业销毁：能 / 不能 + 原因
- 危废专业销毁：能 / 不能 + 原因
- TS合规专业销毁：能 / 不能 + 原因
- 价格：占位排序 弃置 < 仓内 < 普货专业 < 危废 < TS（待业务价卡替换）

三、和客户已选对比
- 客户选的是否在允许集合内
- 允许集合里有没有更便宜的
- 要不要问销售客服：有则写「建议问要不要改成 XX」；没有则写「不通知，按当前询价走」

【仓库询价步骤】（产品模板，保留）
1. 仓库报价；
2. 客户若同意报价，仓库开始作业，打包完成后联系销毁公司出库；
3. 销毁完成后，将销毁公司提供的销毁证明上传。
```

| 出库产品 | 摘要里 | 什么时候问销售客服 |
|---|---|---|
| 库存弃置 / 仓内销毁 / 三种专业销毁 | 都必须写能走或不能走 | 仅当「能走且（占位）更便宜」 |
| 客户已选 | 必须写编码+名称 | — |
| 没有更便宜允许项 | 写「不通知」 | **不发卡** |

失败收口：商品事实不够 → 仓内销毁不要标「能走」，摘要写未查到。非美仓内一律不能。没有更便宜允许项就不发卡。

## 4. 写入 OMS 时必须换守卫

现网 `writeDraft` 看见 SOP 已有字就当成「审核员手写，禁止覆盖」。  
OSF8 待审核 17 张 **已经印着产品询价三步**，按现网守卫会整批写不进去，摘要回填会失败。

OSF8 专用规则：

- 现有正文 = 已知产品模板（询价三步）→ **允许**改写成「摘要 + 三步」
- 现有正文已被审核员改过（不是模板、也没有【审核参考摘要】）→ **仍禁止覆盖**
- 已有【审核参考摘要】且是本系统写的 → 允许按新事实更新
- 审核信息字段已有人写的字 → 仍禁止覆盖
- 非待审核 → 不写
- **绝不点审核通过**

需求描述 / 需求背景：第一刀不要拿入库的【AI总结】去覆盖（这两格本来就是空的）。只动 SOP 文本框。

## 5. 要查的 API（摘要质量取决于这些）

| 事实 | 现在 | 摘要 | 自动判 |
|---|---|---|---|
| 仓 / 国家 | 增值单 header 已有 | 要写 | 非美 → 仓内销毁标不能 |
| WO | header.businessNo 已有 | 要写 | 缺则红 |
| **客户已选哪条路** | **出库单 `winit_product_code/name`** | **要写** | 对比允许集合 |
| 允许走哪些出库产品 | 规则 + 仓 + 商品 | **要写完整五条** | 有更便宜允许项才通知 |
| SKU / M码 / 品名 / 带电 | 出库商品表；增值商品清单空 | 要写 | 仓内/危废判定的一部分 |
| 金属/液体/电子/化工/食品/纯电 | 商品主数据，Copilot 未接 | 要写；查不到写未查到 | 缺则仓内不要标「能走」 |
| 价格 | 价卡未接 | 占位排序 | 你给价卡后再比真价格 |

接口候选：万邑通 `queryOutboundOrder`（出库专家已用）；OMS 出库单详情页（何静会上点的）。数仓表当前 SELECT 被拒，不要赌。

没有出库产品码时，摘要只能写仓、国家、WO，「客户已选 / 能走哪些」标未查到——审核员知道缺什么，也不要乱标仓内能走。
