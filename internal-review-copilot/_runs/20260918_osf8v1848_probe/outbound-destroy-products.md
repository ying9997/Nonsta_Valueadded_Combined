# 销毁出库：业务流程和系统字段

对照录像 06:30 / 12:35 / 25:45，并用 OMS 出库表核对。代码未改。

---

## 1. 客户选的不是增值原子，是出库单上的「万邑通产品」

客户在**新建出库单**时选怎么处理这批货。录像原话：选弃置就走到库存弃置；点销毁里面才有仓内销毁、普货销毁、危废销毁。

这三样（再加专业销毁的两个细类）都是 **出库单字段 `winit_product_code` / `winit_product_name`**，表：`ods_oms.oms_wh_outbound_order`。大类编码 **OSF83**。

| 万邑通产品编码 | 名称 | 四级分类 | 近量表内张数（全历史） |
|---|---|---|---|
| OSF832009109 | 库存弃置 | OSF832 | 1651 |
| OSF831009110 | 仓内销毁 | OSF831 | 486 |
| OSF831009111 | 普货专业销毁 | OSF831 | 352 |
| OSF831009112 | 危废专业销毁 | OSF831 | 20 |
| OSF831009113 | TS合规专业销毁 | OSF831 | 4 |

老产品 `OSF830859`「Scrap Service（销毁服务）」量很大，是旧销毁产品，不是这次前台三选。

**增值单 OSF8V1848（专业销毁非标询价）是另一张单。** 录像：只要下了三种专业销毁，必须再下一张询价增值单。样例 `WO12271270323`：`need_offline_vas=Y`，产品名「普货专业销毁」，才绑着 `VASC000000374748`。

```
客户下出库单 WO
  选万邑通产品 = 库存弃置 / 仓内销毁 / 普货专业销毁 / 危废专业销毁 / TS合规专业销毁
        │
        ├─ 库存弃置、仓内销毁：一般没有 OSF8 询价单（不进本 Copilot）
        └─ 三种专业销毁：必须再下一张增值单 OSF8V1848
                 │
                 ▼
          Copilot 审的是这张增值单
          但「客户选了哪条路」要读 WO 上的 winit_product，不是增值属性「销毁方式=物理销毁」
```

## 2. 字段对照（增值单 vs 出库单）

样例：增值 `VASC000000374748` ↔ 出库 `WO12271270323`（USKY5，待审核）。

| 问题 | 系统 | 字段 | 样例值 |
|---|---|---|---|
| 这是不是出库来的增值 | 增值单 header | `vaSource` / `businessType` | OUTBOUND / 出库订单 |
| 询价原子 | 增值原子 | `serviceCode` / `serviceName` | OSF8V1848 / 专业销毁非标询价 |
| 增值产品 | 增值 header.vasc | `productCode` / `productName` | VASC202608121453409 / 专业销毁非标询价服务 |
| 绑哪张出库单 | 增值 header.businessOrder | `businessNo` | WO12271270323 |
| 增值上的「销毁方式」 | 原子属性 | 销毁方式 | **物理销毁**（不能当细类用） |
| **客户到底选了哪条销毁路** | **出库单** | **`winit_product_code` / `winit_product_name`** | **OSF831009111 / 普货专业销毁** |
| 要不要线下询价增值 | 出库单 | `need_offline_vas` | Y |
| 出库方式 | 出库单 | `export_type` | RPL（本单） |
| 仓 / 国家 | 出库单或增值 header | `dispatch_wh_code` / `country_code` | USKY5 / US |
| 商品 | 出库商品表 | `merchandise_code`、`merchandise_serno`(M码)、`name_cn`、`brand`、`is_battery` | 本单是摩托车配件，铝拉手等，`is_battery=N` |

增值 `getEventOrder4VaAtom` 对本单返回空。商品必须查出库单，不能指望增值「商品清单」。

化工 / 食品 / 纯电 / 金属 / 液体 / TS 备案：**出库商品表里没有这些完整特性**，还要查商品主数据（录像 15:30–18:26）。`is_battery` 只是带电的一小块。

## 3. 审核员实际在干什么（对应录像，不是绿橙红口号）

1. 打开增值询价单 → 找到 WO。  
2. 看出库单：客户选的万邑通产品是哪一个。  
3. 看商品 + 仓：这批货**允许**走哪些万邑通产品。  
4. 把「能走哪些」和「客户选了哪个」写进 SOP 框给审核员看。  
5. **仅当**允许集合里有比客户所选更便宜的路 → 建话题、发卡问销售客服：现在这个贵，有更便宜的要不要换。  
6. 没有更便宜的允许项 → **不发卡**，只写摘要。

价格第一刀先占位（弃置 < 仓内 < 普货专业 < 危废 < TS），你拿到价卡后再换成真价格。

## 4. 节点 6 / 9 用人话重写

**不要叫「只自动判两刀 / 危废标需人工」。**  
**不要每张单都发绿橙红卡。**

| 旧名字 | 新名字 | 干什么 |
|---|---|---|
| destruction-path-check | `list-eligible-outbound-products` | 用仓+商品事实，列出允许的万邑通产品；对比 WO 上客户已选 |
| feishu-card 绿/橙/红 | `notify-if-cheaper` | 允许集合里存在更便宜项才发卡片；否则静默 |

节点 6 输出（进 SOP 摘要）：

- 客户已选：普货专业销毁（OSF831009111）  
- 本单允许：库存弃置 √；仓内销毁 ×（非美 / 含金属…）；普货专业销毁 √；危废 ×；TS ×  
- 更便宜且允许：库存弃置（价格占位）  
- 结论：要问销售客服要不要改；或不问

节点 9：只有「更便宜且允许」非空才 @销售/客服。文案：客户现在选的是贵的 XX，本单还能走更便宜的 YY，要不要问客户改。
