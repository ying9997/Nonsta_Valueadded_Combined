## 2. 先分清：这不是现网 Copilot 在做的那件事

| | 现网 Copilot | 专业销毁非标询价（OSF8V1848） |
|---|---|---|
| 单据 | 入库/库内「其他服务需求」：OW01V1602 / OSF6V1603 / OSF6V1841 | 出库独立原子，产品名「专业销毁非标询价服务」 |
| 客户写了什么 | 一段非标需求，要匹配场景、补信息、写成仓库 SOP | 销毁类型已经选好了，还绑了一张出库单 |
| 专家真正判断的 | 这是哪张场景卡？信息齐不齐？SOP 怎么写？ | 这种销毁能不能做？该不该换成更合适/更便宜的服务？ |
| 现网处理 | 轮询会审 | 明确跳过。例：VASC000000372702、372513 标了「否 OSF8V1848」 |
| SOP 知识库 | 入库/库内场景很厚 | 第四章出库几乎没有「专业销毁」专章 |

样例真单 `VASC000000370308`：英国仓 UKTW，原子 SOP 已经是固定三步——仓库报价 → 客户同意后找销毁公司 → 回传销毁证明。  
**自动改判的价值不是再写一遍这三步，而是拦住「选错类型 / 不该走这么贵」。**  
**给审核员的价值是：把出库单/商品主数据查回来，连同普货/危废/TS 细类和规则判断，写成摘要回填 SOP 文本框，审核员不用再跨系统切页。**

## 3. 销毁路一共几条（会上对齐的事实）

从便宜/简单 → 贵/复杂：

1. **弃置出库**  
   客户把后续处置权交给万邑通（回收/环保）。很多客户不愿意，所以会改选专业销毁。
2. **仓内销毁**  
   仓库用压缩破坏设备做，可出万邑通销毁证明。  
   **仅美国站普货。** 电子元器件、金属、液体不行。德/澳/加/英因法规和仓库条件不行。
3. **专业销毁（三类）** — 客户前台往往只看到「专业销毁非标询价」，细类由审核对照出库单确认：  
   - 普货专业销毁：找外部供应商，事前不好精确估价  
   - 危废专业销毁：化工 / 食品 / 纯电 / 带电等  
   - TS 合规专业销毁：商品必须在「商品备案管理」里有 TS 备案  

硬规则：客户选了这三类专业销毁，必须再下一张 **专业销毁非标询价**（OSF8V1848）。

会上原话（接近）：「今天有个客户下了几个枕头，选了专业销毁……枕头为啥要限制呢，要销毁也不是不行，只是贵而已。」  
「客户以为专业销毁只有出库处理费、没有销毁费，以为最便宜。」

## 4. 专家脑子里其实在问 4 个问题

不要做成「万能销毁专家」。按这 4 问拆：

```
拿到 OSF8V1848
    │
    ├─ 1. 信息齐不齐？出库单、SKU、IM码能对上商品主数据吗？
    │        不齐 → 红：驳回补信息
    │
    ├─ 2. 这种销毁，这个站点+这些商品，合不合规？
    │        不合规 → 橙/红：改到允许的细类，或做不了
    │
    ├─ 3. 有没有更便宜、仍然合规的路？
    │        有 → 橙：请销售/客服问客户要不要换
    │        （弃置会改处置权，不能自动改）
    │
    └─ 4. 路径本身就对？
             绿：沿用原子上已有的询价 SOP（报价→作业→证明）
```

三个停手，和现网卡片颜色对齐：

| 结论 | 对人说 | 对系统 |
|---|---|---|
| 绿 pass | 这种专业销毁做得，按询价 SOP 走 | 可写 SOP，**仍不代点审核通过** |
| 橙 switch | 能做，但不合适；有更便宜/更匹配的服务 | 飞书请销售/客服改服务，附推荐理由 |
| 红 reject | 信息不够，或这条路根本做不了 | 驳回补信息 / 联系客户重选 |

**不能只按「更便宜」自动改单。** 弃置 = 把货的处置权交给万邑通；仓内证明是万邑通出的，专业销毁证明是外部机构出的。客户要哪一种证明，会上没写成死规则，第一刀只能建议、不能替客户改。

## 6. 原子 Skill（积木）vs 复合工作流（拼图）

拆解口诀：**一个人、一份输入、一份输出、拿掉前后文还能跑。**  
「整场何静」和「从下单到出证明」都是复合工作流，不要封成一个 Skill。

### 6.1 第一刀只要 6 块（审核侧）

| Skill | 干什么 | 输入 | 输出 |
|---|---|---|---|
| `bind-outbound-order` | 增值单绑到出库单 | VASC / OSF8V1848 | WO + 站点/仓 |
| `fetch-outbound-skus` | 拉商品清单 | WO | SKU / 商品编码 / IM 码 |
| `resolve-product-master` | 主数据 + IM 对不上时用商品编码补查 | SKU/IM | 分类、特性、失败项 |
| `check-ts-filing` | TS 备案有没有 | SKU | 是/否 |
| `site-destruction-capability` | 这个仓允许哪些销毁 | 站点 | 允许集合（非美去掉仓内） |
| `recommend-destruction-path` | 合规路径按成本排序，对比客户已选 | 站点能力 + 商品属性 + 已选类型 | pass / switch / reject + 推荐 |

后面再加、不要第一刀做：前台自动勾选最便宜项、价卡实时估价、欧洲法规细表、供应商出证流程。

### 6.2 Copilot 复合编排（审核 OSF8V1848）

`bind-outbound-order` → `fetch-outbound-skus` → `resolve-product-master`（失败走 IM 补查）→ `site-destruction-capability` → 若选 TS 则 `check-ts-filing` → `recommend-destruction-path` → 绿/橙/红停手。

会上还提到第二条复合流：客户在新版出库单前台选「销毁」时，按站点+属性过滤选项并高亮最低价。那是下单引导，不是内部审核 Copilot 第一刀。

## 7. 以后怎么从录像拆 Skill（可重复）

1. **原矿先入库，先不封装。** 只摘事实、如果…就…、例外坑、先做什么、点哪个页面、怎样算做对。
2. **过原子性检验。** 做不到就拆；「审完整张单」标成工作流。
3. **先对 Copilot 停手，再对前台。** 审核 Agent 要的是 pass/switch/reject；客户页要的是过滤选项。两套编排，一套积木。
4. **接现网时选对落点。** 规则闸（像 T1）/ 场景卡 / 只写 SOP。OSF8V1848 不是「其他服务需求」上的场景概述，**不要做成第 69 张场景卡**。
5. **用存量单回放。** 枕头误下专业销毁、英国仓、美国普货，三类至少各抽一批，和何静结论对拍。

本场还缺、写不进可上线 SKILL.md 的：TS 备案字段的准确入口、IM 码全量能否对上、欧洲法规细节、价卡实时接口、客户坚持要贵的专业销毁时运营兜底（默认：建议但不强改）。

## 8. 怎么接到 internal-review-copilot（三方案）

现网白名单不会扫到 OSF8V1848。要扩能力，必须单独开口。**未点名不要改 40、不要改 allowlist。**

| 方案 | 做法 | 优势 | 劣势 |
|---|---|---|---|
| **A. 独立原子闸（推荐）** | 像 T1：轮询识别 `OSF8V1848` 后走销毁规则闸，不进场景卡匹配。绿写询价 SOP；橙请销售改服务；红补信息 | 和现网「其他服务需求」隔离；符合「独立原子」身份；第一刀可只做美国普货「该不该换仓内/弃置」 | 要改 allowlist / 轮询过滤；出库单+商品主数据要新接口 |
| B. 做成一张新场景卡 | `status=supported`，走 L2.5 + 写 SOP | 复用现成 pipeline | 身份不对；会跟入库/库内概述码搅在一起；解决不了「该不该换服务」 |
| C. 另起一个销毁小 Agent | 完全独立轮询和飞书应用 | 零风险碰现网 | 两套值班、两套卡；现阶段过重 |

**第一刀建议（方案 A：原子路由 + 第二条 pipeline）：**

1. 只收 `OSF8V1848`，其它出库原子仍不碰。用服务码路由，不要改现网入库 `runPipeline`。  
2. 只自动判「普货专业销毁 + 美国站普货 → 建议仓内/弃置」和「非美不要推荐仓内」。  
3. 危废 / TS **不自动改判**，但细类、商品、备案结果必须写进 SOP 框的【审核参考摘要】，避免审核员再切出库单/商品页。  
4. SOP 文本框 = 摘要（系统事实 + 规则判断）+ 产品询价三步。LLM 只把 JSON 说成人话。  
5. 橙卡只 @ 销售/客服；**不自动改客户已选类型、不代点审核通过。**  
6. 现网入库/库内 pipeline 一行业务逻辑都不改。
