# 非标页内嵌智能引导

## 1. 模块定位

本模块是独立的“非标页内嵌智能引导”方案，面向万邑联创建增值单流程中的 Step 2 非标增值页面。

- 入口：在创建增值单 Step 2 的非标页内嵌一个 AI 指引框，让客户先用自然语言描述需求。
- 方案边界：只讨论“非标页内嵌 AI 指引框”这一条路径。
- 不与右侧侧栏方案混用。
- 不复用其他方案实现包。
- 本模块当前只维护本目录下的方案、评估、原型和评测材料。

## 2. 业务问题

客户进入非标增值页后，常见问题是：

- 不知道应该选择哪个非标服务项。
- 不知道要补充哪些信息才能让仓库理解并审核。
- 不知道 SOP 应该怎么写，容易写成口语化、缺字段、缺附件的描述。

当前方案通过 AI 在页面内引导客户描述需求，再基于当前页面候选服务、上下文和 SOP 模板判断路径，输出可用于页面字段的建议内容。

## 3. 核心分支

本模块按三类主分支推进，不把所有需求都强行导向 SOP 长追问。

| 分支 | 名称 | 处理方式 |
|------|------|----------|
| 2d | 标准增值推荐直选 | 客户已进入非标页，但标准增值可覆盖时，提示返回标准增值路径，不继续引导填写非标字段。 |
| 2a | 非标增值（免审）推荐直选 | 客户需求命中当前候选内具体非标服务项时，直接引导选择对应服务项，不走 SOP 长追问。 |
| 2b | 非标增值（特批）需求填写指引 | 无法命中具体服务项时，进入 SOP 模板匹配、结构化追问、客户确认、字段建议。 |

候选范围以当前页面和接口返回的候选服务为准，AI 不扩推候选外服务。

## 4. 本期能力

本期目标是把客户在非标页的表达、分流和字段补全先跑通。

- 页面内 AI 指引框。
- 自然语言需求理解。
- 当前候选服务内推荐，不扩推候选外服务。
- 客户确认后生成【需求背景说明】【需求描述】字段建议。
- 目标能力是一键填入原字段；降级方案是展示可复制字段建议。
- 附件要求提示，以及基础附件元数据轻量检查。
- 费用预估只占位，不实现。
- 视频 SOP 解析保留下期。

## 5. 输出与接口约束

结构化输出 schema 是评测与中间层接口强约束，不能只依赖大段自然语言。

- 客户可见文案放在 `displayText` / `customerMessage`。
- 结构化字段用于分流、页面动作、字段写入、附件提示、附件检查和评测。
- 非法 JSON、缺必填字段、候选外推荐等情况，应判为失败或进入兜底重试。

建议固定关注以下结构化字段：

- `route`
- `selectedVasc`
- `selectedService`
- `pageActions`
- `fieldSuggestions`
- `attachmentRequirements`
- `attachmentCheck`
- `displayText`
- `customerMessage`

## 6. 评测设计

首批评测集不少于 9 条，三类分支都要覆盖：

- 2d 标准增值推荐直选：至少 3 条。
- 2a 非标增值（免审）推荐直选：至少 3 条。
- 2b 非标增值（特批）需求填写指引：至少 3 条。

测试集来源优先级：

1. 优先从飞书历史群聊抽取候选样本。
2. 再从客服历史会话数据库补充候选样本。
3. 候选样本必须脱敏，标注 `needsEnrichment` / `evidenceGap`。
4. 经人工复核后，才能进入金标集。

附件 TOP3 问题必须从历史群聊抽取并确认，不得凭空定义。
