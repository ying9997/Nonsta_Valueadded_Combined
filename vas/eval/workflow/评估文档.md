# 评估文档

## 可行性

| 维度 | 评估 |
|---|---|
| 技术 | CSV 可本地解析；无需访问数据库或外网。 |
| 数据 | 可抽出候选，但不是完整多轮原始会话；必须标记证据缺口。 |
| 合规 | 脚本脱敏 URL、邮箱、手机号、长编号、SKU/单号形态；不输出负责人等人员字段。 |
| 业务 | 分桶为原型启发式，需人工复核后才能进入金标。 |

## 成功标准

| 节点 | 成功标准 | 自检方法 |
|---|---|---|
| 脚本 | 可从默认 CSV 生成 JSON/JSONL/报告 | 执行脚本返回统计 |
| Schema | 每条包含用户给定 schema 的核心字段 | JSON 解析并检查字段 |
| 禁止编造 | 空缺字段进入 `needsEnrichment/evidenceGap` | 抽样检查 |
| 分桶 | 三类 route 均有候选，或报告说明不足 | route 分布统计 |
| 附件 | 附件只输出候选信号和 `warning/not_checked` | attachmentCheck 分布 |

## 风险与缓解

- 风险：qa-gen 不是裸客服会话，多轮信息不足。
  - 缓解：`conversationHistory` 只放源 `question`，并写明缺少逐轮角色日志。
- 风险：关键词命中可能混入退货/出库非目标场景。
  - 缓解：保留 `sourceRef`、`category` 报告，人工复核筛除。
- 风险：附件 SOP 被误写成已支持规则。
  - 缓解：全部附件状态保持候选/待核验，不输出定版格式。

## 结论

通过。适合先产出原型候选集，再由业务人工复核和补充页面上下文。
