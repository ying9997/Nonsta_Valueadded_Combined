## 模块 1：产品定位与问题定义

### 1.1 产品概述

| 项目 | 说明 |
|------|------|
| 产品名称 | 库内增值 AI 指引助手 |
| 产品形态 | 嵌入万邑联 seller 端库内增值下单页面的 AI 侧边栏（复用在线咨询入口） |
| 核心价值 | 帮客户选对增值服务 + 生成规范 SOP + 一键填入表单，降低下单门槛和审核沟通成本 |
| 一句话定位 | **库内增值下单的 AI 填单助手——帮你选、帮你写、帮你填** |

### 1.2 场景锚定

| 要素 | 内容 |
|------|------|
| 目标人群 | 万邑联平台 B 端卖家（提交库内增值单的客户） |
| 触发情境 | 客户进入"新增库内增值单"页面，需要选择增值产品/服务并填写需求描述 |
| 当前替代方案 | 客户自己选下拉框 + 手写需求描述（常写错/写不全）→ 审核驳回 → 反复沟通 |
| 核心痛点 | 1) 不知道选哪个服务 2) 需求描述不规范导致审核多次驳回 3) 非标 SOP 不会写 |
| Agent 不可替代性 | 1) 客户表述口语化/模糊，规则引擎覆盖不了 2) 需要结合 SOP 知识库动态生成内容 3) 多步追问+确认才能确定需求 |

### 1.3 场景边界

```
本 Agent 负责 库内增值下单场景，覆盖 增值服务推荐、非标SOP生成、表单一键填入，
不负责 入库增值（暂停）、出库增值、库内异常处理流程、订单状态查询、物流跟踪。
当用户请求超出 库内增值下单 时，引导到在线客服通用对话。
```

### 1.4 成功标准

| 指标 | 目标 | 数据来源 |
|------|------|---------|
| AI 推荐采纳率 | ≥60%（一期） | Coze 日志：客户确认 vs 忽略 |
| 表单一次提交成功率提升 | 有 AI 组比对照组高 20%+ | 灰度对比（30% vs 70%） |
| 审核通过率提升 | AI SOP 通过率比人工写的高 15%+ | TOM 审核结果对比 |
| 客户下单耗时缩短 | ≥30% | 页面进入→提交时间差 |

### 1.5 明确不做

| 不做 | 原因 | 处理方式 |
|------|------|---------|
| 入库增值指引 | 入库异常重构未完成 | 暂停，重构后继续 |
| 自动提交订单 | 风险太高 | AI 填入，客户自己点提交 |
| 替代审核判断 | 一期不做自动审核 | SOP 回填审核端，人工最终把关 |
| 复杂附件内容理解 | 技术不成熟 | 只做附件提示，不解析内容 |

## 模块 2：意图体系与能力地图

### 2.1 核心意图

| 意图 ID | 名称 | 处理路径 | 风险等级 |
|---------|------|---------|---------|
| INT-01 | 标准库内增值推荐 | 识别意图→推荐服务→选中 select→完成 | 低 |
| INT-02 | 非标免审推荐 | 识别意图→推荐免审服务→选中→完成 | 低 |
| INT-03 | 非标特批 SOP 生成 | 识别意图→追问→匹配模板→生成 SOP→客户确认→填入表单 | 中 |
| INT-04 | 超出范围 | 识别不在增值范围内→引导到通用客服 | 无 |
| INT-05 | 放弃/结束 | 客户表示不需要→保存进度→结束 | 无 |

### 2.2 工具-意图映射

| 意图 | 触发的 Tool Call | 参数 |
|------|----------------|------|
| INT-01/02 | `vas_form_action` | actions: [select product, select service] |
| INT-03 | `vas_form_action` | actions: [select product, select service, fill background, fill description] |
| INT-04 | 无 tool call | 纯文本引导 |

### 2.3 兜底规则

| 失败类型 | 处理 |
|---------|------|
| 完全无法识别 | "抱歉我不太理解，您可以换个方式描述，或联系在线客服" |
| 部分理解 | 确认已理解部分 + 追问不确定部分 |
| 超出范围 | "这个问题不在增值下单范围内，建议联系在线客服" |
| 置信度低 | "您是想做XX吗？" + 等客户确认 |
| 连续 3 轮无法识别 | 自动引导转人工 |

### 2.4 置信度阈值

| 范围 | 行为 |
|------|------|
| ≥ 0.8 | 直接推荐 |
| 0.5~0.8 | 推荐但加"请确认" |
| < 0.5 | 不推荐，追问或转人工 |

## 模块 3：对话与交互设计

### 3.1 交互形态

- AI 容器：复用页面已有的在线咨询侧边栏（`#aiChatbotRoot`）
- 触发方式：页面加载后自动弹出侧栏（可设置偏好关闭）
- 气泡样式：线上客服风格（紫色渐变用户气泡 + 白色 AI 气泡）

### 3.2 对话状态机

```
[IDLE] → 页面加载 → [AI_GREETING]
  → 客户输入 → [INTENT_PARSING]
    → 置信度高 → [RECOMMENDING]
    → 置信度低 → [CLARIFYING] → 客户澄清 → [INTENT_PARSING]
    → 连续3轮失败 → [HUMAN_HANDOFF]
  → [RECOMMENDING]
    → 标准/免审 → [SELECTING] → Tool Call → [COMPLETED]
    → 非标特批 → [SOP_GENERATING]
  → [SOP_GENERATING]
    → 有模板匹配 → 展示 SOP → [CONFIRMING]
    → 无模板 → LLM 自由生成 → [CONFIRMING]（标注需人工审核）
  → [CONFIRMING]
    → 客户"确认" → [FILLING] → Tool Call → [COMPLETED]
    → 客户"修改" → 客户补充 → [SOP_GENERATING]
  → [COMPLETED] → "已填入，请确认后提交"
```

### 3.3 对话边界

| 场景 | 规则 |
|------|------|
| 客户关闭侧栏再打开 | 保留对话（复用 Coze conversation） |
| 客户说"算了不搞了" | "好的，如果后续有需要随时找我。" + 结束 |
| 连续无关内容 | 第 2 轮提示"我是增值下单助手"，第 3 轮引导转人工 |
| 最大追问轮数 | 初始 3 轮，上线后数据验证调整 |
| 重复追问防控 | 读取 chatHistoryRound(4-6) 避免重复问已回答的信息 |

## 模块 4：记忆、规划与推理策略

### 4.1 记忆分层

| 类型 | 机制 | 生命周期 |
|------|------|---------|
| 短期（会话内） | Coze `chatHistoryRound: 4-6` + `query_rewrite` | 单次会话 |
| 中期（任务内） | Expert 链 `inputContext/outputContext/sessionHandoff` | 单次请求处理链 |
| 长期（跨会话） | 一期不实现，预留对话日志存储接口 | 二期 |

### 4.2 推理策略

| 阶段 | 策略 |
|------|------|
| 意图识别 | 单步（classification node） |
| SOP 生成（有模板） | 单步（模板填充） |
| SOP 生成（无模板） | 多步 CoT（按 6 章结构逐步生成） |
| 表单填充 | 单步（结构化输出 → Tool Call） |

### 4.3 一期数据预留（为二期储备）

每次 AI 引导完成后，存储：
- 完整对话记录（input/output per turn）
- 最终推荐结果（product + service + SOP）
- 客户是否确认/修改
- 提交后审核结果（通过/驳回 + 原因）

## 模块 5：安全护栏与权限体系

### 5.1 输入防护

| 威胁 | 防护 |
|------|------|
| Prompt 注入 | system prompt 中声明不响应指令覆盖请求 |
| PII 泄露 | 不记录/不传输客户贴入的身份证等敏感信息 |
| 无关内容洪水 | 3 轮无关后结束对话 |

### 5.2 输出约束

| 约束 | 说明 |
|------|------|
| 不推荐超范围服务 | AI 只从系统事实 VASC list 中选择，不编造 |
| 不承诺审核结果 | "提交后审核人员会最终确认" |
| SOP 不编造仓库动作 | 有模板时按模板，无模板时标注"AI 生成，需审核" |
| 费用不随意承诺 | 费用预估标注"仅供参考，以正式报价为准" |

### 5.3 执行约束

| 约束 | 说明 |
|------|------|
| 不自动提交 | AI 只填入，提交按钮由客户自己点 |
| 一键填入需客户确认 SOP 后才触发 | 不跳过确认步骤 |
| Tool Call 失败不重复尝试超 2 次 | 2 次失败→降级提示手动填 |

## 模块 6：人机协作机制

### 6.1 介入触发

| 触发 | 条件 | 方式 |
|------|------|------|
| 用户主动 | 说"转人工" | 立即转 |
| 意图不确定 | 连续 3 轮无法确认 | 转人工 |
| 无模板 SOP | LLM 自由生成 | 客户确认后正常提交，审核端标注"AI生成-无模板" |
| 高频驳回客户 | 历史被驳回 ≥3 次 | 主动提示"建议联系客服" |

### 6.2 渐进式自治路线

| 阶段 | 人工审核比例 | Agent 能力 |
|------|------------|-----------|
| Phase 1（一期） | 100% 人工审核 | 推荐+生成 SOP+填入，审核人员最终把关 |
| Phase 2 | 50% 抽检 | 有模板的 SOP 自动审核通过 |
| Phase 3（二期） | 异常驱动 | AI 自动审核低风险 case |

### 6.3 无模板 SOP 的两条分支（待确认选用哪条）

| 分支 | 流程 | 优点 | 缺点 |
|------|------|------|------|
| A: 正常提交 | 客户确认→提交→审核端标注"无模板-需重点审核" | 不阻塞客户 | 可能审核驳回率高 |
| B: 拦截转人工 | AI 提示"建议联系客服确认"→转人工→人工辅助填写 | 减少驳回 | 阻塞客户流程 |

## 模块 7：质量评测与可观测性

### 7.1 评测集

| 类型 | 量级 | 来源 | 状态 |
|------|------|------|------|
| 金标集（理想态） | 15-30 条（每分支 5-10） | 人工构造 | 待库内数据就绪后构建 |
| 历史数据验证 | 几百条 | udesk + 群聊 | 有数据，待清洗 |
| 审计盘点专项 | 5 条候选 | P1 prompt 提取 | 执行中 |

### 7.2 Trace 数据模型

每次完整任务 = 一条 Trace：
```
Trace
├── Span: 意图识别（input/output/耗时/token）
├── Span: 知识库检索（query/results/匹配场景）
├── Span: SOP 生成（prompt/response/耗时）
├── Span: Tool Call（vas_form_action → 前端执行结果）
└── Span: 用户反馈（确认/修改/放弃）
```

### 7.3 监控指标

| 指标 | 告警阈值 | 来源 |
|------|---------|------|
| Tool Call 执行成功率 | < 90% | 前端日志上报 |
| AI 推荐被忽略率 | > 50% | Coze 对话日志 |
| 对话超 5 轮未完成率 | > 30% | Coze 会话统计 |
| 审核驳回率（AI SOP） | > 30% | TOM 审核结果 |

## 模块 8：降级容错与运维机制

### 8.1 降级策略

| 故障 | 一级降级 | 二级降级 |
|------|---------|---------|
| AI 服务不可用（Coze 挂） | 侧栏显示"AI 暂时不可用，请手动填写" | 页面正常使用不阻塞 |
| LLM 响应超时（>15s） | 显示"正在思考..." → 超时提示重试 | 降级为"手动填写" |
| 结构化输出解析失败 | 重试 1 次 | 降级为纯文字建议（不自动填入） |
| Tool Call 执行失败 | 提示"自动填入失败，请手动复制" | 展示内容供手动复制 |

### 8.2 成本熔断

| 项 | 阈值 | 行为 |
|----|------|------|
| 单次 Trace token | 配置项（默认 8K） | 自动终止+降级 |
| 单用户日调用次数 | 20 次 | 限流提示 |

## 模块 9：上线策略与迭代闭环

### 9.1 灰度策略

| 阶段 | 范围 | 能力 | 审核 |
|------|------|------|------|
| 内测 | 内部 10 人 | 全功能 | 100% 人工审核 |
| 灰度 | 客户编码尾号 369（30% 流量） | 全功能 | 100% 人工审核 |
| 全量 | 全部客户 | 全功能 | 抽检 |

### 9.2 成功指标对比方案

灰度期间 30%（有 AI）vs 70%（无 AI）对比：
- 一次提交成功率
- 审核通过率
- 下单耗时
- 客户主动使用率（非被动弹出后立即关闭）

### 9.3 反馈闭环

```
审核驳回 → 记录结构化驳回原因 → 定期导出 → 更新 prompt / 知识库
  需要后端研发配合：TOM 审核驳回时存储原因字段
  Coze 不自动支持回传，需人工定期 review
```

### 9.4 迭代节奏

| 周期 | 活动 |
|------|------|
| 日 | 标记低置信度对话 → 人工审核 |
| 周 | Top10 失败场景分析 → 优化 prompt |
| 月 | 评估指标趋势 → 调整能力边界 |
| 季 | 金标集更新 → 策略校准 |
