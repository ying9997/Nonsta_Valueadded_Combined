# 方案文档 - 非标页内嵌智能引导

> 日期：2026-07-29  
> 模块：`module_非标页内嵌智能引导/`  
> 方案定位：方案乙，包含标准页 AI 下单指引弹窗前置模块和非标页内嵌智能引导主模块。  
> 本次范围：只做方案设计与评估口径更新，不改代码、不改其他方案。

## 1. 目标与非目标

### 1.1 目标

在万邑联创建增值单链路中增加智能引导能力：前置模块在标准增值推荐页触发 AI 下单指引弹窗，判断客户真实需求是否可由标准增值覆盖；主模块在 Step 2 非标页面内嵌智能引导输入框，客户可直接自然描述“希望仓库做什么”，AI 自动读取异常单上下文、`systemScopedVascList` / `listAllVasc` 候选、页面当前可选非标服务项和 SOP 模板库，判断并引导客户走正确路径。

三类核心分支：

| 分支 | 名称 | 判定 | 引导结果 |
|------|------|------|----------|
| 2d | 标准增值纠偏 | 客户已进入非标页，但需求可由候选内标准增值覆盖 | 建议客户返回标准增值路径，选择候选内对应标准增值；不继续引导填写非标字段 |
| 2a | 命名/具体非标服务直选 | 客户需求命中当前候选内具体非标服务项，且不是“入库/库内/出库其他服务需求” | 直接引导选择对应增值产品和服务项；不进入 SOP 长追问 |
| 2b | 其他服务需求 + SOP | 客户需求无法命中具体非标服务项，但可走“入库/库内/出库其他服务需求” | 进入 SOP 模板匹配、结构化追问、客户确认、字段建议流程 |

### 1.2 非目标

- 不承诺审核通过：客户确认只代表确认处理方式和已提供信息，不等于审核通过。
- 不做免审、不绕过报价和审核流程。
- 不对客输出仓内不可公开的完整操作细节。
- 不推荐 `systemScopedVascList` 之外的产品或服务项。
- 不宣称已枚举全部非标服务项。
- 不凭空列举类似 `包裹串仓异常调拨` 的服务项；除该示例外，其他具体服务项必须来自 `listAllVasc` / `getVascInfo` 返回清单的实地枚举。
- 本期不实现费用预估，只预留“费用预估待接入”。
- 本期不实现视频 SOP 解析；该能力保留下期迭代，不纳入本期验收。
- 本期不做复杂附件内容理解：不做视频内容解析，不做复杂图片识别，不自动上传附件，不强制拦截提交。

### 1.3 实现边界

本方案包含前置模块（标准页 AI 下单指引弹窗）和主模块（非标页内嵌智能引导）。主模块可独立运行：客户直接进入非标页时触发 2d 标准增值纠偏；前置模块上线后，经弹窗引流到非标页的流量跳过 2d。两个模块无上线顺序依赖。后续若做 Coze 智能体，应独立建包或独立智能体，不复用或污染其他方案包。

## 2.5 前置模块：标准页 AI 下单指引弹窗

### 2.5.1 定位与入口

标准页 AI 下单指引弹窗是方案乙的前置模块，在标准增值推荐页面触发，不是独立方案。入口放在标准页 `demo-vas-A-v2.html` 中第一题标题旁：

`<div class="q-title">这批异常货物，你希望怎么处理？</div>`

页面在该 `q-title` 旁内嵌一个小图标，客户点击后弹出“AI 下单指引”窗口。该窗口服务于标准页到非标页的智能分流，主模块仍可在客户不经过弹窗、直接进入非标页时独立运行。

### 2.5.2 弹窗 scope 与行为

弹窗 scope 是全量意图判定，覆盖标准增值和非标增值，不只是现有决策树卡片覆盖不了的补充。

弹窗行为：

1. AI 主动提问客户真实需求，结合异常单上下文和 `systemScopedVascList` 判断客户要达成的处理目标。
2. 判定能走标准增值时，在弹窗内给出操作路径参考，例如应选哪个处理方式、哪个标准增值产品；AI 只提供参考，不代替客户操作。
3. 判定不能走标准增值时，引导客户点击【我要提非标增值】按钮；点击后以站内新 tab 跳转到非标页，tab 层级与“创建增值订单”tab 同级，不打开新浏览器 tab。

### 2.5.3 输出给非标页的上下文

弹窗跳转非标页时，可向主模块传入 `popupContext`。该上下文是可选依赖；缺失时不阻塞非标页主模块独立运行。

```json
{
  "conversationId": "",
  "customerInput": "",
  "routeDecision": "nonstandard",
  "systemScopedVascList": [],
  "exceptionContext": {},
  "dialogHistory": []
}
```

`routeDecision = "nonstandard"` 表示弹窗已完成标准/非标判定，客户诉求不能由标准增值覆盖，进入非标页后主模块可跳过 2d 标准增值纠偏，直接进入 2a / 2b 判定。

### 2.5.4 与现有决策树卡片的关系

标准页现有决策树卡片是系统“处理方式”字段，用于表达上架、销毁、自提、拍照等处理方式；每个处理方式下可能同时包含标准增值和非标增值。

AI 弹窗与现有决策树卡片不是替代关系，也不是互补关系。弹窗的作用是通过理解客户真实需求，判断标准增值是否覆盖客户目标；卡片仍是页面原有处理方式选择入口，AI 不代替客户点击卡片或提交表单。

## 3. 端到端流程

| 步骤 | 客户操作 | AI 判定/操作 | 页面输出 |
|------|----------|--------------|----------|
| 0 | 客户从标准页弹窗点击【我要提非标增值】跳转，或直接进入非标页 | 检查 `popupContext` 是否存在 | 有 `popupContext.routeDecision = "nonstandard"`：跳过 2d，直接显示基于已有对话的引导并进入 2a / 2b；无 `popupContext`：显示自然语言输入态，后续正常执行 2d |
| 1 | 客户进入非标 Step 2 页面 | 页面注入异常单上下文、候选产品/服务项、当前页面已选值；如有弹窗上下文，同时注入 `popupContext` | 智能引导输入框显示自然语言输入态或基于弹窗已有对话的承接态 |
| 2 | 客户描述“希望仓库做什么”，或沿用 `popupContext.customerInput` | 若无有效 `popupContext`，AI 先判断是否属于 2d 标准增值纠偏；若有 `popupContext.routeDecision = "nonstandard"`，跳过 2d | 如命中 2d，提示返回标准增值路径并给出候选内标准增值名称；跳过 2d 时不重复标准纠偏 |
| 3 | 若不触发 2d | AI 判断是否命中当前候选内具体非标服务项 | 如命中 2a，输出应选择的增值产品和服务项，不进入 SOP 追问 |
| 4 | 若不命中 2a | AI 判断是否可走“其他服务需求” | 如可走 2b，先匹配 SOP 模板 |
| 5a | SOP 模板检索匹配 | 本期优先采用 prompt 内嵌 SOP 模板库全文；若模板库超出 token 上限，改为中间层预过滤后注入匹配候选 | 输出 `matchedTemplateId` / `matchedTitle` / `evidence`；成功标准：能说明是否命中可复用模板及证据 |
| 5b | 客户确认摘要生成 | LLM 基于命中模板、客户描述、异常上下文和必要补充信息生成确认摘要；如缺少生成摘要所需的最小信息，先追问后再生成 | 输出追问清单或确认摘要；确认摘要必须包含“确认≠审核通过”句式 |
| 6 | 2b 无可复用 SOP 模板 | AI 不编造 SOP，按 SOP 模板结构追问 | 输出结构化追问清单 |
| 7 | 客户确认 SOP 摘要 | AI 生成可写入原字段的建议，并生成操作说明附件要求 | 输出 `需求背景说明`、`需求描述`、`操作说明附件要求`，并提供填入按钮或可复制文本 |
| 7a | 客户上传附件或页面已有附件 | 如前端传入附件基础元数据，AI 做轻量附件检查 | 输出建议补充/更换附件提示；不承诺审核结果，不拦截提交 |
| 8 | 客户填入/粘贴字段并提交 | 原页面字段仍为提交源 | 系统按原流程保存草稿、提交、审核、报价 |

## 4. 决策树

```text
输入 =
  客户自然语言
  + 页面上下文 / 异常单上下文
  + systemScopedVascList / listAllVasc 候选
  + 当前页面可选非标服务项
  + 当前页面已选值
  + 多轮对话历史
  + SOP 模板库

0. 检查入口上下文
   - 若 `popupContext.routeDecision` 存在且等于 `"nonstandard"`：
     跳过 2d 标准增值纠偏，直接进入步骤 2（2a 判定）
   - 若 `popupContext` 缺失，或未携带有效 `routeDecision`：
     执行步骤 1（2d 标准增值纠偏）

1. 2d 标准增值纠偏（条件触发）
   - 字段级判定条件：`systemScopedVascList` 中 `type = "标准"` 的产品即为候选内标准增值。
   - 若需求可由候选内标准增值覆盖：
     route = 2d_standard_redirect
     输出候选内标准增值名称
     建议客户返回标准增值路径
     不继续引导填写非标字段
   - 否则进入 2。

2. 2a 命名/具体非标服务直选
   - 若需求命中当前候选内具体非标服务项，且该服务项不是“入库/库内/出库其他服务需求”：
     route = 2a_named_nonstandard_direct
     输出应选择的增值产品和服务项
     不进入 SOP 长追问
   - 否则进入 3。

3. 2b 其他服务需求 + SOP
   - 若候选内存在“入库/库内/出库其他服务需求”：
     route = 2b_other_service_sop
     先匹配历史 SOP 模板
   - 若不存在：
     输出候选内高适配度建议或转人工，不扩推候选外服务项。

4. 2b SOP 处理
   - Step 5a SOP 模板检索匹配：本期优先采用 prompt 内嵌 SOP 模板库全文，输出 `matchedTemplateId`、`matchedTitle`、`evidence`；成功标准是能说明是否命中可复用模板及证据。若模板库超出 token 上限，改为中间层预过滤后注入匹配候选。
   - Step 5b 客户确认摘要生成：LLM 基于命中模板、客户描述、异常上下文和必要补充信息输出确认摘要；如缺少生成摘要所需的最小信息，先输出追问清单，补齐后再生成摘要。成功标准是必须包含“确认≠审核通过”句式。
   - 无可复用历史 SOP 模板：
     不编造 SOP；
     按《非标增值服务SOP模板 及 填写示例.md》结构追问：
       场景概述、客户/业务单据/SKU、需求背景、操作目的、适用范围、
       操作步骤（操作说明/注意事项/工具材料）、关键输出、异常处理、附件要求。

5. 客户确认后
   - 生成原页面字段建议：
     需求背景说明
     需求描述
     操作说明附件要求
   - 如前端传入附件基础元数据，做轻量附件检查：
     是否已上传附件
     文件名/备注中是否包含必要单号或 SKU
     附件类型是否与 SOP 要求匹配
     是否存在明显不匹配提示
   - 输出费用占位：
     费用预估待接入。
```

## 5. 前端交互能力

### 5.1 目标态

客户确认 SOP 摘要后，AI 生成可写入原字段的建议，页面提供按钮：

- 【填入需求背景说明】
- 【填入需求描述】

非标补全前置链路必须按 Step 5a/5b 执行：先完成 SOP 模板检索匹配，输出 `matchedTemplateId`、`matchedTitle`、`evidence`；再由 LLM 基于模板、客户描述和异常上下文生成包含“确认≠审核通过”句式的客户确认摘要。如缺少生成摘要所需的最小信息，先追问补齐后再生成摘要。

附件字段不做静默上传。AI 生成 `操作说明附件要求`，前端在【操作说明附件】上传控件旁展示该提示。

### 5.1.1 本期轻量附件指引

本期附件能力为“附件要求提示 + 基础元数据轻量检查”：

- AI 在生成 SOP 摘要和字段建议时，同时生成 `操作说明附件要求`。
- 前端在【操作说明附件】上传控件旁展示该提示。
- 如果前端能读取附件上传状态和基础元数据，可把附件列表传给 agent 做轻量检查。
- 本期不做视频内容解析，不做复杂图片识别，不做自动上传附件，不做强制拦截提交。

本期可支持的轻量附件检查：

| 检查项 | 示例 | 输出方式 |
|--------|------|----------|
| 是否已上传附件 | SOP 要求标签文件，但附件列表为空 | 提示“建议补充附件” |
| 文件名/备注是否包含必要单号或 SKU | 文件名或备注缺少新入库单号 / SKU | 提示“建议在附件名或备注补充单号/SKU” |
| 附件类型是否与 SOP 要求匹配 | SOP 要求标签文件、照片、操作说明文件 | 提示“建议上传对应类型附件” |
| 是否明显不匹配 | SOP 要求标签文件，但只上传了无关截图 | 提示“建议补充/更换附件” |

检查结果只做提示，不做强制拦截。输出应告诉客户“建议补充/更换附件”，不得承诺审核结果。

本期建议前端/中间层传附件基础信息，不直接传完整文件内容：

```json
{
  "fileId": "",
  "fileToken": "",
  "fileName": "",
  "fileType": "",
  "fileSize": 0,
  "uploadStatus": "",
  "userRemark": "",
  "relatedOrderNo": "",
  "relatedSku": ""
}
```

如需读取真实文件内容、图片内容或视频内容，应作为下期能力，依赖文件签名 URL、OCR、图片理解、视频转写/抽帧等服务。

### 5.2 文案定位

文案定位必须保留，用于说明：

- 客户应该选择哪个增值产品/服务项。
- 为什么这样选。
- 字段内容将写到哪里。

定位粒度到页面区域和字段名即可。一期不强制自动滚动和高亮。

示例文案：

“以下内容将填入页面【需求背景说明】字段，您也可以点击上方按钮一键填入：”

### 5.3 降级态

如果前端排期无法实现按钮，则先提供文字指引和可复制字段内容，由客户手动粘贴到：

- `需求背景说明`
- `需求描述`

### 5.4 标注稿与增强能力

- HTML 标注稿用于产品/前端对齐页面位置，不等同于线上能力。
- 滚动和高亮作为增强能力，不作为一期必须项。

## 6. 输出结构

结构化输出 schema 是评测与中间层接口的强约束：

- Agent 内部/接口返回必须包含固定 JSON 字段。
- 固定 JSON 用于 route 判断、页面落点、字段填入、附件要求提示、轻量附件检查、状态存储、多模型评测。
- 客户可见文案可以自由生成，但必须放在 `displayText` 字段中。
- 客户可见文案不得替代结构化字段。
- 若模型输出不是合法 JSON，中间层应判为失败或进入兜底重试。

```json
{
  "route": "2d_standard_redirect | 2a_named_nonstandard_direct | 2b_other_service_sop",
  "selectedVasc": {},
  "selectedService": {},
  "pageActions": [],
  "missingFields": [],
  "sopTemplateMatched": true,
  "confirmationSummary": "",
  "fieldSuggestions": {
    "background": "",
    "description": ""
  },
  "attachmentRequirements": [],
  "attachmentCheck": {
    "status": "not_checked | ok | warning | missing",
    "issues": [],
    "suggestions": []
  },
  "feeEstimatePlaceholder": "费用预估待接入",
  "displayText": "",
  "forbiddenViolations": []
}
```

各分支要求：

| 分支 | route | selectedVasc / selectedService | confirmationSummary | fieldSuggestions |
|------|-------|--------------------------------|---------------------|------------------|
| 2d | `2d_standard_redirect` | 填候选内标准增值；服务项可空 | 空 | 空，不生成非标字段建议 |
| 2a | `2a_named_nonstandard_direct` | 填候选内具体非标服务项 | 空或短确认 | 只补该服务项必需字段，不生成 SOP 长文 |
| 2b | `2b_other_service_sop` | 填候选内其他服务需求 | 客户确认用 SOP 摘要 | 客户确认后生成 |

## 7. 费用预估占位

当前阶段不实现费用预估。Agent 输出中保留：

```json
{
  "feeEstimatePlaceholder": "费用预估待接入"
}
```

接入时机：待非标指引流程跑通后，再接入现有计费/报价链路。当前不得自行估价、承诺报价或替代审核报价。

## 8. 视频 SOP 解析能力（下期迭代）

视频 SOP 解析能力保留，但不纳入本期验收。

下期方向：

1. 客户上传操作视频。
2. 前端/中间层提供视频 `fileToken` 或签名 URL。
3. 中间层完成视频转写、抽帧、关键动作描述。
4. Agent 将视频内容抽取为《非标增值服务 SOP 模板》结构。
5. 客户确认后，再生成 `需求背景说明`、`需求描述`、`操作说明附件要求`。

下期应单独建立 `video-sop-extraction` 测试集，包含：

- 视频或转写文本。
- 期望 SOP 结构。
- 操作步骤。
- 注意事项。
- 工具/材料。
- 关键输出。
- 异常处理。
- 附件要求。

## 10. 评测设计

### 10.1 评测集覆盖

评测集必须覆盖三类核心分支：

| 分支 | 最小用例 | 验证重点 |
|------|----------|----------|
| 2d 标准增值纠偏 | 至少 3 条 | 返回标准增值路径，不生成非标字段建议 |
| 2a 命名/具体非标服务直选 | 至少 3 条 | 输出候选内增值产品和服务项，不进入 SOP 追问 |
| 2b 其他服务需求 + SOP | 至少 3 条 | 先模板匹配；有模板最小追问，无模板结构化追问；确认后生成字段建议 |

首批评测集规模：三类分支每类至少 3 条，总计不少于 9 条。每类 3 条应覆盖：

- 明确命中。
- 信息缺失 / 需追问。
- 边界 / 易混淆场景。

附件轻量检查也进入评测设计：

- 至少补充 3 条附件问题候选用例。
- 附件 TOP3 问题必须先从飞书历史群聊抽取并人工确认。
- 示例问题类型可以包括单号写错、标签文件缺失、附件与需求不匹配，但这些只是待调研方向，不得直接断言为 TOP3。
- 本期 agent 只针对已确认 TOP3 做轻量识别和提示。
- 未确认的问题不得凭空加入规则。

### 10.2 评测集构建方案

#### 10.2.1 评测集来源

评测集来源分为两类：

| 来源 | 抽取方式 | 定位 | 重点抽取 |
|------|----------|------|----------|
| 来源 A：飞书历史群聊 | 由飞书 Aily 按提示词，从审核同事与客服/销售的多轮讨论中抽取非标增值测试样本 | 内部审核与业务口径真源 | 业务判断口径、审核关注点、所需字段、是否可复用 SOP、最终服务项/处理方式 |
| 来源 B：客服历史会话数据库 | 由本地 Cursor/AI IDE 或离线脚本，从线上客服与客户的真实沟通记录中抽取非标增值测试样本 | 客户真实表达与多轮沟通真源 | 客户自然语言需求、多轮追问、客户补充信息、最终确认内容 |

两类来源都只能生成候选测试集。候选样本必须经过脱敏和人工复核后，才能进入金标评测集。

候选集来源优先级：

1. 第一阶段优先抽飞书历史群聊。
2. 第二阶段再抽客服历史会话数据库。

附件问题调研：第一阶段从飞书历史群聊中抽取非标增值附件提交的 TOP3 高频问题。示例问题类型可以是单号写错、标签文件缺失、附件与需求不匹配，但必须标注“需从群聊实地抽取后确认”，不得在抽取前写成已支持规则。

#### 10.2.2 候选用例扩展字段

每条候选用例在原测试字段基础上增加：

| 字段 | 说明 |
|------|------|
| `sourceType` | `feishu_group_chat` 或 `customer_service_db` |
| `sourceRef` | 原始材料引用，如群聊链接、消息时间范围、客服会话 ID、数据库记录 ID |
| `evidenceSnippets` | 支撑该用例的原文片段，脱敏后保留 |
| `needsEnrichment` | 原始材料没有、但可通过页面上下文或接口补齐的字段 |
| `evidenceGap` | 无法从材料确定的字段，不得编造 |
| `humanReviewStatus` | `pending` / `approved` / `rejected` |

#### 10.2.3 缺字段处理规则

- 能从原始材料抽取的字段直接填。
- 原始材料没有、但可通过页面上下文或接口补齐的，写入 `needsEnrichment`。
- 无法确定的，写入 `evidenceGap`，不得编造。
- `systemScopedVascList` / `listAllVasc` 候选、`selectedService`、费用、审核结论不得凭空补。
- 若缺少关键候选信息，该用例只能进入候选集，不能直接作为金标集。

### 10.4 评分维度

| 维度 | 判定 |
|------|------|
| 路由是否正确 | `route` 是否等于期望分支 |
| 是否只推荐候选内产品/服务项 | `selectedVasc`、`selectedService` 是否存在于候选 |
| 是否正确区分 2a 与 2b | 具体非标服务项不得进入 SOP 长追问；其他服务需求不得冒充命名服务项 |
| 2d 是否正确返回标准增值路径 | 不继续引导填写非标字段 |
| 2b 是否先模板匹配再追问 | 有模板最小追问；无模板结构化追问 |
| 是否避免编造 SOP | 无模板时不得输出伪历史 SOP |
| 是否包含“客户确认不等于审核通过” | 2b 确认摘要必须包含 |
| 是否生成可填入原字段的建议 | 仅客户确认后生成 `background` / `description` |
| 是否输出附件要求提示 | `attachmentRequirements` 是否与 SOP 摘要/字段建议一致 |
| 是否正确执行轻量附件检查 | `attachmentCheck` 是否只基于附件元数据输出提示，不强制拦截 |
| 是否触发禁止输出 | 检查 `forbiddenViolations` 和人工复核 |

2. 固定输出 JSON schema。

4. 记录每个模型的：
   - route accuracy
   - 候选内推荐准确率
   - SOP 字段完整率
   - 违规输出率
   - 人工复核备注

## 11. 风险与回退

| 风险 | 表现 | 缓解 | 回退 |
|------|------|------|------|
| AI 扩推圈外产品 | 推荐不在候选内的产品或服务项 | 强制候选内校验 | 转人工或提示无法确认 |
| 2a/2b 混淆 | 具体非标服务项被拉进 SOP 长追问，或其他服务需求被冒充为命名服务项 | 固定 2d -> 2a -> 2b 决策顺序 | 输出候选建议，要求人工确认 |
| 2d 纠偏失败 | 标准增值可覆盖却继续引导填非标字段 | 评测集加入 2d 回归用例 | 输出返回标准路径的纠偏提示 |
| 无模板时编造 SOP | AI 将泛化经验当成历史 SOP | 无模板时只按 SOP 模板结构追问 | 转人工或保留客户原始描述 |
| 客户误解审核结果 | 把 SOP 摘要理解为审核通过 | 固定写“客户确认不等于审核通过” | 不输出确认摘要，只输出缺失项 |
| 附件检查越界 | 将轻量附件提示写成强制拦截或审核承诺 | 只输出建议补充/更换附件，不拦截提交 | 降级为附件要求文字提示 |
| 附件 TOP3 未确认 | 未调研就把示例问题写成规则 | 先从飞书历史群聊抽取并人工确认 | 暂作为候选评测项 |
| 前端按钮未排期 | 无法一键填入原字段 | 提供可复制字段内容 | 客户手动粘贴 |
| 费用误导 | AI 自行估价 | 固定输出“费用预估待接入” | 不展示费用内容 |

4. 评测集构建方案落地：第一阶段优先抽飞书历史群聊，第二阶段再抽客服历史会话数据库，完成脱敏、分桶、补齐标记和人工复核流程设计。
5. 结构化输出 JSON schema：作为评测与中间层接口强约束，固定 route、候选、页面动作、SOP、字段建议、附件要求、轻量附件检查、费用占位、展示文案、违规项。
6. 中间层接口契约草案：与 HTML 标注原型并行产出、互不阻塞，HTML 可先使用占位字段。草案需包含：请求体 schema 字段名（`conversationId`、`eventNo`、`exceptionContext`、`pageContext`、`systemScopedVascList`、`currentPageValues`、`customerInput`、`conversationHistory`、`attachmentMetadata`、`confirmedSummaryVersion`）；调用时序（页面采集上下文 -> 中间层注入候选和 SOP 检索上下文 -> Agent 返回结构化 JSON -> 前端展示、写入或继续多轮）；会话生命周期（进入非标页或首次输入时开始，多轮携带 `conversationId` 和历史上下文，客户确认/提交/离页/超时后结束）。
7. 基础评测表：记录 route accuracy、候选内推荐准确率、SOP 字段完整率、违规输出率、人工复核备注。
