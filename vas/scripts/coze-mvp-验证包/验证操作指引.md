# Coze SDK 联动验证操作指引

## 目标

验证 Coze Bot 能稳定输出纯 JSON，确认后续 Web SDK 的 `afterMessageReceivedFinish` 回调能正确接收和解析。

## 步骤（10 分钟）

### Step 1：创建 Bot（3 分钟）

1. 打开 https://www.coze.cn（或你的 Coze 工作空间）
2. 点击"创建 Bot"
3. 名称填：`VAS指引-SDK联动验证`
4. 人设/提示词：复制粘贴 `system-prompt.md` 的全部内容
5. 模型选择：`doubao-pro-32k`（或任意可用模型）
6. 温度设为 `0`（确保输出稳定）
7. 保存

### Step 2：预览测试（5 分钟）

在 Coze 的"预览调试"面板中，依次输入以下测试用例：

| 输入 | 期望返回的 route | 验证点 |
|------|-----------------|--------|
| "帮我换个包装继续上架" | `2d_standard_redirect` | JSON 格式正确，selectedProduct = "原单上架" |
| "这批货我要自提拿回来" | `2a_named_nonstandard_direct` | JSON 格式正确，selectedProduct = "上架前自提" |
| "需要按条码对应关系换标后上架" | `2b_other_service_sop` | JSON 格式正确，pageAction.type = "select_card_and_open_window2" |
| "帮我处理一下" | `need_more_info` | JSON 格式正确，selectedProduct = null |

### Step 3：验证判定标准

每条测试检查：
- [ ] 返回的是纯 JSON（没有 markdown 代码块 ``` 包裹）
- [ ] 能被 `JSON.parse()` 成功解析（没有多余文字）
- [ ] route 值和期望一致
- [ ] customerMessage 有内容
- [ ] pageAction 结构正确

### Step 4：记录结果

| 测试用例 | 是否纯 JSON | route 正确 | 备注 |
|---------|------------|-----------|------|
| 换包装上架 | ✅/❌ | ✅/❌ | |
| 自提 | ✅/❌ | ✅/❌ | |
| 条码换标 | ✅/❌ | ✅/❌ | |

## 常见问题

### Bot 返回了 ```json ... ``` 包裹的文本

在 prompt 最后再加一行强调：
```
再次强调：直接输出 JSON 文本，不要使用 markdown 代码块（```）包裹。你的回复应该以 { 开头，以 } 结尾。
```

### Bot 在 JSON 前后加了说明文字

在 prompt 中加：
```
你的回复中不能包含任何非 JSON 内容。整个回复就是一个 JSON 对象，没有前缀没有后缀。
```

### 验证全部通过后

表示 Coze Bot 能稳定输出结构化 JSON → Web SDK 的 `afterMessageReceivedFinish` 回调拿到的 `props.message.content` 就是这个 JSON string → 前端 `JSON.parse()` 后即可操作 DOM。

**MVP 验证通过 = Coze 方案技术可行性确认。**
