## 2. 实体关联链路

```
WI（businessNo）──parent──► EB（businessNo, eventCode）
     │                              │
     │ businessOrderNo              │ linkedVascNo（post_vas）
     ▼                              ▼
VASC（orderNo）◄──childBusinessOrders──┘
     │
     ├── getVasList ──► 原子服务（serviceCode + serviceSequence, status=CO）
     ├── getEventOrder4VaAtom ──► EB + eventCode + eventFiles
     ├── getVaAtomDetails ──► businessOrder.businessNo = EB
     └── queryRelatedVaOrdersPage ──► WI 行 + EB 行
```

| 关联 | 字段 A | 字段 B | 档位 |
|------|--------|--------|------|
| WI → EB | `EB.parentBusinessNo` | `WI.businessNo` | 两档 |
| WI → VASC | `VASC.businessOrderNo` | `WI.businessNo` | post_vas |
| EB → VASC | `EB.linkedVascNo` | `VASC.orderNo` | post_vas |
| VASC → EB（结构） | `VASC.childBusinessOrders[].businessNo` | `EB.businessNo` | post_vas |
| 原子 → EB（运行时） | `getEventOrder4VaAtom.eventNo` | `EB.businessNo` | post_vas |
| 原子 → PMS | `getEventOrder4VaAtom.eventCode` | PMS `eventCode` | 两档 |
| 原子 → PMS 服务定义 | `getVasList.serviceCode` | PMS VAS `eventCode` | post_vas |

### 4.2 pre_vas 档位 — 验收清单

**查询条件**

| 步骤 | 入口 | 查询条件 |
|------|------|----------|
| 1 | 异常单列表 | 异常单号 = `{EB.businessNo}` 或 入库单号 = `{WI.businessNo}` |
| 2 | 异常单详情 | 打开 `{EB.businessNo}` |
| 3 | PMS 主数据 | `eventCode` = 该 TC 的 PMS 编码 |

**成功标准**

| # | 检查项 | 通过条件 |
|---|--------|----------|
| 1 | EB 存在 | 列表/详情能查到 `{EB.businessNo}` |
| 2 | 关联 WI | 详情显示父单 `{WI.businessNo}`，类型为入库单 |
| 3 | 异常类型 | `eventCode` = TC 规定值；`eventName` 与上表一致 |
| 4 | 异常状态 | `statusDesc` = **待客户处理** |
| 5 | 无增值单 | `linkedVascNo` 为空；该 EB 下**无**已完成 VASC |
| 6 | 仓库实拍 | `eventFiles` ≥ 1 张，图片可预览 |
| 7 | AI 推荐（核心） | 用户消息：「我的入库单 {wi_no} 有个异常 {eb_no}，仓库反馈「{场景名}」，应该怎么处理？」→ AI 应答中**推荐的原子服务 serviceCode** 须包含该 TC 的推荐列表（见 P0 总览表），且**不得**推荐 `must_not` 分支（如 B01E02 知悉类） |
| 8 | PMS 旁证 | `pms.PlanEventService_queryPlanEventPage` 能查到对应 `eventCode`，`eventAttr` = 操作增值类 |

### 4.3 post_vas 档位 — 验收清单

**查询条件**

| 步骤 | 入口 | 查询条件 |
|------|------|----------|
| 1 | 增值订单列表 | `orderNo` = `{VASC.orderNo}` |
| 2 | 增值订单详情 | 打开 `{VASC.orderNo}` |
| 3 | 异常单列表 | `EB.businessNo` = 该 TC 的 EB |
| 4 | 接口验收 | 见 4.4（可用 `query_vas_order.py` 脚本） |

**成功标准**

| # | 检查项 | 通过条件 |
|---|--------|----------|
| 1 | VASC 列表 | `pageQuery` 能查到；`statusDesc` = **已完成**；`vaSource` = UNUSUAL |
| 2 | 套餐产品 | `vasc.productCode` = 该 TC 指定套餐（见 P0 文档） |
| 3 | 关联 WI | `businessOrderNo` = `{WI.businessNo}` |
| 4 | 原子服务 | `getVasList` 返回该 TC 全部 `serviceCode`，每条 `statusDesc` = **已处理** |
| 5 | 属性完整 | 有 `vaAtomAttrs` 的服务，必填属性均已填（值可与 3.5 表一致） |
| 6 | EB 关联 | `getEventOrder4VaAtom`：`eventNo` = `{EB.businessNo}`，`eventCode` = PMS 编码，`eventFiles` 非空 |
| 7 | 商品明细 | `getVaAtomDetails`：`businessOrder.businessNo` = `{EB.businessNo}`，`businessType` = UNUSUAL |
| 8 | 关联订单页 | `queryRelatedVaOrdersPage` 至少 2 行：WI 入库订单行 + EB 异常订单行 |
| 9 | EB 状态 | 异常单详情：`statusDesc` = **已关闭**；`linkedVascNo` = `{VASC.orderNo}` |
| 10 | AI 追问（可选） | 「我的增值单 {vasc_no} 处理得怎么样了？入库单 {wi_no} 上的异常 {eb_no} 是否已经处理完？」→ AI 能正确引用已完成状态 |
