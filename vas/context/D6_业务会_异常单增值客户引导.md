# 异常单增值客户引导 — 业务会方案（修订版）

> **用途**：给业务方、产品、审核负责人开会看的方案对比与决策材料。
> **范围**：仅「异常单增值客户引导」；「增值原子 AI 预配置」见 [`D6_业务会_增值原子AI预配置.md`](D6_业务会_增值原子AI预配置.md)。
> **一句话**：客户在第二步选增值时，用 AI 帮看、帮问全——一期先定入口形态（自己打开 / 内嵌轻量入口 / 自动打开侧栏），后端引导逻辑同一套。

---

## 会议速用版

### 一页方案对比（一期 3 方案 + 二期方向）

| 方案 | 产品形态 | 客户怎么用 | 优点 | 缺点 | 推荐 |
|------|----------|------------|------|------|------|
| 客户自己打开智能客服 AI 助手提问 | 复用现有页面侧栏 AI 客服，客户主动发问 | 客户自己打开侧栏，输入异常单号或问题 | 万邑联零改造；后端逻辑同一套，随时升级 | 客户不主动问就没用；会议已明确「跟现在没区别」 | **一期兜底** |
| 第二步内嵌轻量 AI 助手（按钮/浮层） | 在第二步「增值产品信息」区域嵌入轻量入口（按钮或气泡） | 客户看到「不确定选哪个？AI 帮你看」→ 点击 → AI 自动带上当前异常单信息并引导 | 触发点贴合痛点；改造极小；不打扰不需要帮助的客户 | 依赖入口位置与文案；客户可能忽略不点 | **一期可选**（不接受自动打开时的主方案） |
| **进第二步自动打开 AI 助手侧栏 + 前端代发异常单消息** | 进入第二步 → 侧栏自动打开 → 前端/中间层代发异常单上下文给现有 Coze 智能客服 | 客户无需点击、无需复制单号；AI 直接开始引导 | 触发率最高；复用现有智能客服；数据侧零开发 | 可能打扰；需确认关闭/记忆策略；需确认 Coze 能否稳定走到增值引导 | **一期主推** |

**二期方向（本期不拍板落地）**：页面感知联动 + 提交前预审 + 预估报价参考——需万邑联前端改造、业务标注/审核规则、价卡数据通道，一期不纳入。

### 会议决策清单

- [ ] **一期入口形态三选一（或主推 + 降级）**：自动打开侧栏 / 内嵌轻量入口 / 客户自己打开 — 推荐：主推自动打开；不接受则退到内嵌轻量入口；前端排不上再兜底自己打开
- [ ] **若选自动打开：关闭/记忆策略** — 客户能否关闭？关掉后下次进入是否再弹？（问万邑联产品）
- [ ] **若选内嵌入口：位置与文案** — 放在增值产品列表上方/旁边？文案是否用「不确定选哪个？AI 帮你看」？
- [ ] **客户填写指引口径负责人** — 非标场景「客户需提供什么」由谁审定？（问增值审核业务）
- [ ] **非标「客户确认用 SOP 摘要」口径** — 依据审核 SOP / 模板生成给客户确认的处理方式摘要；仓库内部细步骤是否对客展示、谁审定？（问增值审核业务）
- [ ] **Coze 智能客服能否稳定走到增值引导** — 代发/带上下文后能否触达增值专家链？（会后问 Coze 维护人）
- [ ] **系统可选增值范围查询一期谁接、何时可用** — 硬分流必备（问 PMS/OpenAPI）

### 会后待办

| 负责人 | 待办 |
|--------|------|
| 万邑联产品 | 拍板一期入口形态；若自动打开则确认关闭/记忆；若内嵌则确认位置与文案；确认前端能否直接取到异常编码 |
| 增值审核业务 | 审定非标「客户需提供」清单 +「客户确认用 SOP 摘要」口径（与仓库内部细步骤分层）；指定 ground truth 负责人 |
| AI 侧 | 确认 Coze 代发后能否稳定触达增值专家链；推进系统可选范围查询接入；标准路径接 xlsx、非标路径接 SOP 追问与确认摘要 |
| Coze 维护人 | 确认代发/带上下文消息分类后是否生成增值专家 ID（核心瓶颈） |

## 一、我们要解决什么

**审核团队的痛**：双人每天 8 小时审核，近一半时间花在跟客户反复确认需求、补资料。

**客户的痛**：分不清标准增值和非标增值，明明有标准服务还是选了非标；选完之后该填什么、该传什么附件也不清楚，提交后被退回再补。

**本期只做异常单场景**（从异常单列表 → 处理异常 → 选增值产品），不做普通增值下单入口、不做预估报价参考、不做精确报价、不做自动审核 / 提交前预审。

---

## 二、客户现在的操作路径（三步）

| 步骤 | 客户看到什么 | 现在的问题 |
|------|-------------|------------|
| ① 异常单列表 | 异常单号、异常名称、仓库、状态、预计销毁日期 | 客户从这里进入处理异常，AI 不应在这一步打断 |
| ② 第一步：基本信息 | 仓库、入库单号、异常明细（异常单号、异常名称、异常对象、异常图片） | 客户确认异常事实；这步的信息 AI 可以自动获取 |
| ③ **第二步：增值产品信息**（痛点集中） | 系统圈定的增值产品列表、服务要求、增值文件、预估费用提示 | **客户在这一步最容易选错**：不知道标准和非标的区别，不知道该选哪个，选完之后字段填不全、附件漏传 |

**AI 引导的最佳触发点 = 第二步。** 一期三个方案的差别，主要在「怎么在第二步把客户接到 AI」，不在后端引导逻辑。

## 三、可行性校验

### 3.1 触发 + 代发

| 维度 | 结论 |
|------|------|
| **现有智能客服能力** | 万邑联侧栏 AI 助手（Coze 智能客服）的全量路径已具备专家编排能力：production 和灰度路径均含增值专家链，全量客户代发消息不会被灰度拦截在专家链之外 |
| **代发路径** | 前端/中间层在客户进入第二步（或点击内嵌入口）时，代发一条含异常单上下文的消息到现有 Coze 智能客服，走 production 路径即可 |
| **缺口** | ① Coze 收到消息后，分类 → 知识匹配是否为增值场景生成正确专家 ID（待 Coze 维护人确认）；② 自动打开侧栏需产品同意；③ 异常编码是否由前端可直接获取（待万邑联前端确认） |
| **假设** | 代发消息经分类后能到达增值专家链；若不能，备选为中间层直接调用专家编排（绕过分类） |

### 3.2 硬分流（谁推荐产品、谁只做话术）

| 层 | 谁做 | 依据 | 说明 |
|----|------|------|------|
| **硬分流：判断客户能选哪些增值产品** | 前端/中间层 | 调系统接口查询当前异常 + 仓库 + 入口下可选增值范围 + 异常→增值对照表 | **不由 AI 大模型猜测或推荐产品** |
| **话术/追问/需求整理** | AI 大模型（Coze 专家链） | 操作路径说明、字段追问措辞、需求摘要整理 | AI 只负责通俗话术引导客户填写，产品圈定由系统接口决定 |

**现状**：现有增值专家完全基于离线知识库做推荐，不调系统接口查可选范围。一期须在中间层补上系统接口查询，圈定后再注入 AI 上下文。

**缺口**：系统可选范围查询接口一期谁接、何时可用（待 PMS/OpenAPI 确认）。

### 3.3 客户填写指引 vs 仓库处理流程（两层分离）

| 层 | 面向谁 | 内容 | AI 一期职责 |
|----|--------|------|-------------|
| **客户填写指引** | 外部客户 | 客户需要提供什么信息才能提交完整工单 | **一期做**：分步追问 → 收集齐全 → 结构化需求摘要 |
| **客户确认用 SOP 摘要** | 外部客户 | 「是否按此处理方式让仓库操作」的确认稿：处理目标、关键步骤要点、需客户配合事项 | **一期做（2026-07-24 口径）**：依据《非标增值单审核 SOP 知识库》+《非标增值服务 SOP 模板及填写示例》生成，请客户确认；**不**等于自动终审、**不**替代人工审核 |
| **仓库内部细步骤** | 内部仓库/审核 | 扫描定位、系统操作路径、仓内执行细节等 | **一期不对客全文输出**；内部执行仍以审核/仓内 SOP 为准 |

**MVP 两条分流（与 HANDOFF §0 对齐）**：

1. **标准增值**：依据《操作增值类异常及增值解决方案（202511）.xlsx》+ 系统 `listAllVasc` 圈定，引导客户下正确标准增值，避免无特殊需求时误提非标。  
2. **非标增值**：标准确实无法覆盖 / 客户特殊需求时——① 追问真实需求；② 生成客户确认用 SOP 摘要。

**分析结论**：非标增值审核 SOP 知识库中场景模板已区分「客户需提供」与「仓库操作流程」。一期把前两者对客交付；仓库内部细步骤不对客倾倒。

**缺口**：部分场景的「客户需提供」与「确认用摘要」模板尚未结构化提取，待业务方审定口径后导入 AI 知识。

**红线**：不对客户倾倒仓库内部操作全文；「客户怎么填 / 客户确认什么」≠「仓库系统怎么点」；不承诺审核通过。

### 3.4 一期边界

- 不自动提交增值单
- 不替代人工审核，不保证通过（含：客户确认了 SOP 摘要 ≠ 审核通过）
- 不做提交前预审（漏填/错选拦截）
- 不输出预估报价参考，也不做精确报价
- 不做普通增值下单入口（仅异常单场景）
- 不做知识库实时同步（一期静态导入）
- 不做页面感知联动
- **不做**：无客户确认的「静默自动绑定并下发仓库执行」；一期必须有客户确认环节

## 四、一期三个入口方案（后端逻辑同一套）

三个方案触发后，AI 做的事相同：硬分流 → **标准推荐** 或 **非标（追问 + 客户确认用 SOP 摘要）**。差别只在**怎么接到 AI**。

### 4.1 方案一：客户自己打开智能客服 AI 助手（兜底）

| 维度 | 说明 |
|------|------|
| **产品形态** | 复用现有侧栏 AI 客服，页面不加新入口 |
| **客户怎么用** | 自己打开侧栏，输入异常单号或描述需求 |
| **改造量** | 万邑联：0；AI 侧：引导逻辑 + 知识 |
| **解决什么** | 客户主动来问时，能推荐标准 / 追问非标 / 输出摘要 |
| **不解决什么** | 客户不知道要问 → 没有价值；不能主动拦截错选 |
| **推荐级别** | **一期兜底**——内嵌入口与自动打开都排不上时先上 |

### 4.2 方案二：第二步内嵌轻量 AI 助手（按钮/浮层）

| 维度 | 说明 |
|------|------|
| **产品形态** | 在第二步「增值产品信息」区域嵌入轻量入口（按钮或气泡浮层） |
| **客户怎么用** | 看到「不确定选哪个？AI 帮你看」→ 点击 → 前端带上当前异常单上下文打开 AI，开始引导 |
| **改造量** | 万邑联：只加一个入口（极小）；AI 侧：同方案一 |
| **解决什么** | 在客户最容易选错的位置给出可见触点；点击后自动带上下文，无需复制单号 |
| **不解决什么** | 客户没看到或不点，仍走老路；不做全页实时感知 |
| **优点** | 贴合痛点位置；不强制打扰；比「自己打开」主动得多 |
| **缺点** | 依赖位置与文案；部分客户可能忽略 |
| **推荐级别** | **一期可选**——产品不接受自动打开时，作为正式主方案；也可作为自动打开关闭后的手动再开入口 |

### 4.3 方案三：进第二步自动打开侧栏 + 前端代发（主推）

| 维度 | 说明 |
|------|------|
| **产品形态** | 进入第二步即自动打开 AI 助手侧栏，并由前端/中间层代发异常单上下文 |
| **客户怎么用** | 无需点击、无需复制单号；进第二步后 AI 直接开始引导 |
| **改造量** | 万邑联：自动打开 + 代发（比内嵌入口稍多）；AI 侧：同方案一 |
| **解决什么** | 彻底解决「不知道有 AI」；触发率最高 |
| **不解决什么** | 仍不做全页字段级感知；不自动提交、不替代审核 |
| **优点** | 触发率最高；复用现有 Coze 智能客服 |
| **缺点** | 可能打扰；需确认关闭与记忆策略 |
| **推荐级别** | **一期主推** |

#### 触发契约（方案三）

1. 客户在第一步点「下一步」→ 进入第二步「增值产品信息」
2. 页面**自动打开** AI 助手侧栏
3. 前端/中间层**自动代发**含异常单上下文的消息（不是客户复制单号）
4. 客户可关闭侧栏；关闭后可用方案二的内嵌入口手动再开

#### 代发 + Coze 智能客服衔接

代发消息进入现有 Coze 智能客服后，走全量 production 路径：

1. 消息经意图分类  
2. 知识匹配生成专家 ID  
3. 若增值专家 ID 被正确生成 → 专家编排 → 增值诊断 → 产品推荐 → 服务配置  
4. 若未生成 → 走老知识库兜底回答  

**已验证**：production 路径具备专家编排能力，不再被灰度拦截。  
**待确认**：知识匹配环节是否为增值场景生成正确的专家 ID。

#### 硬分流（三个方案共用）

```
前端代发 / 带上下文（含异常编码 + 仓库 + 客户）
  ↓
中间层调系统接口：查该异常场景下可选的增值产品范围
  ↓
┌─ 系统候选中有标准增值且对照表语义匹配 ─→ 推荐标准增值
│    AI 话术：「这个异常可以选 XX 标准增值，流程更快、信息更简单」
│    + 列出客户需填写的字段清单
│
└─ 标准覆盖不了 / 客户坚持非标 ─→ 非标客户填写指引
     AI 分步追问 → 输出结构化需求摘要
```

**关键原则**：产品推荐由「系统接口圈定 + 对照表」决定；AI **只负责话术与追问**，不自行推荐产品。

#### 标准 / 非标分支（三个方案共用）

**标准**：系统确认有可选标准增值 → AI 告知可优先选标准，并列出需填字段；多候选时先追问意图。

**非标指引（两轮，2026-07-24 口径）**：

| 轮次 | AI 做什么 | 客户做什么 |
|------|-----------|------------|
| 第一轮：追问 | 按 SOP「客户需提供」清单逐项追问：对象、动作、数量/条码、附件、特殊要求 | 逐项回答、上传附件 |
| 第二轮：确认 | ① 结构化需求摘要（已齐/缺失）；② **客户确认用 SOP 摘要**（处理方式要点 + 需配合事项，依据审核 SOP / 模板） | 确认「是否按此流程让仓库操作」，或补充修正 |

**输出物**：结构化需求摘要 + 客户确认用 SOP 摘要。  
**不做**：不承诺审核通过；不对客输出仓库内部系统细步骤全文；不在无客户确认时静默下发执行。

#### 客户填写 vs 仓库流程（再次强调）

- **对客户说**：「请提供入库单号、包裹号、商品条码对应关系…」；以及「拟按如下方式处理，请确认是否让仓库按此操作：…（确认用 SOP 摘要）」
- **不对客户说**：仓内扫描枪路径、系统菜单点击顺序等内部细步骤
- 「客户怎么填 / 客户确认什么」≠「仓库系统怎么点」

## 五、一期入口怎么选（推荐演进）

```
主推：自动打开侧栏 + 代发
  → 产品不接受自动打开 → 内嵌轻量 AI 入口（按钮/浮层）
    → 前端连入口都排不上 → 客户自己打开智能客服（兜底）

二期再做：页面感知联动 + 提交前预审 + 预估报价参考
```

三个一期方案**后端同一套**；会上只需拍板入口形态，不必争论引导能力本身。

## 六、二期方向

一期不纳入、会上不承诺落地时间。二期三项能力与依赖如下。

### 6.1 页面感知联动

客户选错、漏填时 AI **主动**提示，无需客户再点入口。

**依赖**：万邑联前端**较大改造**——页面须持续暴露步骤、已选产品、字段/附件变化等状态给 AI（React 单页应用无法靠外挂可靠感知）；需产品 PRD 与前端排期（协调周期不可控）。

### 6.2 提交前预审（三层，缺一不可）

客户点提交前，拦漏填、漏附件、明显错选。不是「只业务标答案」，也不是「只前端加校验」，而是三层一起：

| 层 | 谁做 | 做什么 |
|----|------|--------|
| **规则与标准答案** | 业务 / 审核 | 定义「什么算对、什么算错」；提供标注样本（ground truth）；审定必填清单与错选口径 |
| **校验执行** | AI / 中间层 / 规则代码 | 按接口必填项、对照表、业务规则判断：漏字段、漏附件、明显错选 |
| **提交前拦截体验** | **万邑联前端** | 提交按钮挂钩；结果展示在页面字段旁或弹层；硬拦或软提示的产品策略落地 |

**一期为什么不做**：标注数据预计 7 月底才到位；提交钩子与表单状态联动需额外前端改造；没有可靠规则前不应承诺「能拦住错选」。

### 6.3 预估报价参考

在引导选型时，给客户**参考性费用区间或标准/非标粗略对比**（仍标注「预估、以实际扣费为准」），帮助客户理解「选标准通常更省 / 非标可能更贵」。

**依赖**：价卡 / 计费数据通道打通；标准与非标计价口径由业务确认；与页面现有「系统预估费用」提示对齐，避免两套数打架。

**一期为什么不做**：一期不接入价格数据源；不做精确报价、也不做标准/非标价差对比，避免误导客户或与实扣费用冲突。

### 6.4 二期依赖一览

| 二期能力 | 主要依赖 |
|----------|----------|
| 页面感知联动 | 万邑联前端较大改造（状态 hook / 主动弹窗） |
| 提交前预审 | 业务标注 + 审核规则 + 校验执行 + 前端提交拦截 |
| 预估报价参考 | 价卡数据通道 + 业务计价口径 |

| **自动审核通过** | AI 只帮问全、整理摘要，不替代人工审核 | 即便有提交前预审，也只是初筛提示，审核结论仍由人定 |
| **量化推荐命中率 / 错选率下降比例** | 需业务方标注数据集（ground truth），到位前只能定性验证 | 标注到位后建回归基准，再谈命中率/错选率数字 |
| **无确认的静默自动下发仓库执行** | 一期非标会生成**客户确认用 SOP 摘要**并请客户确认，但仍不替代人工审核、不保证通过 | 二期可探索：确认后与工单/审核流更紧耦合；仓内细步骤执行编排仍须业务与仓内系统能力 |

## 八、15 分钟会议讲稿

### 0:00–1:30 · 开场定调

- 目标：客户在第二步选增值时，AI 帮看、帮问全。
- 一期先定**入口形态**；引导逻辑（硬分流 + 标准/非标）三个方案共用。
- 不做普通下单、不报价参考、不替代审核、不做提交前预审。

### 1:30–3:30 · 痛点回顾

- 审核：一半时间追客户补料。
- 客户：标准非标分不清、填不全、退回反复改。
- 痛点在第二步「增值产品信息」。

### 3:30–7:00 · 一期三个入口方案

- **自己打开**：零改造兜底，客户不主动问就没用。
- **内嵌轻量入口**：第二步加按钮/浮层，点击后带异常单上下文引导——改造小、不强制打扰。
- **自动打开 + 代发**（主推）：进第二步侧栏自动开、代发上下文——触发率最高，需确认是否打扰。
- 共用能力：硬分流（系统圈定产品）+ AI 话术；标准依 xlsx；非标 = 追问真实需求 + 客户确认用 SOP 摘要（不对客甩仓库内部细步骤）。

### 7:00–9:00 · 可行性与风险

- 已验证：Coze 全量路径已具备专家编排，代发有机会直接触发增值引导。
- 待确认：知识匹配能否稳定生成增值专家 ID。
- 演进：自动打开 → 不接受则内嵌入口 → 再不行则自己打开。

### 9:00–12:00 · 决策清单

- 一期入口选哪个？（自动打开 / 内嵌 / 自己打开）
- 自动打开的关闭记忆？内嵌的位置文案？
- 客户填写口径谁审？非标「客户确认用 SOP 摘要」谁审？
- Coze 专家 ID？系统可选范围查询谁接？

### 12:00–13:30 · 一期不承诺

- 不做页面感知、不做提交前预审、不做预估报价参考。
- 提交前预审不是「只业务标答案」：还要规则引擎 + 前端提交拦截。
- 不自动审、不承诺命中率；非标有客户确认摘要，但**无确认不静默下发**、确认≠审核通过。
- 二期三项：页面感知 + 提交前预审（三层）+ 预估报价参考。

### 13:30–15:00 · 下一步

- 会后按入口拍板更新排期。
- AI 侧推进 Coze 确认 + 系统接口接入。
- 产品确认入口与侧栏策略。
