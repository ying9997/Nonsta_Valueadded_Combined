## 一句话说明

AI 通过 Coze SDK 侧栏与客户对话，对话完成后通过结构化 JSON 驱动页面表单操作。
需要前端实现 SDK 回调解析和 DOM 操作；后端提供审核回填接口或确认现有接口可用。

## 研发需要做的事

### 前端（客户端页面）

#### 必须做

1. **Coze SDK 集成**
   - 升级 `@coze/chat-sdk` 至支持 `afterMessageReceivedFinish` 的版本。
   - Bot ID：[待填]
   - 集成位置：库内增值下单页面，复用现有在线咨询侧栏容器。

2. **Tool Call 回调解析**
   - 监听 `afterMessageReceivedFinish`。
   - 从 `message.content` 中提取 `vas_form_action` JSON。
   - 只处理 `function_name = "vas_form_action"` 的结构化指令。
   - 详见 `contracts/tool-calling-spec.md` §4.1-§4.3。

3. **表单操作执行**
   - 支持 4 个 target：`product` / `service` / `requirementBackground` / `requirementDescription`。
   - 实现 Target 到页面控件的 DOM 映射层，DOM 变化时只改映射层。
   - 按 action 顺序执行：先选产品/服务，再填需求背景和需求描述。
   - 详见 `contracts/tool-calling-spec.md` §4.4。

4. **降级处理**
   - JSON 解析失败：静默忽略，不影响 AI 文本展示和客户手动下单。
   - 控件找不到、选项不存在或填入失败：记录失败并 toast 提示“请手动填写”或“请手动选择”。
   - 执行后页面校验报错：保留已填内容，让客户按原页面校验继续修改。
   - 详见 `contracts/tool-calling-spec.md` §6。

5. **日志上报**
   - 每次 Tool Call 执行结果上报，至少包含 action、target、截断后的 value、status、error、页面路径、conversationId。
   - 用于监控 Tool Call 执行成功率、解析失败率和 target 失败分布。
   - 详见 `contracts/tool-calling-spec.md` §4.6、§7。

#### 可选（一期建议有）

- 偏好设置 localStorage（“不自动弹出”）。
- AI 填入后字段高亮提示。
- 一键填入失败时展示可复制内容。

### 后端（审核回填 + 数据存储）

#### 必须做

1. **审核回填接口**
   - 增值单状态变为“待审核”时，将 AI 生成且客户确认的 SOP 回填到 TOM 的“操作SOP”字段。
   - 需要接口支持：增值单号 + SOP 内容 + 场景概述（如可用）+ AI 来源标识 -> 写入审核信息。
   - 或确认现有 TOM OpenAPI 是否已支持该写入能力：[待确认]

2. **AI 原文存储字段**
   - 增值单需要能关联 AI 原文，至少保存 `ai_original_sop` 或等价存储位置。
   - 用于后续对比 AI 原文、客户提交版本、审核最终版，计算客户修改率和审核修改率。
   - 若一期使用飞书多维表格 `vas_trace_store` 存原文，后端需确认 TOM 侧是否能通过增值单号关联查询：[待确认]
   - 详见 `contracts/tool-calling-spec.md` §11。

#### 可选（一期可降级）

- TOM 审核页面增加“AI 质量评价”组件。
- 审核驳回原因结构化字段，用于后续反馈闭环。

### 接口契约

| 接口 | 方向 | 用途 | 规格 |
|------|------|------|------|
| `vas_form_action` | AI -> 前端 | 驱动页面表单操作 | `contracts/tool-calling-schema.md` |
| `vas_trace_store` | AI -> 飞书多维表格 | 存储 AI 原文 | `contracts/tool-calling-spec.md` §11.3 |
| 审核回填 | 后端 -> TOM | SOP 写入审核页面 | 待确认 OpenAPI |
| 增值单详情查询 | 后端 -> AI 评测 | 拉取客户提交版本、审核结果、审核最终 SOP | 待确认 TOM OpenAPI / tom-relay |

## 分支实现规则

| 分类 | 前端表单动作 | 后端动作 |
|------|--------------|----------|
| A 类：已有命名服务 | 只选中 `product` + `service`，不填 `requirementBackground` 和 `requirementDescription` | 不需要 SOP 回填 |
| B 类：有模板 | 选中“库内非标增值（特批）/库内其他服务需求”，填入需求背景说明和需求描述 | 待审核时回填客户确认 SOP 到 TOM |
| C 类：无模板或不确定 | 不执行表单 Tool Call，引导转人工 | 无自动回填 |

## 验收标准

前端：

- [ ] Coze 侧栏在库内增值下单页正常弹出，关闭后不阻塞页面操作。
- [ ] AI 返回合法 `vas_form_action` JSON 后，页面表单按 target 正确联动。
- [ ] A 类只选产品/服务，不填需求背景和需求描述。
- [ ] B 类可填入需求背景说明和需求描述，客户可继续修改。
- [ ] C 类不触发表单填入，页面保持可手动下单或转人工。
- [ ] 解析失败、填入失败不阻塞正常下单。
- [ ] Tool Call 执行结果日志正常上报。

后端：

- [ ] 增值单进入“待审核”时，B 类 SOP 已回填到 TOM “操作SOP”字段。
- [ ] 审核人员能识别 AI 预填来源，并可编辑保存最终版本。
- [ ] AI 原文可查，且能与增值单号关联。
- [ ] TOM 审核信息、审核结果、客户提交版本的查询能力已确认；不可用时记录降级口径。
