# 方案文档 - 中间层接口契约草案

> 日期：2026-07-28  
> 模块：`module_非标页内嵌智能引导/`  
> 本次目标：输出 `接口契约草案.md` 与 `字段清单_table.md`，只定义接口契约草案，不实现中间层代码。

## 1. 任务目标

在不修改归一化契约和 HTML 原型的前提下，补齐前端、中间层、Agent 三方交互的接口契约草案。契约需要承接已完成的候选输入结构、枚举、路由映射和方案一 `pageActions` 消费结构，并明确 Agent 决策流、会话生命周期、错误兜底、`matchState` / `matchConfidence` 阈值、`serviceDomain=return` 兜底和扩展入口。

## 2. 整体流程

1. 读取模块 README、归一化契约样例和方案一 HTML 原型，确认已有字段与边界。
2. 设计三段请求结构：前端请求、中间层规整请求、Agent 输入请求。
3. 设计三段响应结构：Agent 输出、中间层封装响应、前端消费响应。
4. 固化路由决策、会话状态、错误兜底和扩展边界。
5. 输出全字段清单，标注必填、来源和消费方。
6. 对照用户边界自检：不改前置文件、不写实现、不写评测、不做费用和视频 SOP 接口。

## 3. 节点明细表

| 节点编号 | 节点名称 | 输入 | 操作 | 输出 | 依赖节点 |
|----------|----------|------|------|------|----------|
| N1 | 基准读取 | README、候选清单归一化契约、candidate sample、方案一 HTML | 提取 `systemScopedVascList`、`routeBranch`、`serviceDomain`、`pageActions`、`matchState` 等已定义字段 | 基准字段清单 | - |
| N2 | 请求契约设计 | N1 输出 | 定义前端到中间层、中间层到 Agent 的请求 schema；保留候选快照和页面上下文 | 请求 schema 草案 | N1 |
| N3 | 响应契约设计 | N1 输出 | 定义 Agent 到中间层、中间层到前端的响应 schema；约束页面动作和字段建议 | 响应 schema 草案 | N1 |
| N4 | 状态与兜底 | N2、N3 输出 | 补齐 Agent 决策流、会话生命周期、错误兜底、`serviceDomain=return` 规则 | 决策和状态规则 | N2、N3 |
| N5 | 字段清单 | N2、N3、N4 输出 | 汇总 request / response 全字段，标注必填、来源、消费方 | `字段清单_table.md` | N2、N3、N4 |
| N6 | 验证归档 | 全部交付物 | 检查边界和文件完整性，记录执行与总结 | workflow 归档 | N5 |

## 4. 影响评估

- 受影响文件：仅新增本 workflow 目录下文档。
- 不受影响文件：归一化契约、HTML 原型、模块 README、任何实现代码。
- 风险点：接口字段可能被误读为已联调实现；草案中需明确“草案”和“不定义实现逻辑”。
- 回退方案：如后续口径调整，仅修订本目录新增文档；删除本 workflow 目录即可回退本切片。
