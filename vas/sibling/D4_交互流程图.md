# D4 交互流程图

> 节点：N-M2-4  
> 主线：异常单入口 -> 处理异常 -> 第二步增值产品信息 -> AI 引导  
> 边界：本期覆盖异常单链路；入库/库内/出库/退货为异常环节分类，不覆盖普通直接下单入口

## 1. 总流程

```mermaid
flowchart TD
  A[客户进入万邑联异常单列表] --> B{选择异常单}
  B -->|处理异常| C[第一步：创建增值订单 / 基本信息]
  C --> C1[查看异常明细：异常单号、异常名称、异常对象、异常图片]
  C1 --> D[点击下一步]
  D --> E[第二步：增值产品信息]
  E --> F{触发 AI 的方式}

  F -->|不触发| G[客户自行选择增值产品/非标并提交]
  G --> G1[现状风险：错选标准增值、误选非标、资料不完整]

  F -->|β：点击 不确定选哪个？AI 帮你看| H[AI 获取异常上下文]
  F -->|β2：进入第二步后自动打开侧栏并自动发问| H0[自动发送固定句式 + 异常单号]
  H0 --> H
  H --> I[queryEventList / queryEventOrderDetail]
  I --> J[归一异常事实：eventCode、eventName、exceptionNode、exceptionObject、仓库、PSC、货物、附件]
  J --> K[listAllVasc 圈定系统可选 VASC]
  K --> L[对照表匹配异常到标准增值语义]
  L --> M{标准增值可覆盖且在系统候选中}

  M -->|是| N[推荐标准增值]
  N --> N1[getVascInfo / BaseAttrRel 拉必填字段、选项、附件]
  N1 --> N2[输出：推荐理由 + 需填写清单 + 禁用/互斥提示]
  N2 --> O[客户按推荐选择并补全]

  M -->|否 / 客户坚持非标| P[进入非标补全]
  P --> P1[getVascInfo / BaseAttrRel 拉非标原子与属性]
  P1 --> P2[分步追问：背景、对象、动作、条码/数量、附件、特殊要求]
  P2 --> P3{信息是否完整}
  P3 -->|否| P2
  P3 -->|是| P4[输出完整需求摘要 + 缺失为零/转人工原因]
  P4 --> O

  O --> Q[客户保存草稿或提交]
  Q --> R[系统按现有流程审核/执行]

  L --> S{异常属于知悉类或无需提交增值}
  S -->|是| S1[提示无需提交增值，说明仓库默认处理/关注状态]
  S1 --> T[结束]
  S -->|否| M
```

## 2. β 首选路径交互

```mermaid
sequenceDiagram
  participant C as 客户
  participant W as 万邑联异常单页面
  participant AI as 增值引导 AI
  participant OMS as 异常单查询
  participant PMS as VASC/属性接口
  participant KB as 对照表+静态KB

  C->>W: 进入处理异常第二步「增值产品信息」
  W-->>C: 展示系统圈定的增值产品、服务要求、增值文件、预估费用提示
  alt β 按钮触发
    C->>W: 点击「不确定选哪个？AI 帮你看」
    W->>AI: 触发入口（可选传 eventNo；不传则由客户/AI 补）
  else β2 自动触发
    W->>AI: 进入第二步后自动打开助手侧栏
    W->>AI: 自动发送固定句式 + eventNo
  end
  AI->>OMS: queryEventList / queryEventOrderDetail
  OMS-->>AI: 异常编码、名称、环节、对象、仓库、货物、附件
  AI->>PMS: listAllVasc(exceptionEventCodeSet, warehouseCode, pscCode, addValueEntry)
  PMS-->>AI: 系统可选 VASC 候选
  AI->>KB: 查询异常到增值语义、话术、非标兜底
  KB-->>AI: 标准推荐语义与补全口径
  AI->>PMS: getVascInfo / BaseAttrRel
  PMS-->>AI: 原子、互斥组、必填属性、附件、禁用原因
  AI-->>C: 推荐标准增值或分步补全非标资料
  C->>W: 按清单选择、填写、上传、保存或提交
```

## 3. 标准增值推荐分支

```mermaid
flowchart LR
  A[异常事实] --> B[对照表：异常编码/类型 -> 标准增值]
  A --> C[listAllVasc：系统候选]
  B --> D{语义推荐与系统候选交叉}
  C --> D
  D -->|命中| E[推荐标准增值]
  E --> F[说明：解决什么问题、为什么优先标准、需补哪些字段]
  F --> G[客户选择标准增值]
  D -->|未命中| H[不强推]
  H --> I[提示系统未圈定该标准增值，建议人工确认或走非标补全]
```

推荐话术：

> 已根据异常编码、异常对象和系统当前可选增值范围，识别到可以优先选择「{标准增值}」。该路径比非标更标准，通常处理更快，也能减少因信息不完整被退回的概率。你还需要补充：{字段清单}。

## 4. 非标补全分支

```mermaid
flowchart TD
  A[客户选择非标或标准不可覆盖] --> B[说明非标需审核，不承诺通过]
  B --> C[收集业务背景]
  C --> D[收集操作对象：包裹/商品/单品/托盘、条码、数量、等级]
  D --> E[收集期望动作：拍照、贴标、换包装、上架、销毁、自提、文件修改等]
  E --> F[收集附件：图片、文件、条码对应关系、商品清单]
  F --> G[校验 getVascInfo / BaseAttrRel 必填项]
  G --> H{仍缺信息}
  H -->|是| I[继续追问缺失项]
  I --> C
  H -->|否| J[生成完整需求摘要]
  J --> K[提示费用和可执行性以审核/实际扣费为准]
```

非标话术：

> 当前需求超出标准增值覆盖范围，建议走非标增值。为减少驳回，请先补充：处理对象、期望动作、条码/商品清单、附件或图片、特殊要求。费用与是否可执行以审核和实际扣费为准。

## 5. 知悉类 / 无需提交增值分支

```mermaid
flowchart TD
  A[异常事实] --> B[对照表判断]
  B --> C{知悉类或无需提交增值}
  C -->|是| D[提示无需提交增值]
  D --> E[说明仓库默认处理、客户需关注状态/预计销毁日期]
  C -->|否| F[进入标准推荐或非标补全]
```

适用示例：

- 退货知悉类异常：只需告知处理方式，不引导提交增值。
- 包裹包装异常且无需客户处理：不建议新增增值单。

## 6. 边界标注

| 项 | 本期处理 | 不做 |
|----|----------|------|
| 异常单入口 | 覆盖，从异常单列表到处理异常第二步 | 不覆盖普通服务中心增值申请 |
| 入库/库内/出库/退货 | 作为异常环节分类参与推荐语义 | 不视为四条普通下单入口 |
| 页面触发 | β：第二步轻量入口；β2：进入第二步自动打开助手并自动发问；α：手动异常单号兜底 | 不做 γ 全页面自动感知 |
| 推荐 | 标准优先，非标补全，知悉类提示无需提交 | 不自动提交，不替客户审核 |
| 费用 | 保留“系统预估，最终按实际扣费” | 不做精确报价或价差承诺 |
| 验收 | 节点自检覆盖链路和边界 | 不做 N-M2-5 命中率/错选率 ground truth |
