# 万邑联下单触点核验

> 节点：N-M2-1  
> 范围：异常单入口；不覆盖非异常直接下单  
> 依据：3 个万邑联 HTML 快照、异常单接口文档、增值产品接口文档、PLAN §10.3

## 1. 结论

一期客户引导应嵌在「异常单列表 -> 处理异常第一步 -> 第二步增值产品信息」链路中。推荐落点是第二步「增值产品信息」区域，在系统已经圈定可选 VASC 后，给客户一个轻量触发入口，例如「不确定选哪个？AI 帮你看」。

该入口不要求万邑联额外传业务参数：智能体可凭异常单号或当前客户上下文调用既有异常单查询能力，自取异常事实；系统允许选择的增值产品范围，以 `pms.vasc.listAllVasc` 为准；单个产品的原子、互斥组、必填项与属性展示规则，以 `pms.vasc.getVascInfo` 和 `pms.BaseAttrRelService.findBaseAttrRelPage` 为准。

## 2. 页面触点核验

| 页面 | 已核验业务文本 / 控件 | 对 AI 引导的含义 |
|------|------------------------|------------------|
| `万邑联-海外仓-异常单管理列表.html` | 页面菜单包含「异常单」；业务区存在异常筛选、异常名称、登记仓库、异常类别、异常状态、预计销毁日期、批量处理异常、批量反馈等文本 | 异常单列表是入口前置页，可从待反馈/处理中异常进入处理链路；AI 不应在此直接替客户下单，只做入口提示或异常单上下文识别 |
| `万邑联-处理异常-第一步-创建增值订单.html` | 标题「新建入库增值订单」；步骤「1 基本信息」「2 增值产品信息」；基本信息含仓库、入库单号；异常明细表含异常单号、异常名称、异常对象、查看异常图片；样例为 `EB0326062258 / 包裹内出现订单外商品 / 商品`；底部有保存草稿、下一步 | 第一步可展示异常事实，适合做“已识别异常，下一步将推荐增值产品”的弱提示；关键推荐动作应放到下一步，避免客户还没进入产品选择就打断 |
| `万邑联-处理异常-第二步-填写增值产品信息（核心）.html` | 步骤「增值产品信息」；展示最大可下单金额、账户组金额；增值产品表含「增值服务 / 服务要求 / 增值文件」；出现 VASC 原子如「入库-补贴包裹条码」；属性项包括标签类型、尺寸规格、上架的商品等级；底部有上一步、保存草稿、提交；提示“以上费用为系统预估费用，最终收费按实际扣费为准” | 第二步是首选触发点。AI 可在客户选择前推荐标准增值，或在客户选择非标/信息缺失时按原子属性引导补全。费用只能提示“系统预估/最终以实际扣费为准”，一期不做精确报价 |

## 3. 字段与上下文来源

| 需要的信息 | 页面可见性 | 接口权威来源 | 用途 |
|------------|------------|--------------|------|
| 异常单号 | 第一步异常明细可见 | `queryEventList.eventNo`；详情入参使用 `eventDetailId` | 作为客户手动输入或 AI 自取上下文的主线索 |
| 异常编码 / 异常名称 | 列表接口返回，第一步展示异常名称 | `queryEventList.eventCode/eventName`；`queryEventOrderDetail.unusualEventOrderVos[].eventCode/eventName` | 对照表推荐语义、传 `exceptionEventCodeSet` 圈定 VASC |
| 异常环节 | 列表和详情接口返回 | `exceptionNode/exceptionNodeName` | 判断入库/库内/出库/退货异常边界 |
| 异常对象 | 第一步异常明细可见 | `exceptionObject/exceptionObjectName` | 判断商品/包裹/单品/子包裹等对象，生成资料清单 |
| 仓库 / PSC / PSCG | 页面展示仓库；接口返回仓库与 PSC | `warehouseCode`、`winitProductCode`；`listAllVasc` 支持 `warehouseCode/pscCode/pscgCode` | 圈定系统可选增值产品 |
| 关联货物、附件、外部属性 | 页面可查看图片；详情接口返回明细 | `queryEventOrderDetail.packages/merchandises/items/subPackages/attachmentList/externalAttributes` | 判断需客户补充的照片、条码、商品资料、特殊说明 |
| 可选 VASC | 第二步产品区展示 | `pms.vasc.listAllVasc` | 系统允许范围，优先级高于静态知识库 |
| VASC 原子与必填属性 | 第二步产品表展示服务要求/增值文件 | `pms.vasc.getVascInfo`、`BaseAttrRelService.findBaseAttrRelPage` | 生成非标或标准增值的分步补全清单 |
| 费用 | 第二步展示预估费用提示 | `RevenueEventChargeItemService.findChargeItemPage` + 价卡链路 | 二期报价；一期只做口径提示，不输出精确报价 |

## 4. §10.3 五步接口映射

### 4.1 归一异常事实

输入来自 `oms.unusualEventOrder.queryEventList` 与 `oms.unusualEventOrder.queryEventOrderDetail`：

- 列表先按客户上下文、状态、日期、异常单号等筛选，拿到 `eventNo/eventCode/eventName/eventDetailId/isNeedFeedback/isNeedCustomerInformation/warehouseCode/exceptionNode/exceptionObject/vascCode`。
- 详情再用 `eventDetailId` 查询完整异常单，补齐 `eventProcessFlow/attachmentList/unusualEventOrderVos/externalAttributes/packages/merchandises/items/subPackages`。
- AI 内部统一成结构：`eventNo + eventCode + eventName + exceptionNode + exceptionObject + warehouseCode + pscCode + goodsContext + attachments + customerNeed`。

### 4.2 圈定可选增值范围

调用 `pms.vasc.listAllVasc`，建议传入：

| 参数 | 来源 | 说明 |
|------|------|------|
| `exceptionEventCodeSet` | 当前异常编码 `eventCode` | 异常场景圈定核心条件 |
| `warehouseCode` | 异常单仓库 | 避免推荐仓库不可用产品 |
| `pscCode` | `winitProductCode` | 按产品能力圈定 |
| `pscgCode` | 产品组信息，若可由 PSC 推得则传 | 提高圈定精度 |
| `addValueEntry` | 当前入口，异常处理链路 | 区分普通下单和异常入口 |
| `attributeQueryList` | 已知属性过滤 | 有明确属性时再传，不做猜测 |

输出 `vascCode/vascName/vascAttributeMap` 作为系统允许选择的 VASC 候选集。若候选集为空，AI 不应硬推标准增值，应转“需人工确认/可能非标”。

### 4.3 标准 vs 非标推荐

语义基准使用 `海外仓各业务环节异常类型与增值服务对照表.md`：

- 若对照表中的异常编码或异常类型能映射到标准增值，且该增值在 `listAllVasc` 返回候选中存在：推荐标准增值，并解释“标准路径更快、更少审核、通常成本更可控”。
- 若对照表有推荐但接口候选集中不存在：以接口为准，不直接推荐；输出“系统当前未圈定该标准增值，建议人工确认配置或选择非标兜底”。
- 若对照表无编码或只给处理方式：保留为知识解释，不构造标准推荐。
- 若客户需求超出标准增值覆盖范围：进入非标增值补全。

### 4.4 必填清单与非标分步补全

对候选或客户已选的 `vascCode` 调：

1. `pms.vasc.getVascInfo(vascCode)` 获取原子分组、互斥组、是否必填、是否展示、是否禁用、禁用原因、属性数组。
2. `pms.BaseAttrRelService.findBaseAttrRelPage(instanceCode=vascCode 或原子/实例编码)` 补齐属性名称、展示类型、下拉选项、是否必填、文件格式、是否展示给客户。

AI 输出时按客户语言组织成清单：

- 需要选择的服务：VASC 名称、原子名称、互斥关系。
- 需要填写的字段：属性名、是否必填、输入类型、枚举选项、单位/格式。
- 需要上传的资料：图片、标签文件、条码对应关系、商品/包裹清单等。
- 不能选择的项：展示 `disableReason`，不替客户绕过。

### 4.5 二期报价对比

`pms.RevenueEventChargeItemService.findChargeItemPage` 和价卡链路仅作为二期“简易报价对比”接口基础。一期交付中只保留页面已有口径：费用为系统预估，最终收费以实际扣费为准；不输出精确价格、不承诺标准与非标价差。

## 5. β 触发入口落点

首选落点：

- 页面：第二步「增值产品信息」。
- 位置：增值产品表上方或产品选择区域旁。
- 文案：`不确定选哪个？AI 帮你看`。
- 触发后：AI 根据异常单号/当前客户上下文自取异常事实，不要求页面传完整参数。

降级落点：

- 若产品暂不接万邑联入口改造，先走 α：客户在现有 AI 窗口手动输入异常单号。
- AI 仍按同一套 `queryEventList/queryEventOrderDetail -> listAllVasc -> getVascInfo/BaseAttrRel` 链路执行。

不建议落点：

- 列表页直接弹强提醒：客户还没进入增值选择，容易打扰。
- 第一步强制弹窗：第一步主要是确认异常明细，推荐动作应留到第二步。
- 纯外挂脚本自动感知：PLAN 已核验万邑联为 React SPA，纯外挂无法可靠感知业务节点。

## 6. 边界与待确认

- 本期只覆盖异常单入口，不纳入入库/库内/出库普通增值直接下单。
- 入库/库内/出库/退货在对照表中是异常环节分类，不等于本期覆盖四条普通下单入口。
- β 入口方案可推荐，但是否加按钮、按钮位置与文案仍需产品确认。
- N-M2-5 的推荐命中率/效果验收因缺 ground truth 暂不执行，本文件不构造验收 oracle。
