# 一期业务系统映射关系矩阵（定稿）

> **承接**：GPT v1 初稿（仅接口/字段级骨架，无 xlsx 校准） + xlsx 业务校准层（202511） + D6 硬分流边界 + 万邑联触点核验
> **范围**：一期 MVP「异常单增值客户引导」；不覆盖普通增值下单、不做预估报价、不做提交前预审
> **核心变化（相对 GPT v1）**：E 类改为「PMS × xlsx 双向交叉验证」框架；新增 F 类意图路由与 H 类校准规则；xlsx 走「校准参考」而非运行时真源

## §0 Executive Summary

### 0.1 GPT v1 可直接保留的部分

| 模块 | 保留内容 | 文件位置 |

| 遗漏项 | 重要性 | 本定稿补救位置 |

| H 规则与冲突项的关联（H01–H18 指向 §3.3 哪些行） | 中 | §5 末列 |

### 0.3 一期能否闭环？阻塞 Top 3

| 阻塞项 | 严重度 | 谁解 | 解法路径 |
|--------|--------|------|----------|
| **PMS 侧实测数据缺失**（xlsx 给了 vascCode↔中文名候选，但 PMS `listAllVasc` 实际返回的 vascName 未对账） | **高** | PMS 抽样验证 | 见 §3.1：需 PMS 抽样的 vascCode 清单（优先高频 ⭐） |
| **Coze 增值专家链稳定性**（`pre_get_solution/post_get_solution` 是否稳定生成 `value-add-*` expert_ids） | **高** | Coze 维护人 | C1b 待确认；不通过则 BFF 直调 recaller 备选 |
| **非标「客户需提供」清单未结构化审定** | 中 | 增值审核业务 | 仍需业务方给定 179 个 SOP 场景的客户层字段表 |

**结论**：技术链路可搭建，但 E 类对账（产品名↔vascCode）必须以 PMS 抽样为先决条件；本期只能上「verified 项 + pending_pms 兜底推荐池」，conflict 项必须人工。

### 0.4 E 类对账状态总览（当前仅有 xlsx 一侧时）

| 对账状态 | 含义 | 一期动作 |
|---------|------|----------|
| `verified` | PMS vascName 与 xlsx 中文名完全一致，且 vascCode 双向可定位 | 进推荐池 |
| `pms_only` | PMS 有候选但 xlsx 未列出（或对应行缺失） | 标待 PMS 人工核对；不进推荐池 |
| `xlsx_orphan` | xlsx 有中文名但 PMS 无对应 vascCode | 标「业务语义孤岛」；不进推荐池 |
| `name_mismatch` | PMS vascName 与 xlsx 中文名不一致 | 必须人工裁决；不进推荐池 |
| `pending_pms` | xlsx 给了 vascCode 但 PMS 实测未抽到（本期常态） | 暂进「推荐池 v2」需 PMS 抽样后升级 |

## §1 GPT v1 质检（六维 + 缺 xlsx 维）

> 原六维来自初稿作者自检；本节加入「缺 xlsx」与「对照表真源误用」两维。

| # | 维度 | 结论 | 处理 |
|---|------|------|------|
| 1 | **接口字段完整性** | 合格 | 保留 §2.1–§2.6 |
| 2 | **硬分流原则正确** | 合格 | 保留「系统接口圈定 + 对照表语义交集」 |
| 3 | **客户填写 vs 仓库流程分层** | 合格 | 保留 F 类「客户需提供」禁写仓库 SOP |
| 4 | **业务语义对照定位** | 合格，但范围限定 | D 类定位降为「业务语义基准」，不可做系统权威（与 xlsx 校准不冲突） |
| 5 | **注入契约完整** | 合格 | 保留 recaller 9 字段 + value-add `inputs` |
| 6 | **缺口清单完备** | 合格 | G01–G14 全部保留；新增 G15–G17（见 §7） |
| 7 | **缺 xlsx 校准层** | **不合格** | 本次补 F/H/E 交叉三类 |
| 8 | **E 类定义不严谨（向 PMS 单向要）** | **不合格** | 改为「PMS × xlsx 双向交叉」 |
| 9 | **未误把对照表当 E 类真源** | 基本合格，但有歧义 | 初稿 §0 写「对照表 > 离线 KB」，易被读作「对照表即真源」；本定稿明确「对照表=业务语义，真源=PMS」 |
| 10 | **未误把 md 对照表当 E 类真源** | **存在误用风险** | md 版《海外仓各业务环节异常类型与增值服务对照表》是 md 业务梳理稿（用于业务语义匹配），E 类真源必须以 xlsx《附件2 vascCode 桥接候选表》+ PMS 实测为准 |

### 1.1 关键修正点

- **E 类不再「向 PMS 单向要桥接」**：xlsx 附件 2 已给出 45 条候选桥接（vascCode↔中文名），E 类权威 = `PMS 实测 vascName` × `xlsx 中文名` 双向交叉
- **md 对照表 ≠ E 类真源**：md 用于语义匹配（高频 eventCode → 推荐产品名），不替代 vascCode；E 类走 xlsx 校准层
- **新增 F/H 类**：F 是意图路由（客户需求描述→产品），H 是规则引擎（block/downgrade/ask_intent/manual）

## §6 硬分流 + 校准决策流（定稿版）

```text
on customer enters "处理异常第二步：增值产品信息":
  open AI sidebar and send context by frontend/middleware

middleware:
  event_list = queryEventList(eventNo or page/customer filters)
  event_detail = queryEventOrderDetail(eventDetailId)
  facts = normalize(eventCode, eventName, exceptionNode, exceptionObject,
                    warehouseCode, pscCode, goods, attachments, externalAttributes)

  # 硬分流：PMS 系统圈定（权威）
  system_candidates = listAllVasc(
    exceptionEventCodeSet = facts.eventCodes,
    warehouseCode = facts.warehouseCode,
    pscCode = facts.pscCode,
    pscgCode = facts.pscgCode if verified,
    addValueEntry = exception_value_add_entry
  )

  # 业务语义匹配（仅作交叉，不替代系统）
  semantic_products = lookup_md_counterpart(facts.eventCode)         # D 类
  bridge_table = lookup_xlsx_attachment2(productName)                # E 类一侧
  # E 类交叉验证：PMS vascName × xlsx 中文名
  e_match = cross_verify(system_candidates, bridge_table)
  e_verified = filter(e_match, status == "verified" or "pending_pms")  # 仅 verified+pending_pms 进推荐池
  e_conflict = filter(e_match, status in ["name_mismatch", "xlsx_orphan", "pms_only"])
  # conflict 项 BLOCK，禁止 LLM 追加产品

  # F 类意图路由
  intent_triples = lookup_xlsx_sheet2_3(eventCode)
  # H 类规则触发
  h_rules_hit = evaluate_h_rules(facts.eventCode, candidate_products)
  h_block = filter(h_rules_hit, action == "block")
  h_downgrade = filter(h_rules_hit, action == "downgrade")
  h_ask_intent = filter(h_rules_hit, action == "ask_intent")
  h_manual = filter(h_rules_hit, action == "manual")

  # finalRecommendable 集合
  finalRecommendable = e_verified - h_block
  # H 规则关联
  if h_manual is not empty:
    needsHumanReview = true
  if h_ask_intent is not empty:
    customerIntentNeedClarification = true
    mustAskList = collect h_ask_intent questions

  # 多标准方案分支
  if len(finalRecommendable) > 1:
    customerIntentNeedClarification = true
    mustAskList += [F 表对应意图问题]
    # AI 必须先问客户意图再推荐
    # 答案不在 F 表内则进入非标兜底

  # 注入 Coze
  inject:
    inputs.enrichedContext.systemScopedVascList = system_candidates
    inputs.enrichedContext.counterpartSemanticMatch = e_match.summary
    inputs.enrichedContext.fieldRequirements = getVascInfo + BaseAttrRel
    inputs.enrichedContext.forbiddenProducts = e_conflict + h_block
    inputs.enrichedContext.hRulesHit = h_rules_hit
    inputs.enrichedContext.intentTriples = intent_triples
    inputs.customerActionIntent = need_clarify (if any)
    needsHumanReview = (h_manual not empty) or (system_candidates empty) or (e_conflict not empty)

  # 禁止
  ✗ 禁止 LLM 在 finalRecommendable 之外追加产品
  ✗ 禁止 LLM 自行裁决 e_conflict
  ✗ 禁止 H.manual 时 AI 给推荐
  ✗ 禁止 H.ask_intent 时 AI 跳过追问直接推荐
  ✗ 禁止 LLM 写仓库处理流程
  ✗ 禁止 LLM 报价
```
