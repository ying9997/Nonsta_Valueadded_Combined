# 非标分流：命名直选 vs 其他服务需求 + SOP

> 成稿：2026-07-27  
> 发现来源：[`非标增值单审核SOP知识库-新版.md`](../../../../../增值配置AI化/增值单ai指引助手/docs/非标增值单审核SOP/非标增值单审核SOP知识库-新版.md)  
> 产品编排证据：`agentic/value-add-service-guide/`（特批产品页 + `atom-attr-coverage-2026-06-22.csv` + 事件目录快照）  
> **用途**：客户引导 / D6 / HANDOFF 口径；**不是**运行时 `listAllVasc` 替代品。

---

## 0. 一句话

非标不是一条路：

1. **已有独立命名、且不是「××其他服务需求」的非标原子** → **直接让客户选该增值服务**（在系统圈定内）。  
2. **走入库/库内/出库「其他服务需求」、且有历史 SOP** → **标准提问补全需求描述 → 对照本 SOP 知识库找相似场景 → 生成确认用 SOP**。

示例：`包裹串仓异常调拨` 属于第 1 类（挂在「入库非标增值（特批）」下，与「入库其他服务需求」并列），**不要**再当成「其他服务需求」去长篇追问写描述。

---

## 1. 两类定义

| 类 | 名称 | 产品层特征 | 引导行为 |
|----|------|------------|----------|
| **A** | 命名直选非标 | `增值类型=非标增值`；原子名 **≠** `入库其他服务需求` / `库内其他服务需求` / `出库其他服务需求` | 意图匹配后，引导选对应 **VASC 产品 + 命名原子**；只补该原子必填字段（若有） |
| **B** | 其他服务需求 + SOP | 兜底原子三选一；需求靠描述+附件；审核侧有历史场景模板 | 按模板维度标准追问 → 匹配《SOP知识库-新版》相似场景 → **客户确认用 SOP 摘要**（确认≠审核通过） |

**硬约束（不变）**：最终可选范围仍以 `systemScopedVascList`（`listAllVasc`）为准；AI 不扩推圈定外产品。

## 3. B 类：其他服务需求 + SOP 知识库

### 3.1 何时走 B

- 系统候选命中「××其他服务需求」，且意图**不能**落到 §2.1/§2.2 命名原子；或  
- 客户描述属于 SOP KB 中大量「场景化」标题（典型：**§2.1 尺重/标签辨识后换标上架**），历史上靠「其他服务需求」提交。

### 3.2 AI 步骤（钉死）

```
1) 标准提问补全（模板维度：背景/目的/对象/动作/单号对应/附件/特殊要求…）
2) 用补全后的描述，对照《非标增值单审核SOP知识库-新版》做相似场景匹配
3) 按命中场景模板生成「客户确认用 SOP 摘要」→ 客户确认
4) 确认 ≠ 审核通过；仓内细步骤不对客全文倾倒
```

### 3.3 SOP KB 中「标题像产品、但默认仍属 B」的说明

知识库 **§2/§3/§4 章节标题**多数是**审核场景名**，不等于 PMS 里已配置的命名原子。  
例如 §2.1「换标上架」有完整 SOP，但**入库特批产品编排里没有同名原子** → 一期按 **B（入库其他服务需求 + SOP）** 处理（与已打通的非标 2.1 一致）。

仅当章节标题与 §2.1 A 类原子**同名/强对应**时，优先改走 **A 直选**（如 §2.4 包裹串仓异常调拨）。

### 3.4 B 侧高频 SOP 场景（抽样，完整见 KB）

入库：§2.1 换标上架、§2.2 批量补贴条码、§2.3 海运整柜、§2.5 换商品标签上架、§2.8 商品质检、§2.10 预报 SKU 不符…  
库内：§3.3 良品/不良品检测、§3.9 换标上架、§3.16 外观辨识+贴标…（除 §2.1 表内 A 类）  
出库：§4.x 多数（出库特批仅「其他服务需求」）→ **默认 B**

## 4. 决策顺序（写进引导逻辑）

```
标准可覆盖？ → 推标准（既有）
否则：
  圈定内是否有匹配的 A 类命名非标？ → 直选该原子（可附短说明/仓群限制等）
  否则是否需非标兜底？ → B：其他服务需求 + 提问 + SOP KB 匹配 + 确认摘要
  都无法？ → 澄清 / 转人工
```

**优先级**：命名非标 **优先于** 其他服务需求（与产品页「不要把串仓调拨泛化成其他服务需求」一致）。
