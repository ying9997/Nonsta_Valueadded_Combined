# 非标 SOP 2.1：入库尺重/标签辨识后换标上架

本片段编译自 `value-add-recommendation-rules/nonstandard-sop/2.1-inbound-relabel-shelving.md`，只用于非标路径追问与客户确认用 SOP 摘要。

## 边界

- 产品范围权威仍是 `recommendationInput.enrichedContext.systemScopedVascList`。
- SOP/xlsx 只做话术和字段校准，不得扩推产品。
- 客户确认用 SOP 摘要不等于审核通过，不替代人工审核。
- 不对客输出仓内系统操作细步骤全文。

## 触发

当异常/客户诉求体现以下任一内容，且系统候选无可用标准覆盖、客户坚持特殊处理，或候选中仅有非标/特批产品时，走非标 2.1 路径：

- 尺重/标签辨识后换标上架。
- 商品条码与系统登记不符，需要按实物条码对应新 SKU/商品条码换标。
- 包裹内混 SKU，需要按客户对应关系补贴新商品标签。
- 供应商贴错条码，需要辨识后换标并上架到新入库单。

## 客户需补充

必填：

- 异常单号 / eventNo。
- 新入库单号。
- 实物条码到新 SKU/商品条码的对应关系。
- 处理对象范围：包裹号、商品条码、SKU、数量。
- 标签附件：新商品标签；如需补贴包裹标签也需提供包裹标签。
- 是否需要补贴新入库单包裹标签。

可选：

- 特殊要求或无法辨识/对应关系不一致时的处理方式。

## 输出要求

字段不齐时，先追问缺失字段，不输出完整确认稿。

字段齐全时，输出“客户确认用 SOP 摘要”：

- 处理目标。
- 客户已提供信息。
- 拟处理方式摘要：定位异常货物、按对应关系换商品标签、按需补贴新入库单包裹标签、上架到指定入库单。
- 需客户确认：是否按此处理方式提交非标增值申请。
- 明确说明：确认不等于审核通过，最终以审核和仓库可执行性为准。
