## 打进哪条对话流（不是另找一张工作流）

`7685975376836739124` 是 **对话流** `cs_Bot_Client_v2p_1`（客服 Bot 最外层那条），**不是** Coze 里另建的「工作流」。

前端侧不用改聊天怎么发：还是打现在这个 Bot。AI侧只是在这条对话流里、Query 问答后面加了几格：判断这次要不要出卡/读页，再用现有的「函数调用」插件发出去。

时序图里的 `workflow/run` 是前端 SDK 的叫法，意思是：**同一条对话再跑一轮**（把脱水 DOM 当下一轮输入）。接收方就是上面这条对话流，不要去工作流列表里再找一张。

同源文件：`a2ui/catalog.json`、`a2ui/prompt.md`、`fixtures/sidecar-select-option.json`、`fixtures/sidecar-render-a2ui.json`、`fixtures/sidecar-page-read.json`、`fixtures/card-action-select-option.json`。

**卖家页气泡只给人话。** 出卡 JSON 走 `tool_call_send` / `queryToolCall`，不要画进聊天文本。Coze 预览里看到 JSON 可以。

AI侧发指令的通道和现网客服「正在思考」是同一条：Coze 插件 `cobra_agent_http` / `tool_call_send`。前端侧对应时序图里的 **queryToolCall 拿到一条 tool**。

## 前端侧问的两句话，AI侧直接答



### 1. pageRead：AI侧怎么告诉前端侧开始读？前端侧怎么把页面信息给 AI侧？

**开始读：** 前端侧继续 `queryToolCall` 轮询。收到：

- `function_name`（或 tool name）= `pageRead`
- `arguments` = 字符串，parse 之后：

```json
{ "reason": "eds_value_add_form_need_facts" }
```

`reason` 可空，有则写日志。收到这条就开始读当前业务页（侧栏外面那页），不要等用户再点一次。

**页面信息怎么给 AI侧：** 读完页之后，前端侧把脱水 DOM 当作**同一条对话的下一轮输入**再打进来（时序图里这个动作叫 `workflow/run`，实际打进的仍是对话流 `cs_Bot_Client_v2p_1` / `7685975376836739124`）。

- **不要**再找一张新的「工作流」。
- 测试 Bot 必须绑这条对话流。
- DOM 不要塞进 `toolCalled`。`toolCalled` 只表示「pageRead 这条指令收到了」。



### 2. A2UI 怎么传给前端侧？operatePage 做完怎么告诉 AI侧？

**出卡：** 前端侧 `queryToolCall` 收到：

- name = `renderA2UI`
- `arguments` parse 之后：

```json
{ "commands": [ /* A2UI v0.9 命令数组 */ ] }
```

`commands` 必须能用前端侧内建 catalog（`catalogId: "ai-chatbot-builtin"`）画出来。标准样例就是 `fixtures/sidecar-render-a2ui.json` 的 `arguments`。

卡片按钮的 action 名只能是 `readPage` / `operatePage`。注意两个读页名字不要混：

- AI侧下发的后台 tool：`pageRead`
- 用户点卡片上的按钮：`readPage`

**点页（点卡）：** AI侧 **不会**再单独发一条 `operatePage` 的 `tool_call_send`。点卡不是第三条后台口令，而是出卡 JSON 里按钮上已经写好的 `action.event`。用户一点，前端侧自己执行 `operatePage`。做完按 Phase 4 走 `toolCalled` **回传执行结果**（或只在卡片里提示）。AI侧 Coze 画布上没有名为 toolCalled 的节点。

**选中推荐产品 / 原子（和前端 catalog 对齐）：** 不要点「第 0 个元素」，也不要另接一套 `fieldKey + valueCode`。用 catalog 已有的：

- 单次：`method: "selectOption"`，`args: [index, optionText]`
- 一组（产品 + 原子）：`actions: [{ method: "selectOption", args: [index, optionText] }, ...]`，整批 `requireConfirmation: true`

`optionText` 必须是当前页下拉里**看得见的字**。`index` 是该下拉在 `interactiveElements` 里的编号；样例里的 `0` / `1` 是占位，真页要用读页结果替换。标准样例：`fixtures/sidecar-select-option.json`。

卖家页气泡只显示人话。JSON 只走 `queryToolCall`。Coze 预览里看到 JSON 可以。

## 三条对照时序图


| 时序         | 谁先动  | 前端侧 `queryToolCall` 看到的 name | arguments（parse 后）        | 前端侧接下来做什么                     | 怎么回给 AI侧                                 |
| ---------- | ---- | ---------------------------- | ------------------------- | ----------------------------- | ---------------------------------------- |
| Phase 2 读页 | AI侧  | `pageRead`                   | `{ "reason": "..." }`     | 读业务页脱水 DOM                    | 下一轮打进同一条对话流（id `7685975376836739124`）；`toolCalled` 仅 ack |
| Phase 3 出卡 | AI侧  | `renderA2UI`                 | `{ "commands": [ ... ] }` | 在侧栏气泡画 A2UI 卡                 | 不用回（画出来即可）                               |
| Phase 4 点卡 | 用户点卡 | **不是** queryToolCall 下发      | 卡片 `action.event`         | 执行 `readPage` 或 `operatePage` | 读页同 Phase 2；点页结果 `toolCalled`            |


正常文字对话仍是 Phase 1 的 `sendMessage` SSE，与这三条并行存在。
