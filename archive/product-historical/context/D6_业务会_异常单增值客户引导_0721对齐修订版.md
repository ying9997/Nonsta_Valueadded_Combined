## 一、我们要解决什么

**审核团队的痛**：大量时间花在追客户补资料、改「其他服务需求」里写不清的描述；不少客户是**先找客服写一段再提交**。

**客户的痛**：分不清标准/非标；有标准仍提非标；非标该填什么、附件怎么交不清楚，提交后退回再补。

**一期目标（0721 原话精神）**：

- 有标准可覆盖 → **引导选对标准**，少走非标  
- 必须非标 → **AI 代替客服**把场景问清、按审核 SOP/模板维度补齐，并给出**可确认的处理方式摘要**  
- 先把**能力做出来**（有无优先于完美）；质量靠上线后快迭代  

**一期主触点**：异常处理链路进入 **「增值产品信息」填写页（第二步）**。  
**不否定**后续把同一智能体挂到主动加增值等入口——但**不做多个智能体**。

## 二、客户现在的操作路径（三步）

| 步骤 | 客户看到什么 | 现在的问题 |
|------|-------------|------------|
| ① 异常单列表 | 异常单号、异常名称、仓库、状态等 | AI 不在此步打断 |
| ② 第一步：基本信息 | 仓库、入库单号、异常明细 | 异常事实可进上下文 |
| ③ **第二步：增值产品信息**（痛点集中） | 系统圈定的增值产品、服务要求、文件、费用提示 | **选错 / 填不清 / 乱选「其他」**；0721 主战场 |

**AI 引导最佳触发点 = 第二步。** 三方案差别在「怎么接到 AI」，后端引导逻辑同一套。

**系统已有能力（会议强调）**：同一异常类型下，前端/配置已限制可选增值产品范围——AI 应在**圈定范围内**匹配与话术，而不是凭空扩推。

## 三、可行性校验

### 3.1 触发 + 代发

| 维度 | 结论 |
|------|------|
| **现有智能客服** | 侧栏 AI（Coze）；现网主路径走 **`cs_Default_Query_v4_staging_D` → `experts_recaller_v2_staging_D`（含 Agent Loop）**；production 工作流多为备份（以摸底为准） |
| **代发路径（0721 主推）** | 客户点下一步进入第二步 → **自动开侧栏** → **万邑联页调用 AI 客服前端提供的接口**代发固定话术（含 eventNo/异常上下文） |
| **缺口** | ① **代发 API：PDM 未回则入口链缺口仍在**；② Coze 分类/QID/`sys_experts` 能否落到增值推荐专家；③ 异常编码/上下文前端是否可取 |
| **话术风格（0721）** | 尽量简洁：直接说「你这种情况可优先选哪些标准产品 / 若非标需补哪些信息」，少堆自我独白 |

### 3.2 硬分流（谁圈定产品、谁只做话术）

| 层 | 谁做 | 依据 | 说明 |
|----|------|------|------|
| **硬分流：能选哪些增值产品** | 前端/中间层 | `listAllVasc`（或等价）+ 异常/仓库/入口配置 | **不由大模型扩推产品** |
| **话术/追问/润色/确认摘要** | AI（Coze 专家链） | xlsx 校准、SOP 客户填写层、模板 | AI 在圈定内推荐或追问 |

**现状**：推荐专家历史上偏离线 KB；一期须补中间层圈定注入（`systemScopedVascList`）。  
**缺口**：接口一期谁接、何时可用。

### 3.3 客户填写 vs 确认摘要 vs 仓内细步骤

| 层 | 面向谁 | 内容 | 一期 |
|----|--------|------|------|
| **客户填写指引** | 客户 | 要提供什么才能交完整 | **做**：追问 → 补齐 |
| **客户确认用 SOP 摘要** | 客户 | 「是否按此方式让仓库做」 | **做**：依据审核 SOP/模板；**确认≠审核通过** |
| **需求描述双轨（0721）** | 客户 + 审核 | 客户原始表述 + AI 润色/结构化版；引导客户尽量用润色版提交，不强制 | **做口径**；落库字段是否加列待产品 |
| **仓库/审核内部细步骤** | 内部 | 仓内系统点法、扫描路径等 | **不对客全文倾倒** |
| **审核侧生成物（0721「生成」）** | 审核 | 场景识别（如原单/新单）、操作 SOP 草稿、缺单号追问等，便于人改 | **一期能力建设方向**；回写 TOM 接口/排期与质量门槛另跟研发 |
| **免审 / 自动下发仓库** | — | — | **一期不做** |

**MVP 两条分流（非标再拆两类）**：

1. **标准**：xlsx（202511）校准 + `listAllVasc` 圈定 → 意图追问（多标准时）→ 推荐标准产品 + 字段话术；**优先避免无必要非标**  
2. **非标**：  
   - **2a 命名直选**：圈定内命中命名非标原子（≠ 入库/库内/出库其他服务需求）→ **直接选对应增值**（例：包裹串仓异常调拨；库内特批下还有代采购包材、审计盘点、DG 销毁、货权转移换标/改数等）  
   - **2b 其他服务需求 + SOP**：走三兜底之一且有历史 SOP → ① 标准提问补全需求描述 ② 对照《SOP知识库-新版》相似场景 ③ 客户确认用 SOP 摘要  

详见交付物：`module_异常单增值客户引导/deliverables/非标分流_命名直选_vs_其他服务需求/非标分流两类口径.md`。

**红线**：不对客倾倒仓内全文；确认≠审核通过；无确认不静默下发。

### 3.4 附件（0721）

| 项 | 一期口径 |
|----|----------|
| 假设 | 侧栏/对话侧**可上传**常见附件（Word/Excel/图片优先），AI 可解析文本类内容辅助完整性 |
| 现实 | 与页面表单附件、未提交落库等系统能力可能未通——**按「假设可做」建设能力**，系统对接找 MAS/Henry 等另排 |
| 明确后置 | **大视频（如百兆级）**、复杂工厂 SOP 视频理解 |

### 3.5 需求描述双轨（0721 新增写入）

```
客户原始需求（框里自己写的）
  → AI 追问补齐 + 润色/结构化
  → 请客户确认：采用 AI 版 or 坚持原始版
  → 提交：优先引导用 AI 版填「需求描述」；坚持原始版则提醒可能被打回（一期不强制拦）
  → 审核侧：希望能看到 AI 整理版（加字段 or 同字段分区，待产品）
```

### 3.6 一期边界

- 不自动提交增值单  
- 不替代人工审核、不保证通过（含：确认了摘要 ≠ 审核通过）  
- 不做免审直发仓库  
- 不做提交前硬预审（可做对话内提醒）  
- 不输出对客「精确报价/实扣承诺」（预估费用能力可二期）  
- 不做多套智能体（多入口仍同一智能体）  
- 不做知识库实时同步（一期静态/编译进专家）  
- 无客户确认不静默下发  

### 3.7 非标两类（2026-07-27，对照 SOP KB + 产品编排）

| 类 | 特征 | 引导 | 典型例子 |
|----|------|------|----------|
| **2a 命名直选** | `增值类型=非标增值`，原子名**不是**「××其他服务需求」 | 在圈定内**直接选**该命名服务 | 入库特批：`包裹串仓异常调拨`；库内特批：代采购包材、审计盘点、DG 销毁、货权转移换标/改数；另有上架前自提、入库非标拍照等产品下的命名原子 |
| **2b 其他服务需求 + SOP** | 三兜底之一；需求靠描述；KB 有历史场景 | 标准提问 → 对照《SOP知识库-新版》相似场景 → 确认用 SOP 摘要 | §2.1 换标上架等大量场景标题（标题≠必有同名原子） |

**注意**：SOP KB 章节标题多数是审核场景名；仅与 PMS 命名原子同名/强对应时走 2a，其余默认 2b。出库特批当前编排**只有**「出库其他服务需求」→ 出库非标默认 2b。

## 四、一期三个入口方案（后端逻辑同一套）

触发后 AI 相同：**硬分流 → 标准推荐 或 非标（2a 直选 / 2b 追问+SOP 匹配+确认摘要）**。

### 4.1 方案一：自己打开（兜底）

零改造；客户不主动问则无效。

### 4.2 方案二：内嵌轻量入口（可选主方案）

第二步按钮/浮层；点击带上下文。不接受自动打开时用。

### 4.3 方案三：自动打开 + 代发（主推，0721）

| 维度 | 说明 |
|------|------|
| 形态 | 进第二步自动开侧栏 + **调 AI 客服代发接口**发固定话术 |
| 固定话术方向 | 含 `{eventNo}`；引导判断标准/多标准追问/非标需补信息（与 HANDOFF 固定句一致） |
| 改造 | 万邑联页 + AI 客服前端接口；**当前 PDM 未回则阻塞** |
| 优点 | 触发率最高；符合 0721 原型讨论 |
| 缺点 | 打扰感；接口与排期依赖外部 |

#### 硬分流（共用）

```
代发/带上下文（异常编码 + 仓库 + 客户 + eventNo）
  ↓
中间层：listAllVasc 等圈定 systemScopedVascList
  ↓
┌─ 有可匹配标准增值 ─→ 简洁推荐标准 + 字段清单（多候选先问意图）
│
├─ 有可匹配命名非标（2a，≠其他服务需求）─→ 直接引导选该原子 + 短字段提示
│
└─ 需走其他服务需求（2b）─→ 标准提问 → SOP KB 相似匹配 → 确认用 SOP 摘要
```

#### 非标两轮（主要针对 2b；2a 以直选+短字段为主）

| 轮次 | AI | 客户 |
|------|----|------|
| 追问（2b） | 按「客户需提供」/模板维度逐项问 | 回答、上传 |
| 确认（2b） | 结构化摘要 + **客户确认用 SOP 摘要**（经 KB 相似场景） | 确认或修正 |
| 直选（2a） | 指出应选的命名非标及注意点（如串仓仓群限制） | 在页面选中该服务 |

**不做**：仓内细步骤全文对客；承诺审核通过；无确认静默下发。

| 免审直发 | 客户确认 SOP+费用后少人工 | 稳定质量 + 业务授权 |
| 页面感知 / 提交前预审 | 选错漏填主动拦 | 前端大改 + 规则 |
| 视频大附件 | 工厂级视频 SOP | 后置 |

**0721 共识倾向**：先做指引（+确认摘要/生成能力建设），免审后置；回写与质量可并行谈排期，但**不能用「没回写」挡「先有能力」**。
